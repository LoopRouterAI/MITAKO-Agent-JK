# Implementation Plan: 0714 甲方反馈闭环整改

**Branch**: `002-customer-feedback-0714-closure` | **Date**: 2026-07-14 | **Spec**: [spec.md](./spec.md)

## Summary

在保留现有 React + FastAPI + SQLite + 视觉审核 POC 的前提下，建立统一业务案例和响应编排规则，优先修复跨用户/订单污染、业务意图错配、审核结果未回写、虚假转人工和坐席简报问题，再补齐审核服务稳定性、运维可观察性、演示边界和发布包验收。

## Technical Context

**Language/Version**: Python 3.x、JavaScript/React 18、HTML/CSS/JavaScript

**Primary Dependencies**: FastAPI、SQLite、LangGraph、React、Vite、现有视觉审核 POC

**Storage**: 现有业务 Mock JSON、SQLite 会话/后台数据库、视觉审核任务与报告目录

**Testing**: Python 专项回归、API smoke、视觉工作台 smoke、npm build、浏览器桌面与移动端回归、发布包解压后验收

**Target Platform**: Windows 11 内部研发与演示；兼容甲方 Linux 私有化部署

**Project Type**: 用户客服 Web + 坐席台 + 运营后台 + 标准审核 API + 视觉审核工作台

**Performance Goals**: 旧异步响应不得污染新用户；用户轮次最多一张卡；审核任务异步可追踪；批任务部分失败可隔离

**Constraints**: 不更改用户已配置模型名和接口名；不暴露 Key/Prompt；真实甲方接口只提供 Mock 与契约；不恢复旧陪伴能力

**Scale/Scope**: 0714 至 0804 连续反馈、商品有伤/发错货/漏发货/未成年人资料四类审核、发布包和内部开发文档

## Constitution Check

- SOP 优先：PASS。所有用户可见状态必须来源于持久化事实。
- 情绪与业务准确：PASS。L4 建议人工但继续给实质方案，L5/法律/明确请求才强制转接。
- 移动端与无障碍：PASS。一轮一个主卡降低刷屏。
- 模块化：PASS。编排、案例和审核状态使用独立函数/服务，避免继续扩大上帝文件。
- 品牌与安全：PASS。不新增模型、Key、Prompt 暴露。

## Phase Plan

1. 冻结 0714 规格、根因、数据模型和契约。
2. 先写失败回归，锁定订单优先级、意图、转接和卡片编排。
3. 修复 P0 统一状态与审核闭环。
4. 修复 P1 业务分支、坐席与运营体验。
5. 完成 API、浏览器、并发、发布包和文档验收。
6. 接入 0722 新订单快照资料：先完成只读盘点和唯一映射，再将当前审核任务需要的 SKU、履约基线和官方商品图按需注入；商品图不得全量下载，失败时必须可解释降级。
7. 统一审核建议结果：事实结论、未校准证据分数、三级人工复审、流程建议和风险信号分层；离框只按争议商品必要展示窗口与重新入镜同物关系判断，时长仅作黄色证据说明，不使用统一秒数自动补件或判负；API 可选择 JSON-only 或 JSON + HTML。
8. 建立客诉多源证据契约：发错货和漏发货分别校验订单、包裹、物流与证据覆盖；离线盲测只读取用户消息，禁止把人工终判送入模型；脱敏历史风险只影响抽检建议，不改变事实结论；未成年人资料继续拆分视觉一致性与甲方权威核验。
9. 将现网已验证的 Gemini 网关认证、Celery 任务注册和视觉结构化日志回迁 Git，并纳入发布门禁，避免运行环境修复只存在于服务器或运维记忆。
10. 将视频抽帧审核模型和渠道改为运行时配置：默认 `gemini-3.5-flash-lite`，按 BananaRouter、百度、API易、Google 官方顺序尝试；未配置的渠道直接跳过，继续复用现有重试、脱敏日志和业务报告边界，不新增路由服务。
11. 以 `E:\AIGC\0 Mitako样本` 复核字段来源并冻结标签隔离：标注与客服终判仅用于离线评测；修复正式 API 的结构化物流上下文贯通；所有样本脚本改用参数化根目录，甲方部署不依赖研发机盘符。
12. 根据 0727 反馈重构事实层与复审层的组合：商品有伤的可见事实不再被成因/连续性不确定覆盖；补件、可抽检和必须复审分流；HTML 统一使用建议契约，并建立事实、责任和经营处置分层的黄金样本口径。
13. 根据 0730 真人复测纠正未成年人退款口径：五类必交材料与视觉字段一致性是当前可执行审核基准；身份证、运营商和订单支付在线验真默认关闭且不阻断结论，只有甲方显式启用后才进入强制复审。报告改为场景专属交通灯、证据可回看和客服行动指引；51/62 图继续全量处理，并使用独立、受限的资料审核并发配置缩短等待时间。
14. 根据 0731 商品有伤复测纠正证据聚合与 SOP 判定：主视频、补充图片和人工业务规则必须分层，补充图片不得改写“主视频是否看见损伤”；不合规开箱视频可按甲方已确认规则输出“不支持诉求”的分类建议，同时明确补充图片仅供最低档补偿或人工复核参考；视频加速本身不是不合规条件。报告首屏先展示“按照 SOP 的审核倾向”，再展示需要进一步核对的证据分歧，且不得出现同一证据既“已确认”又“未直接观察”的矛盾。
15. 0731 修偏以结构化证据契约替代样本词表和业务特例：模型明确输出伤情是否可见、是否同一争议商品及可回链帧，服务端只按字段聚合，再由版本化 SOP 给出审核倾向。同步闭环视频速度/离镜取证、未成年人证件与监护关系初审、动态并发/指数退避/已配置渠道兜底；无法由素材客观证明的倍速、证件真伪或责任归属必须输出 `unknown`，不得用猜测补齐。
16. 收口发布目录与本地安全瘦身：双 ZIP、独立甲方 HTML 和验收脚本默认路径统一到 `dist/`；前端构建仅清理自身产物并保留发布物；删除已验证可重建的运行缓存、重复发布包和旧压缩副本，不改写 Git 历史，不删除原始样本、环境依赖或未确认业务资料。
17. 根据 0803 真人复测纠正证据语义与决策分层：商品有伤不再用全部技术门槛的合取结果限制 SOP 建议；未成年人资料区分文档类型、用户特定有效材料、字段冲突与图片风险；模板和普通运营商账户截图不得替代手机号实名归属证明。人工复审独立于建议结论，报告首屏只展示结论、原因、下一步和关键证据，技术详情默认折叠。
18. 以中立案件 ID 和推理后加载标签的方式执行正负样本盲测；模型请求、媒体路径、文件名和业务上下文不得包含人工标签、目录标签、`annotation` 或 `reply.json` 终判信息。完成单元、真实 API、网页端、HTML、双 ZIP 和独立解压验收后方可发布。
19. 根据 0804 反馈和甲方客服主管交流重新冻结证据关系：商品补充图片逐张独立并发审核，事实层与开箱合规层分开；只有直接动作前后链可判断用户操作致损。未成年人监护关系未证实为黄色补证；申请时未满 10 周岁只加强支付密码来源和监护人发现消费过程核验，不仅凭年龄给结论或强制人工，明确材料字段冲突优先进入红色复核。网页提供四个独立业务入口，发错货与漏发货可复用开箱技术链但不得复用业务语义。
20. 根据 0807 五份人工黄金指南和用户确认口径，视频加速改为“橙色信号 + 实际审核影响”两层事实：默认 1 FPS 可完整回链时非阻断，1 FPS 不足时先保持不确定并建议 2 FPS 有界强化，强化后仍不可判断才形成实质不合规。同步补齐封箱起始、面单可读、后补时态、特殊商品缺陷资格、监护人手机号持有和承诺书内容完整性；沿用现有模型、抽帧、连续性、决策和报告链，不引入平行审核框架。详细执行以 `implementation-plan-0807-guide-iteration.md` 为准。
21. 吸收 0807 最新黄金标回收表、客服主管记录和 9 份人工指南：将前 25 条正式黄金标与后 75 条回收数据按来源归并；补齐仓库终审事实、订单包裹归属、多原子诉求、包装来源错场景、重复媒体去重和可复位装配状态。所有案例只提供离线评测标签，生产规则只实现可泛化字段和优先级。
22. 在不修改现有模型名的前提下确认百度云通道，并比较旧分阶段、统一抽帧结构化推理和百度原生视频实验路径。统一推理合并重复视觉理解，服务端保留覆盖、引用、冲突和 SOP 确定性门禁；结构缺口按维度回退，未达质量门槛前不静默切换默认路径。
23. 0809 按 review-agent 完成 API/Web/报告/发布全链路审查，以固定种子真实样本验证人工减少范围；高置信未满 9 周岁只触发授权复核，跨户口本关系链形成明确补件。原生视频主审不再执行全量重复抽帧，但保留 0/1 秒开场锚点和必要时仅核对开场字段的一次轻量专项；这项有界校验用于纠正原生模型把内包装误认封箱起点的问题。`598089`、`140592`、`606669` 和 `568689` 已收口；全量回归与报告验收通过，待无上下文独立终审、双 ZIP 冷启动后提交私库。

24. 0810 根据 609768、587966 和离框误判反馈重开模型选型门禁：百度 Gemini 大文件优先通过受控 HTTPS `fileData.fileUri` 提交原片，不得把 Google 外部 URL 的 100 MB 限制未经验证地套用到百度渠道；无公网地址时使用短时签名 Cloudflare Tunnel。URL 失败后才按 2K、1080P 梯度使用 HEVC/VP9、最高 24 FPS 做保真转码。Gemini 3.5 Flash-Lite 与 3.6 Flash 在完整视频盲审、`medium/high` 思考、`high` 媒体分辨率和 65,536 输出上限下比较；感知型 Schema 与完整旧 Schema 同时对照。开箱完整性继续作为商品有伤强制门槛，9 个黄金标字段、加速不确定黄标、有效展示窗口离框语义、客服报告小字说明和 API/Web/安全一致性全部纳入发布门禁。详细当前状态以 `docs/integration/百度Gemini原生视频模型选型与传输主线-20260810.md` 为准。
25. 0811 纠正 598089 的旧验收基线污染：20260806 终审表确认该工单 `sealedStart/waybillVisible/continuous/allItemsShown/issueVisible=是`、`hasEdit/hasSpeedChange/hasOffscreen=否`、`overallVideoResult=合格`。0809 报告和商业验收脚本中“偏离过久、商品未完整展示”的人工基线已失效，不得继续作为黄金答案；后续离框只统计争议商品必要展示窗口，不累计展示完成后的无关片段。
26. 0811 以真实 598089 复跑关闭重复推理根因：百度 `gemini-3.5-flash-lite` High/High 单次完整视频已经识别伤点并返回四项开箱时间戳，后续 0/1 秒专项却错误覆盖全片事实，因此生产路径删除这两类二次模型调用。完整原生结构有证据时直接聚合；缺失才回退默认 1 FPS、最长边 1920 的独立无损 WebP 批次。默认不发送 `maxOutputTokens`；仅高于 2K、24 FPS 或 6 Mbps 的视频才生成最高 2K/24 FPS/6 Mbps HEVC/VP9 代理，正常原片不降质。模型选型在业务效果相当时使用成本更低的 Lite，3.6 仅保留显式实验档。旧第 23 条的强制开场专项和第 24 条的 65,536 输出上限结论已失效。
27. 0812 用当前紧凑 Schema 纠正模型选型过度结论：587966 的 Lite 与 3.6 都未可靠闭环主视频约 00:37 的目标伤点，1 FPS WebP 分批虽覆盖该时间点但窗口过宽且成本约为原生 Lite 的 4.95 倍；609768 则由 Lite 命中主视频划痕、3.6 保持不确定。因此 Lite 仅为暂定默认，选型仍未完成。报告证据必须人话化并回链原始视频时间点，严重质量标识只在高置信严重伤损时显示，空栏目和重复结论不渲染。旧 598089 产物中“补图零引用却已验证”的状态已失效，必须用当前证据引用守卫真实重跑后再验收。
28. 0812 以 598089 正式工单收口报告证据回链：正常 1080p、低于 6 Mbps 的 30 FPS 原片不因帧率单项转码；同一完整视频单次百度 Lite High/High 调用必须返回九字段与真实证据引用。正式登录报告将结构化引用转成伤点优先、同秒合并的客服可读卡片，并用租户/工单/媒体绑定的签名 URL 跳到原片秒数；脱敏分享页不携带原片。严重质量标识仅在高置信严重/极严重损伤时显示。真实 API/Web 与桌面/移动门禁通过后，仍需全仓、冷启动与独立终审才能发布。
29. 0812 冻结本轮模型选型，停止围绕三个特殊样本反复刷模型：百度 Lite High/High 继续作为成本受控的默认档，3.6 High/High 保留显式实验档；完整原生视频单次调用仍是主路径，只有原生结果缺失关键身份/时间窗时才允许 1 FPS 独立 WebP 分批回退。587966 的回退纠正了“商品未出现”但用了 10 次调用且仍看不清红痕，609768 的 1 FPS 回退用了 12 次调用且不优于原片，足以证明全量抽帧不应默认化。速度策略同步修订：PTS、帧率、光流和动作语义没有可信原速参照时都不能单独证明倍速；未知/疑似加速只黄标并回链受影响片段，不强制 2 FPS，不因速度本身判负。
30. 0812 依据甲方主管最新口径重建四场景唯一审核契约：程序先扫描 API/目录生成待审核清单，Gemini 再识别素材语义和场景事实，服务端据此生成独立 `material_readiness`，最后执行确定性 SOP 决策和场景专属双层报告。普通商品有伤保留开箱门槛，高置信严重/极严重结构问题先行形成“材料不齐全但应重点跟进”的窄分支；发错货与漏发货分别使用应收/实收/包裹清单，不再依赖缺字段的通用 Schema；未成年人按五类材料展示结果，材料齐全时不输出无用人工流程文案。旧 0809 报告、混合模型 UI 证据和旧发布包均降为历史材料，不得继续充当当前验收。详细契约以 `docs/product/四场景审核业务决策与报告契约-20260812.md` 为准。
