# 2026-07-30 未成年人策略与人类客服报告升级日志

状态：已收口

时间：2026-07-30 22:50:00 +08:00

覆盖关系：本记录覆盖此前“未成年人资料缺少权威接口就必须转 VIP 客服”的旧实现；动态素材容量、正式异步 API、业务动作禁止、标签隔离和四场景事实/责任分层继续有效。

## 本轮根因

1. 旧策略把“视觉一致性不等于法定真实性”错误实现成“没有权威接口就必须转人工”，而甲方当前没有身份、运营商或支付验真接口。
2. 五类材料全部识别后，任意 `uncertain` 字段都会把 `human_required` 置为 `true`，造成 51/62 图样本仍全量转人工。
3. 公开 DTO 漏掉已计算的图片真实性风险，报告显示 `-%`；报告还混入商品有伤策略、空订单基线和英文内部状态。
4. 移动端使用 `100vw` 计算容器宽度，与滚动条宽度叠加后产生横向溢出。
5. 网页工单文件夹入口虽然过滤隐藏资源，但仍可能接收 `annotation.json`、`reply.json` 等离线评测答案。

## 策略修正

- 默认：`minor_refund_policy.review_mode=standard`、`authoritative_verification=disabled`。
- 可选提示：`authoritative_verification=advisory`，不阻断视觉初审。
- 严格模式：只有甲方显式选择 `review_mode=strict + authoritative_verification=required` 才等待外部权威核验。
- 普通黄色项：字段看不清、无法比较、缺少 EXIF、单个疑似编辑信号，允许 `continue_by_customer_policy`，不要求每单人工。
- 红色阻断项：明确字段冲突、字段比对技术失败、多重疑似编辑证据、严格验真待完成。
- 所有结果保持 `business_action_allowed=false`；Agent 不自动退款、通过或拒绝。

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---:|---|
| `REVIEW_MINOR_WORKERS` | `6` | 单案未成年人资料模型并发，服务端限制最大 8 |
| `REVIEW_MINOR_IMAGE_BATCH_SIZE` | `4` | 每个材料识别请求的图片数 |
| `REVIEW_MINOR_CONSISTENCY_IMAGE_LIMIT` | `12` | 单次字段一致性请求上限，超出继续分段 |
| `REVIEW_MINOR_SCHEMA_RETRIES` | `2` | 结构遗漏修复次数，不是业务重试 |
| `REVIEW_ASSET_SOFT_LIMIT` | `40` | 正常容量软上限 |
| `REVIEW_MAX_ASSETS` | `200` | 正式 API 单案安全上限 |
| `VISUAL_MAX_FOLDER_FILES` | `200` | 网页工单文件夹安全上限，应与正式 API 一致 |

这些参数控制单案吞吐，不是全局供应商并发预算。生产还需按供应商限流设置进程数、任务队列并发和网关速率限制。

## API 示例

```json
{
  "client_case_id": "MINOR-20260730-001",
  "scenario": "minor_refund",
  "minor_refund_policy": {
    "review_mode": "standard",
    "authoritative_verification": "disabled"
  },
  "output_options": {
    "include_html_report": true
  }
}
```

Java 只调用主服务 `/api/v1/review/*`；视觉服务保持内网。网页工作台用于 UAT 和人工查看，不是生产批量编排入口。

## 已知边界

- 目前没有甲方权威身份/运营商/支付接口，默认不依赖；未来启用严格模式必须另做真实联调。
- 当前证据分是未校准的证据强度，不是生产准确率。生产阈值仍需冻结黄金集后校准。
- 报告图片可能包含用户提交的敏感原图，必须通过鉴权报告路由和短期签名 URL 访问；文本结果不输出 OCR 原文。
- 当前单案并发已改善 51/62 图处理，不代表跨任务无限并发。生产容量需结合供应商 QPS、进程数、队列和成本预算压测。
