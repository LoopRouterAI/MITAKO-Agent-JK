# 升级日志：审核建议契约与可选 HTML

时间：2026-07-23
状态：当前有效

最新复核：2026-07-23 20:38:44 +08:00。交叉审查发现的旧摘要冲突、旧分流字段冲突、异常任务缺少主契约、未成年人权威核验边界和 OpenAPI 任意对象问题均已修复。

## 本轮目的

修正旧版“发现疑点就强制转人工”和“API 无条件生成 HTML”的问题。审核服务现在以统一结构输出事实结论、未校准证据分数、三级人工复审建议、流程建议和风险信号，同时保持不执行任何售后业务动作。

## 代码变更

- 新增 `review_service/advisory_assessment.py`，作为工作台与正式审核 API 共用的结果归一化模块。
- `ReviewCaseMetadata` 新增 `output_options` 与 `review_routing_policy`。
- `include_html_report=false` 时，工作台不写报告 JSON/HTML 注册记录，正式 API 不返回虚假报告 URL。
- 报告路由对 JSON-only 任务返回 409 `review_report_not_requested`。
- 输入资料缺口从旧 `manual_review/human_required=true` 改为 `request_more_material/human_required=false`。
- 连续离镜默认阈值改为 3 秒；达到阈值只建议补连续原视频，不改写事实标签，不把离镜单独解释为剪辑、调包或欺诈。
- 短暂离镜、遮挡和低风险媒体取证进入 `optional` 抽检信号，不再导致每单强制人工。
- HTML 报告新增“审核建议与使用边界”首屏面板。
- 旧 `human_required/decision/system_yes_no` 现在镜像主契约，不再与 `advisory_assessment` 给出相反结论。
- 资料缺口守卫会同步覆盖旧 positive 摘要，避免“要求补材料但文字仍称支持诉求”。
- 未成年人资料图像识别完成但身份、实名、订单或支付归属尚未通过权威系统核验时，输出 `required`。
- 工作台或模型调用失败时也返回统一契约，并将报告标记为 `unavailable`。
- OpenAPI 新增审核结论、三级复审、信号、边界和报告引用的强类型模型，Java 可生成 DTO。
- 逆序置信度阈值直接返回 422，不再静默改写。

## 调用链

```text
Java / 网页
  -> ReviewCaseMetadata
  -> review_service.service._review_fields
  -> visual workbench
  -> 模型与确定性证据聚合
  -> attach_advisory_assessment
  -> 正式 API 再归一化一次
  -> JSON 持久化 / 可选 HTML
```

正式 API 在应用服务端策略和输入就绪守卫后再次归一化，避免工作台结果与最终 API 结果因后处理发生分歧。

旧 `predicted_label/system_yes_no/decision/human_required` 保留一版兼容并镜像主契约，但新开发必须优先读取 `advisory_assessment`。

## 仍有效边界

- 三级复审是建议，不是甲方售后动作授权。
- `confidence` 未经独立留出集校准，不能解释为客观正确率。
- 真实企微、飞书、订单、库存、CRM/CDP、对象存储与回调仍需甲方环境联调。
- 生产自动化使用阈值前，甲方仍需审批风险策略和例外规则。
