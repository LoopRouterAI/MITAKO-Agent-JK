## 执行结论

当前代码达到**可控试点**标准，尚未达到无人终审标准。确定性开箱硬失败、明确材料缺口、跨户口本关系缺口、仓库终审覆盖和高置信未满 9 周岁风险分流，已经能减少客服重复判断；复杂多视频和特殊商品案件仍需定向抽检。

固定种子诊断集已用于定位问题，最终再通过正式 API 独立复跑 `598089` 两次、`606669` 与 `568689`。`598089` 的开箱硬事实和“无须补件”稳定，但顶层分类仍有 `negative/review` 波动；因此不能再用单一 `6/6` 掩盖稳定性差异。报告中的 `confidence` 是模型与证据聚合分数，不是经过统计校准的正确概率。

最终回归修复了四个商业阻塞项：`598089` 稳定识别开箱材料不合规且不重复补件；`140592` 识别两本户口本之间无桥接关系；`606669` 按主连续开箱来源得到面单与伤点时态两项硬失败并输出不合规倾向；`568689` 由可信仓库终核覆盖历史过程备注，输出确定未漏发且无需人工。

## review-agent 代码审查

本轮由主 Agent 按 `$review-agent` 要求完成端到端审查，并由性能/代码、Prompt/业务、报告/发布三路独立 Agent 交叉复核。审查覆盖工作台上传、URL 获取、模型路由、统一结构化推理、专项回退、未成年人五类材料、建议后处理、公开 DTO、HTML 报告、正式 API、Web Demo 和发布包。

已在共享根路径修复的问题：

| 风险 | 根因 | 当前处理 |
|---|---|---|
| 公网 URL 重定向 SSRF | 初始地址校验后允许自动跳转到私网 | 禁止自动重定向并逐跳校验 HTTPS 与公网目标 |
| 单案尾延迟可叠加至约 20 分钟 | 阶段和重试各自超时，没有总时限 | 所有阶段共享 300 秒单案截止时间 |
| 跨案件模型并发叠加 | 只有案件内并发限制 | 共享请求层使用默认 4 路进程级上限 |
| 同帧重复理解 | 主审、连续性和成因专项重复发送同一批帧 | 主审统一返回多任务结构；仅缺关键维度时启动专项 |
| 原生视频回退丢失开场复核 | 回退抽帧结果覆盖已验证开场字段 | 回退后无重复计费地合并已验证开场证据 |
| Web 二次后处理反转硬失败 | 公开字段投影先于共享策略，内部来源证据被丢弃 | 策略先消费完整结构，最后才生成公开白名单 DTO |
| 低龄模型标签绕过年龄门禁 | 高风险标签被等同于已确认低龄 | 只有高置信未满 9 周岁才强制授权人员关注；年龄不直接决定结论 |
| 错发/漏发语义串场 | “缺 A、多 C”仍按漏发聚合 | 分流到错发；可信仓库终审可覆盖过程备注 |
| 文件名触发人工 | `_1` 尾号被误当业务事实 | 删除文件名规则，只看受信事实、证据冲突与系统状态 |
| 跨租户规则串线 | 审核任务租户未贯通到工作台与模型 Prompt | 只接受服务端可信租户，治理接口缺租户声明即拒绝；每案冻结同一规则快照 |
| 规则治理竞争写入 | 编辑页与发布接口缺少版本前置条件 | 使用期望版本冲突检测、强制原因、历史版本和可预览回档 |
| 幂等键未绑定文件内容 | 同键同元数据但上传不同字节可能复用旧任务 | 保存后按文件大小与 SHA-256 计算请求哈希，不一致返回 409 |
| 公共 Job 嵌套字段泄漏 | 顶层白名单内的嵌套对象仍可能携带本地路径或内部字段 | 使用分层 DTO 白名单并递归清理私有键、本地路径和内部媒体信息 |
| 公开投影丢失决策字段 | API/Web 公开投影先删掉补图损伤确认字段，后处理会把可判案件降为复核 | 将策略依赖字段纳入受控白名单，并以投影后真实策略链做回归 |
| 生产 JWT 接受弱密钥 | 只排除两个默认值，公开启动默认值和一字符密钥仍可签发特权令牌 | 至少 32 字符并拒绝全部已知默认值；一键启动每次生成高熵运行时密钥 |
| 同 URL 并发下载互删 | 并发请求写同一目标，失败请求可能删除成功文件 | 每请求写唯一临时文件，完成后使用标准库原子替换 |
| 规则版本读取不一致 | 同一模型请求在 system/user 两处重复读库并注入 | 每案只解析一次版本快照，业务规则仅注入 system prompt；SQLite 使用短超时与最近可用快照 |
| 发布包混入工作区文件 | 复制入口未验证文件是否属于当前提交 | 甲方包所有源码、文档和 Web 资源必须可由当前提交追溯；三个演示视频使用固定 SHA-256 白名单 |
| 动态容量门禁误报 | 公开 Job 已移除内部摄取元数据，旧脚本仍读取 `metadata.ingestion.capacity_mode` | 改用公开资产数与材料管线接收、处理计数验收；真实 HTTP 任务 `RJ-3A9A63B93FA04E8D` 为 `62/62` 并通过 |
| 真实批次门禁误报 | 公开 Job 已移除逐单推理成本和完整源记录，旧脚本仍把两者当必返字段 | 以公开案件 ID、资产数量/总字节和媒体回链验收提交保持，以受控批次 token 汇总确认真实推理；任务 `RJ-5DC121AB23804740` 的 16 个文件、105,994,053 字节均一致 |

没有新增并行审核框架、样本 ID 特例或关键词规则。现有共享服务、结构化 Schema 和后处理路径足以承载修复，避免继续堆叠 Prompt 门槛。

## API 与 Web Demo 一致性

正式 API 与 Web Demo 共用 `review_service.service.postprocess_review`。正式 API 请求工作台返回未后处理结构，再统一后处理一次；Web Demo 直接调用同一函数一次。`defer_postprocess` 只允许持有共享服务令牌的内部调用使用，公开请求不能绕过策略。

一致性覆盖包括：输入就绪门禁、商品有伤开场硬条件、未成年人必交材料、人工复审等级、补件工作流、公开字段白名单、媒体签名地址和失败分流。对应回归位于 `tests/review_service/test_review_postprocessing_parity.py`、`tests/visual_review/test_workbench_public_access.py` 和 `tests/review_service/test_report_output_options.py`。

## 各场景业务理解与自我限制

### 商品有伤

系统分别判断封箱起始、面单、连续拆封、同物连续性、伤情可见性、首次出现时点和可能成因。补充图片只证明自身所见，不能改写主视频时点。视频加速是橙色信号：默认 1 FPS 仍可判断时不阻断；不足时有界升级 2 FPS；强化后仍影响关键事实判断才形成实质影响。

已解除“加速即不合规”“所有技术门槛同时满足才可给建议”“补图一律无效”“特殊商品外观差异即缺陷”等自我枷锁。仍保留证据回链和开场硬条件，因为它们属于甲方 SOP，而不是 Prompt 自我限制。

### 错发货

以版本化订单/SKU 为应收基准，核对实收商品身份、包装与面单归属、赠品/随机款规则。订单、实收商品、面单和包裹关联清楚时允许清晰照片链，不再一律要求完整开箱视频。

### 漏发货

同时核对应收清单、实收清单、全部包裹、分包物流、赠品/选款规则和可信仓库结果。“缺少应购 A 且多出未购 C”转错发方向。`568689` 的仓库终审已确认实收摆件与订单一致，因此系统应输出确定未漏发。

### 未成年人退款五类材料

分别审核身份材料、监护关系、退款承诺书、订单支付凭证和手机号归属。姐姐、学校登记表或分属两本户口本均不能自动闭合法定监护关系；电脑录入姓名不能替代亲笔签名；支付截图不能替代手机号归属；注销号码需要历史归属证明。

高置信未满 9 周岁时要求授权人员重点核对独立支付能力、支付密码来源和监护发现过程，但不得只凭年龄支持、拒绝或判定异常。公开报告只保留 `under_nine` 和年龄置信度，不暴露出生日期或精确年龄。

## 报告可读性、隐私与视觉

报告首屏固定为审核倾向、理由、下一步和关键证据；补件与人工复审互斥分流，失败只输出系统重试，不冒充用户缺件。技术字段折叠，公开 JSON/HTML 移除模型、渠道、Prompt、路径、token、成本、OCR 原文和身份标识；受控工作台仍可通过短期签名媒体回看证据。

桌面与移动端验收必须确认：首屏结论与结构化字段一致；长补件清单不截断；图片、原图和视频无 404；控制台无错误；客户 ZIP 的本地 `href/src` 零断链。

实际验收结果：Python 全量回归 `602 passed、51 subtests passed`；前端生产构建通过；真实 API 报告、140592 与业务规则后台桌面/移动专项验收 `8/8`，客服工作台与运营后台 Playwright 验收 `16/16`，无横向溢出、内容遮挡或控制台错误，证据媒体预览可打开。后台业务规则页支持高级角色访问、强制填写修改原因、追加/替换、版本历史、回档预览、并发版本冲突和未保存内容保护；公开页面不显示模型渠道、Key 或内部 Prompt。仅剩 FastAPI 生命周期和 Starlette TestClient 的 6 条依赖弃用警告，未影响当前行为。

三路无上下文终验已分别复核代码安全、业务报告和发布需求。终验发现并关闭了匿名生图额度消耗、DNS 重绑定 SSRF、任务租约短于取证与重试窗口、公开 JSON 暴露推理用量与成本、未成年人两份补件清单矛盾，以及未提交文件可参与验证但不进入交付包等发布阻塞；复核结论均为 PASS，剩余 P0/P1 为 0。

当前可接受的工程风险有三项：规则治理仍使用本机 SQLite，适合当前单节点私有化部署，扩展为多实例写入前应迁移到共享事务数据库；FastAPI/Starlette 依赖存在 6 条弃用告警；`598089` 的顶层分类仍有波动。三项均不应通过新增平行框架或样本特例掩盖。
