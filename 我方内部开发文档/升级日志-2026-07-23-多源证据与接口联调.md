## 本轮目的

把视觉审核从“上传视频给模型看”收敛为可部署的客诉证据服务：订单、SKU、包裹、物流、工单对话和媒体在同一案件中形成版本化证据包；输出审核建议，不越权执行售后动作。

## 代码变更

- `ReviewCaseMetadata.logistics` 改为有界的包裹与轨迹模型。
- 新增 `customer_risk_context` 脱敏聚合摘要，只用于服务端抽检路由，不进入模型。
- 发错货完整结论新增包裹-SKU 和已提交包裹/运单映射门槛。
- 离线样本不读取 `reply.json`；只有显式准备的 `conversation_predecision.json` 才会进入审核，并再次执行隐私和终判隔离。
- Gemini 原生与兼容网关共用端点构造和认证规则；Google 使用 `x-goog-api-key`，百度兼容端点自动使用 Bearer，也可由环境变量显式覆盖。
- 视觉 HTTP 调用新增脱敏结构化事件，只记录端点形态、状态码、重试次数、耗时和错误类型。
- Celery 显式注册 `sla_worker.tasks`，避免 worker 启动后任务未注册。
- Docker 主服务在 Celery 模式下关闭内联 SLA 调度，避免双调度；审核任务增加周期性租约回收，进程异常后可重新入队。
- 正式 API 拒绝未标记类型的客服消息、最终处理结果和含隐私的风险原因码。

## 新环境变量

| 变量 | 值 | 说明 |
|---|---|---|
| `VISION_REVIEW_GEMINI_AUTH_MODE` | `auto` / `bearer` / `google_key` | 主视觉通道认证方式，默认按端点识别 |
| `GEMINI_AUTH_MODE` | `auto` / `bearer` / `google_key` | 官方/备用 Gemini 通道认证方式 |

不在文档、日志或客户 ZIP 中写入真实 Key。内部 ZIP 按既有规则包含当前 `.env`，仅限我方研发交付。

## 接口边界

- 生产主入口：`POST /api/v1/review/jobs`。
- 预校验：`POST /api/v1/review/metadata/validate`。
- 结构化主结果：`job.result.review.advisory_assessment`。
- 报告可选：`output_options.include_html_report`。
- 批量：每案一个 job，共用 `batch_id`。
- 甲方真实订单、物流、CRM、身份核验和客服动作仍需联调；本仓库只提供契约和 Mock，不宣称已接通。

## Java 开发入口

1. 先阅读 `docs/delivery/after-sales-agent-integration.md`。
2. 以 `docs/delivery/openapi.yaml` 生成 DTO 或客户端。
3. 参考 `docs/delivery/java-client-sample.md` 使用 WebClient 流式上传，禁止 `Files.readAllBytes()` 读取大视频。
4. 在甲方适配层冻结订单/物流/工单快照，生成稳定的幂等键。
5. 不把人工标签、最终退款结果或完整历史客诉正文传入审核请求。
