# 工程师入门

版本：2026-07-11

## 1. 运行进程

| 进程 | 默认端口 | 入口 | 职责 |
|---|---:|---|---|
| FastAPI 主服务 | 8000 | `main:app` | 客服、人工台、后台、鉴权、审核编排、私域 Agent、指标 |
| 视觉审核服务 | 7861 | `poc.visual_review_poc.workbench_server` | 图片压缩、视频抽帧、分段审核、HTML 报告 |
| 前端静态资源 | 主服务同端口 | `dist/` | 用户端、`/desk`、`/admin` |

端口被占用时，测试命令可通过 `E2E_BASE_URL` 指向实际端口，例如当前本机常用 `http://127.0.0.1:8015`。

## 2. Windows 启动

```bat
setup_venv.bat
npm install
npm run build
一键启动-Windows.bat
```

单独启动：

```bat
venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
venv\Scripts\python.exe -m poc.visual_review_poc.workbench_server
```

## 6. 环境变量

- 变量名称以 `.env.example` 为准。
- `.env`、Key、数据库、日志、原始视频和运行时数据禁止提交 Git。
- 视觉服务和主服务必须读取同一部署环境中的必要凭证。
- 客户 ZIP 只有空值模板，生产凭证由部署平台安全注入。

## 7. 开发纪律

- 不让 Agent 直接调用甲方生产写接口；通过独立适配层和人工确认。
- 不把人工标签、标准答案或样本目录信息送入审核模型。
- 不向甲方/用户页面暴露模型渠道、Key、Prompt、原始响应和内部路径。
- 退款、补发、换货、拒绝和最终定责始终由人工或甲方系统执行。
- 不恢复旧陪伴、角色扮演或文字冒险入口。

## 8. 客户打包前置

先启动内部源码版主服务和视觉审核服务，然后执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/pre_release_internal_validation.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package_release.ps1
```

第一条命令验证内部部署、构建与关键回归；第二条命令会再次强制调用同一门禁，避免绕过。审核提示词、抽帧或模型路由变化时，第一条命令增加 `-RunModelBatch`。
