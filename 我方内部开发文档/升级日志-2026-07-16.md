# 升级日志 · 2026-07-16

## 评测边界纠正

- 撤回“双人标注、仲裁、理由完整、证据充分”对运行时 API 的错误硬门槛设计。
- 生产审核继续接受甲方当前可提供的业务字段和素材，不要求人工标签。
- 人工标签只在推理完成后用于离线统计；`ground_truth` 等字段继续由输入隔离规则拦截，防止泄题。
- 新增 `scripts/analyze_visual_review_results.py`，输出混淆矩阵、每类召回/F1、review 路由率、自动判定覆盖率、负向误接纳风险和置信度校准。

## 审核强度与单视频链路

- 标准服务新增 `strong` 档，兼容原 `strict`：全时间轴固定 1 FPS，最多 1200 帧。
- `forensic` 为 2 FPS，最多 1800 帧；`custom` 保持 0.1-2 FPS。
- 手动工作台单视频入口已从旧单次 24 帧调用切换到统一的分段并行引擎。
- Strong 单视频不再只是页面选项：1 FPS/2 FPS 按完整时间轴执行，每 24 帧一个模型分段。
- 结果新增实际策略、FPS、抽帧数、分段数和每段帧数。

## 非 AI 媒体取证

- 新增 `review_service/media_forensics.py`。
- 安装 `ffprobe` 后检查容器、流时长、音视频时长差、帧率/时基、编辑器/转码元数据。
- 最多读取 20,000 个媒体包，识别解码时间戳回退和异常时间轴间隔，并记录覆盖时长和截断状态。
- 所有信号均标记 `is_proof_of_editing=false`；不可用时明确返回 `unavailable`，不伪造“未剪辑”。
- 新增 `REVIEW_FFPROBE_TIMEOUT_SECONDS`，默认 20 秒。

## 有界升级建议

- 低置信、系统结论为 review、材料缺口或取证风险可生成 `recommended_escalation`。
- adaptive 建议升级 strong，strong/strict 建议升级 forensic。
- 当前只生成建议，不自动重复调用模型，不产生无界成本，也不自动执行退款、补发、换货、拒绝或定责。

## HTML 报告

- 显式拆分支持证据、反证、可疑帧和问题时间点。
- 证据可按帧号、图片号、时间戳和文件名回链到画廊。
- 新增置信度理由、材料缺口和模型局限。
- 公开报告继续过滤模型渠道、Key、内部 Prompt 和原始响应。
- 修复服务重启后运行时抽帧 URL 返回 404；只将 `tmp/visual_review_workbench` 加入只读媒体白名单，未扩大到整个仓库。
- Playwright 验证真实报告桌面/移动端 8/8 图片加载、无 4xx、无横向溢出。

## 商品有伤因果与离镜专项通道

- 商品有伤在 `strong/strict/forensic` 档自动启用独立因果扫描，分开输出损伤存在性、首次出现时点、生产/原包装、物流运输、用户拆封操作等成因假设；`adaptive` 默认只执行主审核以控制成本。
- 只有同一视频、同一对象、同一部位、同一 `chain_id` 且帧序递增的动作前/中/后证据，才允许形成直接因果链。
- 主体连续性按快递包装、商品包装、争议商品分别跟踪；报告展示离镜前、离镜起点和重新入镜帧。
- 专项通道出现超时、漏帧、重复帧或结构不完整时，不采用部分结果形成确定结论，统一降级为人工复核。

## 发错货与漏发货履约对账

- 新增 `fulfillment_baseline`、`evidence_coverage` 标准契约和输入就绪检查。
- 每个应发商品行必须可唯一识别并带应发数量；漏发场景还必须提供版本、赠品/特典声明、包裹数和包裹到商品行映射。
- “全部上传/全部展示”的布尔声明不足以通过校验，必须同时提交实际 `package_ref` 或物流单号映射。
- 模型分段输出按包裹去重聚合，跨包裹数量累加；未知包裹、未确认物品或不完整铺开展示均强制 `review`。

## 置信度与调用统计

- 报告拆分主分段模型自评分、损伤成因分、履约对账分、主体可见覆盖率和规则降级后决策分。
- 未经独立留出集校准前，模型自评分不等同于正确率。
- 采样计划、运行结果和 HTML 报告均分别统计主审核、主体连续性、损伤因果三通道的调用数、Token、时延和估算成本。
