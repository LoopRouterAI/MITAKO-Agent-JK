# POC 展示与联调开发说明

更新时间：2026-08-14

状态：已过期。当前四场景业务契约、模型目录和验收入口以 `docs/product/四场景审核业务决策与报告契约-20260812.md`、`docs/product/四场景审核主线进度-20260814.md` 为准；本文件只保留早期 POC 联调背景。

## 面向研发的部署重点

- 所有甲方真实后台接口在 POC 阶段只能使用 Mock 或本地模拟服务。
- 客服主链路、人工接管、后台配置、视觉审核工作台需要分别启动和验收。
- 视觉审核不再引入传统目标检测训练路线，统一以多模态模型选型、结构化证据链和人工复核阈值为核心。

## 视觉审核 POC 展示流程

1. 启动视觉审核工作台。
2. 选择一个业务队列：开箱视频、商品有伤、资料审核。
3. 上传本地视频或输入公开视频 URL。
4. 选择取证密度：普通 1 FPS，严格连续性/离镜检查使用 2 FPS。
5. 提交审核后查看客服摘要报告。
6. 内部验收时打开 `--internal-report` 报告，检查模型原始返回、结构化解析、Token、成本、耗时和每次送审帧数。

## 当前模型边界

- 默认主审：`gemini-3.5-flash-lite`。
- 显式高质量候选：`gemini-3.7-flash`，仅允许管理员明确启用，不进入自动兜底。
- 其他视觉审核模型均已退出当前运行目录；历史名称不得用于配置或自动路由。
- API 成功不等于结构化成功；只有通过本地业务字段校验才参与验收。

## 甲方需准备的联调材料

- SOP、FAQ、培训文档、售后政策、商品资料。
- 三大视觉场景正负样本，最少每类正负各 50 条。
- 每条样本包含用户诉求、视频、补充图片、订单商品名、SKU、规格、仓库/商品主数据、最终人工结论、人工结论原因。
- 未成年人资料必须脱敏，并由甲方确认外部模型使用范围。

## 不可承诺项

- 不自动定责、拒赔、退款、补发。
- 不替甲方改造真实业务系统。
- 不把 POC 小样本命中情况包装成生产准确率。
- 不在甲方可见页面展示模型供应商、Token、成本、端点或内部调试日志。
