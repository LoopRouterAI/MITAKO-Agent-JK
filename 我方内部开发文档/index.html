打通数据流

01 工单甲方 Java 后台或验证样例创建工单上下文。
02 材料视频、图片、文本、SKU、物流、历史对话聚合成证据包。
03 队列按任务类型、优先级、创建时间进入审核队列。
04 审核抽帧、压缩、组 prompt，输出结构化审核结果。
05 报告生成客服可读 HTML，支持图像浮层与视频时间点。
06 人工坐席抽检、逐条复核、补件或升级。
07 回写人工结论回写甲方工单，Agent 只消费公开摘要。

状态机

状态说明系统动作
CREATED任务创建校验幂等键，写入任务
MATERIAL_READY材料齐备进入审核队列
AI_REVIEWING审核中抽帧、组证据包、调用审核模型
NEED_MORE_MATERIAL材料不足生成补件建议
REVIEW_COMPLETED审核完成生成客服可读报告
HUMAN_CONFIRMED人工确认回写甲方工单
FAILED_RETRYABLE可重试失败429 / 5xx 指数退避

队列、重试与大视频

429 必须重试

使用 1s、2s、4s、8s、16s 指数退避，到达上限后进入可重试失败状态，坐席看到友好失败原因。

抽帧后台配置

支持 fps、maxFrames、probeSeconds、strictContinuity，严格审查时提高抽帧密度。

大视频先处理

不要直接上传超大视频。先本地抽帧、压缩、切片，再送审核模型，报告保留时间戳映射。

内部落地计划

阶段目标验收
P0固定三类视觉审核入口、报告样式、浮层预览和文件夹扫描三类样例均能生成客服可读 HTML 报告
P1新增 review_task 数据模型、队列和人工复核状态任务状态可查询、可重试、可回写
P2新增甲方 Java 适配层与回调客户端测试环境完成创建任务、查状态、回写结论
P3收集正负样本进行模型稳定性和成本评测每类正负样本至少各 50 条，有人工理由

合规边界

客服 Agent 可以有 MBTI 服务人格，但必须表现为专业、同理、有边界的客服助手。不能做虚拟陪伴、恋爱、角色扮演或无人最终裁决。
