# 升级日志 · 2026-07-17

## 甲方问题

0716 客户测试版通过 `/api/v1/review/jobs` 提交 3 个视频样本可审核，但视觉工作台通过文件夹上传时均提示视频无法读取。甲方定位到样本目录包含 `__MACOSX/._*.mp4` 等 macOS AppleDouble 资源副本。

## 根因

- 工作台目录上传只按扩展名接收素材，没有复用正式审核 API 的媒体内容签名校验。
- 文件名清洗发生在隐藏文件识别之前，`._002.mp4` 可能被清洗为看似正常的 `002.mp4`。
- `load_case_bundle` 顺序解码全部视频，单个坏视频会中断整个工单。
- 工作台上传目录使用秒级时间与报告数量组合，同秒并发存在目录复用风险。
- 客户包不包含内部 `sample_001~004`，但页面仍显示内置样本按钮。
- 公开工作台报告的 `inference_estimate` 可能泄露 Token、成本和内部调用统计。

## 代码整改

- 新增 `review_media_safety.py`，统一系统文件识别、允许后缀、媒体内容签名和公开跳过原因。
- `poc/visual_review_poc/workbench_server.py` 在文件名清洗前过滤 `__MACOSX`、`._*`、点号路径、`.DS_Store`、`Thumbs.db` 和 `desktop.ini`。
- 单文件和目录上传均校验实际媒体内容；目录上传对无效媒体逐文件跳过并返回 `ingestion`。
- 上传目录改为 UUID 原子创建；限制单次目录文件数；Windows 保留设备名自动加安全前缀。
- `model_selection_e2e.load_case_bundle` 隔离无法解码的视频，存在其他有效视频或图片时继续审核，并返回 `media_warnings`。
- 正式审核 API 跳过系统隐藏文件并在任务 `metadata.ingestion` 中记录接收、接受和忽略数量。
- 工作台浏览器预过滤系统文件，提交时只构造有效文件的 `FormData`，页面显示浏览器与服务端两级回执。
- 内置样本不存在时自动隐藏按钮；批量内置样本必须全部成功才返回成功。
- 公开工作台报告删除 `inference_estimate`、Token、成本和内部调用统计；正式 API/内部运维统计保持不变。
- 客户编译运行时新增 `review_media_safety.py`。
