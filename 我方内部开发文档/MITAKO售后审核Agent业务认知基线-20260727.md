## 1. 商业目标

甲方需要的不是一个替代客服说话的聊天机器人，而是一套能降低客诉证据审查工时的审核服务：自动读取订单、SKU、物流、用户媒体和必要对话，输出可回链的事实结论、证据强度、疑点、人工复审等级与人类可读报告，再由甲方业务规则决定退款、补发、换货、补偿或拒绝。

当前人力排序为：商品有伤 > 漏发货 > 发错货 > 未成年人退款。有伤、漏发、错发需要查看图片/视频并与仓库协作，约占售后审核人力的 80%；未成年人案件量较少，单次审核不重，但材料经常多轮补交，约占 20%。因此 Demo 首要价值指标不是“能否生成报告”，而是：在可审案件中给出明确事实建议，减少无意义的全量人工复核，同时不把证据不足包装成确定结论。

## 2. 必须分开的四层结论

| 层级 | 回答的问题 | 系统输出 | 是否可由历史最终处置替代 |
|---|---|---|---|
| 证据事实 | 媒体与业务基准支持什么事实 | `positive / negative / review`、证据链、分数 | 否 |
| 成因与责任倾向 | 损伤何时发生、哪方更可能负责 | 原因候选、支持/反证、独立置信度 | 否 |
| 人工复审 | 是否必须由授权人员看原始证据 | `required / optional / not_required` | 否 |
| 经营处置 | 退款、补发、换货、补偿或拒绝 | 由甲方系统、SOP 和授权人员执行 | 否 |

事实层的 `positive` 只表示“现有证据支持本次事实诉求”，不是自动退款；`negative` 只表示“现有证据不支持本次事实诉求或命中甲方已批准的材料规则”，不是自动拒绝。平台责任、客户责任和经营弹性必须单列。

## 3. 三种业务现实

1. 平台责任倾向：证据链支持发货、包装、运输或商品原始状态问题。
2. 客户责任倾向：连续证据直接显示客户操作造成损伤，或完整证据不支持其主张。
3. 经营弹性：证据与责任都不足以唯一决定，但金额、用户关系或平台策略允许多种处置。该类应标记为 `discretionary_policy`，不能伪装成模型事实。

## 4. 场景正确理解

### 4.1 商品有伤

- 首先判断伤情是否清晰可见、位置和严重程度；再独立判断发生阶段与责任倾向。
- 明确可见伤情可以形成事实 `positive`，即使物流、原包装或用户操作成因仍不确定。
- 只有连续动作前后证据直接显示用户造成损伤时，才可给客户责任倾向。
- “完整视频未见主诉伤情”的 `negative` 必须满足甲方批准的版本化门槛：诉求部位、同物关联、必检视角、可见覆盖、连续性、补充图片关联、媒体取证和置信度。
- 加速不等于拼接剪辑。一镜到底且关键过程可慢放观察时可继续审核；跳切、拼接、码流异常是独立风险信号。
- 主视频、补充图片和官方商品图是三种不同证据来源：主视频用于开箱过程与伤情可见性，补充图片用于特写佐证，官方图用于标准外观对照。三者不得在聚合时互相冒充。
- 不合规开箱视频可形成 SOP 层面的 `negative` 分类建议；若补充图显示瑕疵，报告必须同时写明“补充图支持瑕疵存在”和“补充图不能替代合规开箱视频”，并给出最低档补偿规则仅供甲方客服参考。
- Agent 在主视频中发现了人工未发现的疑似伤帧时，属于证据分歧，应展示该帧及前后片段并进入人工复核；不得用历史标签静默覆盖模型所见。

### 4.2 开箱视频合规

- 这是证据质量能力，不是独立售后责任结论。
- 分别输出抽帧首尾覆盖、媒体技术取证、开箱过程完整性和争议商品连续性；四者不得互相替代。
- 离镜秒数必须如实记录。超过配置阈值影响证据强度或触发补件，但不能单独证明调包、剪辑或欺诈。

### 4.3 发错货

- 需要订单 SKU、商品名、规格/款式/角色、数量和适用的随机/隐藏/特典规则作为应收基准。
- 用户媒体用于识别实收物；官方商品图只作为标准外观参考。
- 商品身份、订单基准和证据足够时可输出明确正负；缺唯一基准或随机规则时只能降级，不得靠视觉猜订单。

### 4.4 漏发货

- 必须对账“应发清单”和“视频已展示清单”，并核对包裹数、包裹-SKU 关系、物流状态、赠品/特典/套装规则。
- 一个物流单号不证明未分包，多个物流单号也不自动证明分包关系。
- 尚有包裹在途、视频未覆盖全部包裹/物品或包裹映射不明时，只能给证据不足；这是数据缺口，不是模型能力不足。

### 4.5 未成年人资料

- 该场景不是视频事实分类，必须分为材料存在性、跨材料字段一致性、甲方权威真实性核验三层。
- 年龄与行为、监护关系、承诺书、订单支付和手机号归属字段可以做视觉一致性检查。未满 10 周岁只触发支付来源、账号设备控制、支付授权和监护经过的加强核验，不能仅凭年龄直接下结论。
- 身份证、运营商实名、平台订单和支付真实性属于可选的权威核验层。当前甲方没有对应接口时默认关闭，不阻断视觉初审；未来可由甲方接口或授权人员开启严格核验。当前 POC 不得宣称已完成法定真伪验证。
- 五类必交材料按 SOP 核对：未成年人及监护人身份证明、监护关系证明、双方签字承诺书、订单/支付凭证、绑定手机号归属证明。户口本相关页或出生证明可按规则二选一。

## 5. 人工复审策略

| 等级 | 适用情况 | 建议动作 |
|---|---|---|
| 必须复审 | 服务失败、实质证据冲突、低于必须复审阈值、权威核验待完成 | 授权人员核对原始证据 |
| 可抽检 | 事实结论明确，但存在不影响事实的连续性、轻度取证、成因或责任不确定 | 按甲方风险偏好抽检 |
| 无需复审 | 事实证据链达到配置门槛且无阻断信号 | 甲方系统按已批准规则继续 |
| 先补材料 | 缺口可由用户补交解决 | 直接补件，不先占用人工席位 |

降低人工率不能靠放松发错/漏发的业务基准，也不能靠抬高模型分数。正确做法是把非阻断疑点降为“可抽检”，把真正材料缺口走“先补材料”，只把失败、冲突和权威核验放入“必须复审”。

## 6. 黄金样本集

先冻结 100 个视觉案件：商品有伤、开箱合规、发错货、漏发货各 25 个。未成年人资料因任务性质不同，另建材料审核集。

每个黄金案件至少包含：

- 稳定案件 ID、场景、诉求范围与标签版本；
- 允许进入推理的用户媒体、最小化订单/SKU、物流/包裹和审核时点前对话；
- 不进入推理的人工标注、仓库终判、最终补偿/退款结果；
- `evidence_fact_label`：证据支持、证据不支持或证据不足；
- `responsibility_tendency`：平台、客户、不确定；
- `business_disposition`：历史处置及是否属于经营弹性；
- 事实理由、关键帧/材料引用、证据缺口和适用 SOP 版本。

黄金集不要求把所有历史案例包装成绝对客观真相。标注者无法一致判断时应明确记为 `review` 或 `discretionary_policy`，不强迫二选一。

## 7. 评测与验收

- 工程成功率、失败率、延迟、模型调用数、Token 与估算成本；
- 事实三分类混淆矩阵、正负召回、确定性覆盖率和人工复审率；
- `required / optional / not_required / request_more_material` 分布；
- 按场景、证据完备性和策略版本分层结果；
- 报告标题、事实结论、复审等级、流程建议和视频论证的矛盾次数；
- 目录名、`annotation.json`、`reply.json` 和最终处置进入模型请求的次数。

在黄金集冻结前，只能称为 Demo 工程回归，不能宣称生产准确率。冻结后再根据结果校准置信度阈值；当前分数仍是未校准证据强度，不是客观正确率。

## 8. 接口与部署边界

- 甲方业务系统统一调用 `/api/v1/review/*`；网页工作台用于 UAT、人工复测和阅读报告。
- 路径由调用方决定，服务端只接收 multipart 文件或未来双方确认的对象存储引用，不依赖我方 `E:` 盘。
- `include_html_report=false` 可只取结构化字段；开启时返回同一任务的 HTML 报告。
- 真实包裹-SKU 映射、仓库核验、对象存储/转码回调仍是 `customer_integration_required`。未成年人权威核验仅在甲方显式启用严格策略时是 `customer_integration_required`，默认视觉初审不依赖它。

## 9. 本轮代码修正

- 商品有伤：可见伤情事实与损伤成因分离；成因不确定不再强制覆盖明确伤情事实。
- 补充图片：审核通道可以单独确认“补充图中可见伤情”，但不得据此改写“主视频是否看见伤情”；同物关联、形成时间和责任仍分别判断。
- SOP 分类：服务端批准策略可将“经完整时间轴确认的不合规开箱视频”映射为 `negative` 审核倾向；加速字段不参与该规则，补充图片只生成最低档补偿或复核参考。
- 连续性：商品连续性不确定只降低成因/责任可信度；发错、漏发和完整视频未见伤情仍保留严格连续性门槛。
- 复审：连续性不确定作为可抽检信号，不再自动变成必须复审。
- 报告：首屏先展示“按照 SOP 的审核倾向”，再展示“建议进一步评估”；主视频和补充图片分别呈现，公开页不显示内部策略编号。
- 视频论证：明确解释抽帧、媒体取证、开箱完整性和商品连续性四个维度，并把内部状态码转换成人类可读文案。

## 10. 本轮验收证据

- 同一真实案件 `588609` 通过正式 API 三次盲测，均只上传用户诉求、3 份媒体和安全订单快照，未上传目录标签、`annotation.json`、`reply.json` 或 `manifest.json`。
- 首次任务 `RJ-7213A46CF99E4AAC` 暴露旧建议对象内部矛盾；第二次任务 `RJ-862F25E4E8E04FAB` 证明同一材料的模型伤情存在性会在 `confirmed / uncertain` 间波动，但其 `adopted_evidence` 已稳定记录补图伤情、0.90 证据分和同物关联。
- 最终任务 `RJ-765B0EA12FB04FE9` 返回 `positive / 0.65`、伤情 `confirmed`、成因 `indeterminate`、人工复审 `optional`、流程 `continue_by_customer_policy`；媒体取证完成，HTML 报告可读取且不含“需要VIP客服复核”或内部媒体状态码。

## 11. 剩余风险与唯一下一入口

本轮已完成机制性全 REVIEW、建议对象矛盾和报告口径的工程闭环；这不等于 23 个历史样本已达到生产准确率。历史标签仍有口径漂移，继续全量复跑只能得到 Demo 分布，不能得到可信准确率。下一步唯一入口是由双方冻结 100 案黄金集，再以正式 API 输出按场景的三分类混淆矩阵、确定性覆盖率和人工复审率并校准阈值。若仍出现异常高 REVIEW，应按缺口代码区分业务输入不完备、模型证据不足与工程失败，禁止再用单一“模型保守”解释。
