# 2026-07-20 未成年人资料字段一致性审核升级

状态：当前有效
适用：Python 审核服务、Java 网关、测试、实施、运维、产品
对应反馈：0718 版本只判断资料齐全，不判断资料之间的字段是否一致。

## 有效结论

旧版根因不是漏传图片，而是审核管线在完成材料分类后直接按五类材料数量生成 `positive/pass`。该置信度是材料完整性参考，不是字段一致性或真实性分数。

本版将未成年人资料审核拆为三层：

1. 材料完整性：确认所有图片已处理以及五类材料是否存在。
2. 视觉字段一致性：模型读取字段进行跨材料比较，服务端只保留受控状态、风险码和证据图片编号。
3. 权威真伪验证：身份证、运营商实名、订单和支付依赖甲方接口，当前固定为 `customer_integration_required`。

## 调用链

`/api/v1/review/jobs`、`/api/review-folder` 和 `/api/review-folders-batch` 最终共用：

```text
model_selection_e2e.call_model_chunked
  -> run_minor_material_pipeline
      -> minor_material_inventory（全图片分批）
      -> minor_process_video（过程视频）
      -> minor_material_consistency（五项并行）
      -> aggregate_minor_material_results（确定性门禁）
  -> report_renderer / report_assessment_sections
```

五项一致性检查：`identity_age`、`guardian_relationship`、`commitment_signatures`、`order_payment`、`mobile_realname`。

## 安全 Schema

模型可以在单次推理中读取字段，但输出只接受白名单：

```json
{
  "schema_version": "minor_consistency_v1",
  "consistency_check": {
    "check_id": "guardian_relationship",
    "field_results": [
      {
        "field_name": "relationship_link",
        "status": "matched",
        "visibility": "partial",
        "evidence_image_indices": [5, 6]
      }
    ],
    "tamper_risk": "low",
    "risk_reason_codes": ["no_obvious_risk"]
  },
  "authoritative_verification": "customer_integration_required"
}
```

服务端忽略模型返回的未知字段和自由文本，不持久化字段原值、尾号、哈希或 OCR 原文。

## 确定性门禁

- 五类材料齐全但一致性未执行：`review`。
- 任一检查 `uncertain`、`not_assessed` 或调用失败：`review`。
- 任一检查 `mismatched`：`review`，只表示差异复核，不自动拒绝。
- 五项全部 `matched`：只把 `minor_material_assessment.visual_precheck_status` 标记为 `passed`；案件级仍输出 `review/manual_review/REVIEW`，且 `business_action_allowed=false`、`human_required=true`，等待权威接口或授权人员终审。
- `matched` 可接受 SOP 允许的部分打码，只要至少两张图片中的可见片段足以相互支持。
- `mismatched` 只在至少两张图片中的同一字段完整清晰可见且明确不同时成立；遮盖、裁切、主副卡关系不明统一降为 `uncertain`。

## 配置

| 环境变量 | 默认值 | 说明 |
|---|---:|---|
| `REVIEW_MINOR_IMAGE_BATCH_SIZE` | 4 | 材料分类每次送模图片数，最大 6 |
| `REVIEW_MINOR_SCHEMA_RETRIES` | 1 | 图片编号遗漏时的结构重试次数，最大 2 |
| `REVIEW_MINOR_CONSISTENCY_IMAGE_LIMIT` | 8 | 单次一致性推理的图片分段上限，范围 4 至 12；服务会分段覆盖该检查关联的全部图片 |
| `REVIEW_CHUNK_WORKERS` | 2 | 分段与一致性检查并发数，最大 4 |

不新增模型 Key。沿用现有视觉服务模型配置；不得把真实 Key 写入 Git、报告或本文件。

## 剩余风险

- 当前视觉服务的报告和媒体入口用于内部/VIP 复核，生产必须由主服务或反向代理执行租户鉴权，不得直接暴露 `7861`。
- 视觉服务报告与媒体链接已经使用 HMAC、路径绑定和有效期签名；生产必须配置固定 `VISUAL_REPORT_SIGNING_SECRET`，否则进程重启后旧链接会失效。
- 视觉一致性不能替代身份证、运营商、订单和支付系统的权威核验。
- 144989 只证明本轮链路和安全门禁，不代表未成年人资料场景总体准确率；仍需甲方冻结盲测集评估。
