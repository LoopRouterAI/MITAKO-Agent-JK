# 2026-07-31 商品有伤 SOP 与报告一致性升级日志

状态：当前有效

更新时间：2026-08-01 04:56:00 +08:00

## 本轮目的

根据 589098、615437、593840、617109 的反馈，修正“模型看到了证据，但整案仍被旧守卫、文本规则或报告兜底改写”的工程问题。目标不是为四个样本硬编码答案，而是让所有商品有伤案件沿同一条结构化证据链得到可解释的 SOP 倾向。

## 已删除的错误方向

- 不再用目录名、`manifest.tag`、人工标签或最终处置推断场景或审核答案。
- 不再因用户原话包含“审核不通过、拒绝”等词就删除对话；只按 `annotation/label/ground_truth` 等结构化字段和评测文件来源隔离答案。
- 不再把分段模型的 `positive/negative` 做整案投票；分段只提供证据，整案由结构化事实和服务端批准 SOP 生成。
- `damage_causality` 证据守卫不再提前改写整案标签、置信度或人工路由，只输出 `damage_evidence_tendency`；商品有伤分类建议集中到唯一的版本化 SOP 层。
- 0731 默认 SOP 不再把媒体取证、特写、同物关系等非致命项全部串成硬门槛；完整时间轴已审核、未见所诉损伤且无冲突时可给出明确倾向。原严格门槛保留为独立策略版本。
- 不再用中文损伤词、否定词、包装类型词表或分段结束文本裁决伤情。
- 不再因连续性或损伤成因专项局部失败就丢弃其他成功证据或强制整案 `review`。
- 报告层不再改写“外包装”等证据术语，也不再把所有 `review` 统一描述为“证据不足、必须 VIP 复核”。

## 当前证据链

1. 主审核分段只输出画面事实、证据引用和自评分。
2. 连续性专项按源时间戳计算争议商品可见、遮挡、离镜和重新入镜状态。
3. 损伤专项要求 `damage_visible + same_item_linkage + 可回链帧`，否则不得聚合为主视频已确认伤情。
4. 主视频、补充图片和官方参考图分别记录，不互相冒充。
5. 服务端批准的 SOP 根据开箱完整性、可观察范围、连续性、补充证据关联、媒体取证和证据分数形成倾向。
6. `advisory_assessment` 再给出必须复审、可抽检、无需复审或先补材料；任何结果都不自动退款、补偿、换货或拒绝。

## 三项能力核验

### 视频速度与离镜

- `media_forensics.assets[].playback_speed_assessment` 输出技术取证状态。
- 没有原始时钟或可信基准时，`constant_speed_multiplier=null`、`status=unknown`，不会猜“加速几倍”。
- 模型可独立给出画面节奏疑似加速信号；报告明确它不是精确倍速测量。
- `object_continuity_assessment` 输出离镜起止帧、源时间戳、估计秒数、采样分辨率和上下界。

### 未成年人证件与关系

- 支持身份证、户口本、出生证明、护照等资料类型。
- 支持签发国家/地区、身份角色、年龄、监护关系和跨材料一致性初审。
- 公开 DTO 不输出证件号、手机号、地址或 OCR 原文；不可读字段为 `unknown`。
- 标准模式不依赖甲方当前不存在的权威接口；视觉一致不等于法定真伪。

### 稳定性与模型路由

- `REVIEW_CHUNK_WORKERS` 控制单案分段并发，当前硬上限 4；未成年人独立使用 `REVIEW_MINOR_WORKERS`，硬上限 8。
- 408、429、500、502、503、504 等可重试压力会降低后续波次并发；成功波次逐步恢复。
- 重试优先遵守 `Retry-After`，否则按指数退避并加入抖动。
- 只有可重试错误才进入下一个已配置渠道；认证错误和其他非重试错误立即停止。
- 渠道与请求审计只保留在内部结果，公开 API 与 HTML 不显示供应商、Key 或内部端点。

## 真实与自动验证

- 自动回归：视觉审核与审核服务 `334 passed`、`39 subtests passed`；报告与损伤专项定向回归 `29 passed`。
- 四个中立真实案件均完成结构化结果和 HTML；1 个专项完整、3 个保留局部失败，未读取路径标签或人工答案。`case_001` 395 帧、墙钟约 498 秒，其余三案合计约 1395 秒。
- 正式异步 API 任务 `RJ-1FF3D0A5AE80416C`：105.99MB、16 文件、35 帧、6 次模型调用，任务成功；公开 JSON 无渠道/模型明细，时间轴覆盖字段完整，HTML 报告可访问。
- 当前实测说明高密度双专项全量审核的主要成本是模型调用量。不要通过跳过证据或提高未验证并发来制造快结果；生产并发应以供应商限流和黄金集效果压测为准。

## 部署注意

- 必须安装 ffprobe，或设置 `REVIEW_FFPROBE_PATH`；否则媒体技术取证无法生效。
- 主服务调用正式 `/api/v1/review/*`，视觉服务只在内网部署。
- 研发机盘符不属于接口契约。甲方通过 multipart 上传、未来对象存储引用或甲方自己的挂载路径提供素材。
- `.env` 只存在内部安全交付或部署 Secret 中，不进入 GitHub 与甲方测试包。
