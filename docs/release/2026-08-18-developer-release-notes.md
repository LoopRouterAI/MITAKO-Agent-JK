## 一句话摘要

本版本把“多场景视觉审核 POC”整理为可交接的四场景证据链：场景 Prompt/Schema、材料齐全性、媒体预处理、确定性业务对账、API/Web 报告、JKAdmin 策略治理和发布门禁均有明确边界；同时把研发代码包与验收证据包拆开。

## 相比 2026-08-17 的主要变化

### 1. 交付物结构

- 内部研发 ZIP 不再复制大体量黄金样本视频和 8 案离线敏感 WebP。
- 新增独立 `MITAKO_Agent-four-scenario-evidence-YYYYMMDD.zip`，专门保存 8 份 HTML、119 个 WebP、索引和 manifest。
- 甲方运行 ZIP 仍保持源码、Prompt、人工标签、数据库和原始个人材料隔离。
- 发布回执改为同时记录三类包的边界、大小、SHA256 和提交号。

### 2. 四场景审核链路

- 商品有伤：开箱动作、封箱、面单、连续性、伤点和成因链分层；普通伤缺证据进入补件/复核，严重结构伤保留窄例外，低可靠速度/剪辑信号只黄标。
- 发错货：按应收基线、同包裹关系、实收身份、系列/版本/形态/部件逐项对账，静态证据不被夸大为终态。
- 漏发货：区分用户视频、静态材料、分包/赠品和仓库终核；不把缺视频机械判负，不把商品构成误解自动当漏发。
- 未成年人退款资料：五类材料逐项交通灯、身份证正反面、关系闭环、承诺书字段、订单/支付双门槛和手机号一致性；材料缺口输出补件，不把材料失败翻译成退款拒绝。

### 3. Prompt、Schema 与数据流

- 模型只提取可见原子事实、置信度、理由和证据引用。
- 业务结论由程序完成材料齐全、包裹/订单对账、仓库状态、人工路由和公开 DTO 投影。
- API、Workbench 和 HTML 复用同一公开投影，不各自重算结论。
- 主视频证据、补图证据、静态路线和仓库事实保持来源隔离，避免补图越级替代主链。

### 4. 媒体与性能

- 图片逐张 WebP，不拼图；只有超过 4K 才降到约 2K，优先无损，必要时质量 90。
- 视频在 100MB、超过 2K、超过 24FPS 或平均码率超过 6Mbps 时评估完整时长代理；默认 VP9，保留原片哈希和转码版哈希。
- 默认原生视频 1FPS；昂贵的全片 WebP 回退默认关闭，失败时优先系统重试而不是无条件烧模型调用。
- E 盘可作为运行媒体目录，避免 D 盘被转码临时文件占满。

### 5. 管理后台与前端

- JKAdmin 可管理模型启停、默认模型、审核强度、媒体预算和高成本回退开关；每次修改强制填写理由、记录账号/时间/版本并支持回档。
- 底层 Prompt、Schema、Key 和供应商信息不暴露给甲方客服人员。
- 客服工作台、报告页、Pad/手机端统一圆角、字号、触控尺寸、证据预览和错误文案。
