# MITAKO Agent v3.1 Beta 开发者说明

发布日期：2026-08-19

版本标签：`v3.1.0-beta.1`

## 变更摘要

本版承接 v3.0.0-beta.1，重点收口客服对话链的真实状态和交付说明：

- 公开状态只由事实和工具回执生成，用户口述不会被当成已上传、已建单或已完成。
- `transfer_to_chatwoot` 在动作最终归一化后回写公开 brief，失败动作不会残留成功排队文案。
- API、用户端和坐席端继续共用 `conversation_state`，失败、排队、升级和等待人工保持同源。
- 新增甲方可读的 10 项问题闭环 HTML，以及 API/Web Demo 功能测试 HTML。
- 发布说明将“代码已修复”和“等待甲方真实接口”分开，避免把联调依赖误报为代码缺陷。

## API 验收重点

1. `POST /api/v1/chat` 的 SSE `done`、`transfer`、`card` 必须携带同一公开 `conversation_state`。
2. 只有真实附件、工具回执、队列回执和时间戳可以产生完成态。
3. 公开 DTO 不得出现模型、渠道、Prompt、Key、内部工具名和个人证件原值。
4. 视觉审核统一走 `/api/v1/review/*`，工作台内部路由不作为 Java 生产依赖。

## Web Demo 验收重点

- 用户端、坐席台、JKAdmin、视觉工作台分别验证 PC、Pad 和手机竖屏。
- 转人工成功、失败、等待回执必须在 API、用户端和坐席端显示同一个状态。
- 视觉审核报告验证首层结论、材料齐全性、场景专属详情、证据跳秒和签名媒体。
- JKAdmin 业务策略修改必须有角色、理由、时间、版本、历史和回档记录；技术 Prompt/Schema 不向客服主管开放。

## 外部联调边界

以下能力需要甲方提供真实接口或回调后才能宣称完成：订单/SKU、包裹/仓库、历史客诉、改址写入、隐私删除、退款执行、CRM/企微/飞书回写。当前代码只能输出待执行、失败或人工入口，不伪造业务成功。
