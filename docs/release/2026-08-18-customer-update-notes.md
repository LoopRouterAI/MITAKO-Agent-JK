# MITAKO Agent 2026-08-18 甲方用户更新说明

状态：当前有效
更新时间：2026-08-18 03:00:00 +08:00

## r2 重点变化

- 同时送审多个工单时，系统会按服务器当前资源排队处理；资源紧张时稍后继续，不会把所有视频同时塞进内存。
- 送审前的视频和图片处理继续保留原片，报告使用可追溯的送审版本；客服可以在报告中查看处理状态和证据。
- 审核服务新增更完整的运行记录，便于技术人员定位等待、失败和重试；客服页面不展示模型渠道、密钥或内部指令。

## 这次版本解决了什么

这不是只换了页面颜色的更新，而是把审核过程重新整理成“先盘点材料，再看证据，最后给客服建议”的四场景版本。报告会明确告诉客服：材料够不够、看到了什么、哪些结论可靠、下一步该补什么或查什么。

## 客服能直接感受到的变化

- 首屏先显示整体审核建议、确定性、材料是否齐全和下一步，详细证据默认折叠，减少阅读负担。
- 商品有伤、发错货、漏发货、未成年人退款资料使用不同报告，不再用一套泛化模板。
- 证据可以查看图片；视频证据可以跳到对应时间并全屏查看。
- 图片和视频送审前会自动检查清晰度、大小、时长和编码，原片仍保留，客服可以知道报告基于哪个版本。
- PC、Pad 和手机端统一交互，重要按钮有足够触控尺寸，报告不会因为长文案挤出屏幕。

## 四个场景现在如何判断

- 商品有伤：先看初次开箱和争议商品是否形成证据链；严重结构伤会重点提示，普通证据不足会明确补件或复核，不把模糊画面说成确定伤点。
- 发错货：对比订单应收商品和包裹中实际收到的商品，关注系列、版本、形态和配件；图片不足时提示人工或仓库核对。
- 漏发货：对比应发清单、实收商品、分包和赠品规则；必要时提示查仓，不因为没有视频就直接否定用户。
- 未成年人退款资料：逐项核对五类资料、关系、签名、订单支付和手机号；缺哪一项就写哪一项，不把材料问题直接写成用户欺诈或退款拒绝。

## JKAdmin 可以调整什么

客服主管可以调整审核强度、媒体处理预算、是否启用前置开箱视频检查，以及是否允许高成本全片抽帧回退。每次调整都必须填写不少于 6 个汉字的理由，系统记录账号、时间、版本和原因，并支持回档。

底层 Prompt、Schema、模型密钥和供应商信息属于研发设置，不在客服页面开放，避免误改审核规则。

## 八份报告怎么看

本版本提供每个场景 2 份报告，共 8 份。它们用于检查报告是否说清楚、证据是否能回看、API 和 Web 是否一致，不代表生产准确率。逐案说明见《八份审核报告质量索引》。

## 交付包怎么区分

- 甲方运行包：客服、产品和 IT 联调使用，不包含源码和敏感原始材料。
- 验收证据包：授权验收人员查看 8 份 HTML 和图片证据。
- 内部研发包：供 Java/Python/前端研发使用，不应转发给普通客服人员。

订单、仓库、历史客诉和客服会话系统目前仍需甲方按技术对接说明联调；本版本不会把本地演示数据说成已接入生产系统。
