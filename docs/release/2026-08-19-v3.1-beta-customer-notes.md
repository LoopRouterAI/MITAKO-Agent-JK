# MITAKO Agent v3.1 Beta 甲方更新说明

发布日期：2026-08-19

## 这次解决了什么

v3.1 Beta 将 2026 年 8 月 18 日人工客服反馈拆成两类：

- **当前代码可以解决的问题**：已进入本地确定性回归，并修正客服回复、意图、材料状态、人工队列和失败回执的错误口径。
- **必须等甲方联调的问题**：订单、仓库、改址、隐私、退款、CRM、企微和飞书等真实接口尚未提供。这些属于外部依赖，不作为当前代码障碍；接口接通后仍需专项验收。

本轮还修复了一个复核时发现的真实回归：转人工失败时，公开简报不能继续显示“已进入人工队列”。现在失败、排队和等待回执使用不同状态。

在甲方新增截图复测中又发现一条未被原 15×3 样本覆盖的订单卡片问题：用户使用“订单号 + 页面状态 + 查询进度/下一步”表达时，旧规则可能把请求判成闲聊，导致订单进度没有进入业务流程。当前工作树已补上复合订单进度识别、空业务接口的可追溯降级、模型回复安全润色和空分析包装处理；线上环境需重新部署后再复测。

逐项问题见：[v3.1 客服沟通问题与修复说明](../../甲方沟通交付文档/0819客服Agent用户沟通问题闭环验收报告.html)。

## 甲方可以看到的功能

- 用户端：上传材料、查看处理状态、停止生成、重试失败操作、进入人工队列。
- 客服坐席台：查看用户公开状态、队列回执、简报和下一步。
- JKAdmin：查看和调整业务策略、模型档位、媒体预处理策略；修改必须填写理由并留存历史，底层 Prompt、Schema 和密钥不开放给普通客服。
- 视觉审核工作台：四场景材料盘点、图片/视频预处理、异步审核、证据跳秒和双层 HTML 报告。
- 正式 API：任务创建、状态查询、批次查询、JSON 结果、签名 HTML 和签名媒体。

## 甲方建议怎么测

先用本地 Demo 验证“没有回执不说完成”，再验证意图、材料齐全性、失败重试、转人工成功/失败、四场景报告和移动端显示。真实订单、包裹、仓库、改址、隐私、退款和 CRM 业务动作，必须在甲方提供接口、凭证、回调和测试数据后再测。

完整测试顺序见：[API 与 Web Demo 功能测试说明](../../甲方沟通交付文档/0819v3.1_API与WebDemo功能与测试说明.html)。

## 版本边界

v3.1 Beta 是可验收的 POC/联调版本，不把 Mock 或本地回归描述为甲方生产接口已经接通。线上环境需要部署本版本后重新检查版本接口和客服场景。
