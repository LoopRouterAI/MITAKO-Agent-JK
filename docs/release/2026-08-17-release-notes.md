# MITAKO Agent 2026-08-17 发布说明

## 发布定位

这是四场景审核 POC 的发布候选版本，面向甲方客服主管、产品和 Java 后端研发联调。版本输出的是可追溯的客服审核建议，不直接执行退款、补发、换货、赔偿或拒绝。

## 本版解决的问题

- 四个场景分别维护业务规则、结构化字段、材料齐全性、确定性决策和报告详情，移除旧的通用正负槽位验收与场景混用。
- 模型只提取可见事实、置信度、理由和证据时间点；订单/包裹对账、仓库核验、年龄计算、材料结论、人工路由和公开脱敏由程序处理。
- 图片逐张转 WebP，不拼图；超过 4K 才评估缩放到约 2K，无损优先，必要时使用质量 90。
- 视频按体积、分辨率、帧率和码率评估全时长送审版；原片不覆盖，送审版持久化并保存双哈希、编码、分辨率、帧率、码率和失败原因。原生文件可直接送审时不强制转码，超长素材可保留完整时序分 Part。
- 全片 1 FPS 图片回退默认关闭；只有策略明确开启且有审计理由时才允许进入受控回退，原生或代理失败默认进入系统重试。
- API、Web 工作台和 HTML 报告共用同一公开数据；首屏只显示整体建议、确定性、材料状态和下一步，详情再展开场景证据与原片跳秒。
- 修复租户隔离、任务租约 fencing、失败用量累计、持久幂等、公开文本脱敏和客户包运行时模块校验。

## JKAdmin 治理

- 四场景业务规则继续从“业务规则”页维护，支持版本、发布、历史和回档。
- “审核策略”页新增审核强度、采样/帧数预算、开箱角色预检、媒体压缩阈值、编码偏好和高成本回退开关。
- 发布和回档必须填写不少于 6 个汉字的原因；记录租户、账号、角色、时间、源版本、目标版本和变更内容。
- 模型管理页只提供成本可控档和高质量候选档的启停、默认切换和连通性测试；前台不显示渠道、访问凭据、底层指令或内部字段契约。

## 交付证据

- 0816 四场景各 2 案，共 8 份正式 JSON/HTML；每份报告都保留同一工单的 API、Web 和 HTML 关联。
- `甲方沟通交付文档/0817四场景八份审核报告质量索引.html` 提供 8 份脱敏 HTML 的入口和逐案质量评价。
- `甲方沟通交付文档/0817四场景审核业务理解与发布验收说明.html` 说明四场景规则、材料盘点、媒体处理、报告阅读和可配置边界。
- `甲方沟通交付文档/0817甲方技术对接与私有化部署说明.html` 说明 Java 对接字段、订单/物流/仓库/历史客诉接口、媒体服务和私有化验收。

## 验证口径

发布前必须重新运行文档、全仓测试、前端构建、API/Web/移动端验收和 ZIP 内容/哈希门禁。8 案用于证明工程链和报告可读性，不外推生产准确率或固定人效收益。甲方真实订单、仓库、CRM、历史客诉、客服会话和最终业务动作接口仍需联调，不以本地模拟响应替代。

## 报告图片与隐私边界

本轮新增 `甲方沟通交付文档/四场景审核报告/media/manifest.json` 和 113 个 WebP 静态证据资产。它们把八份 HTML 中原本依赖过期签名 URL 的图片改为可离线预览的相对路径，便于逐案核对图片、字段和结论；视频仍通过正式 API 的签名 URL 按秒跳转。

静态包包含用户上传的身份证、支付和其他材料，默认只进入内部研发包与本地验收目录，不进入甲方客户 ZIP 或 Git 仓库公开区。客户环境查看图片应使用授权 API；这不是遗漏，而是对个人信息和原始审核材料的发布隔离。

## 回滚

代码回滚使用 Git 提交；审核规则和媒体策略使用 JKAdmin 的追加式版本回档，不覆盖历史版本。ZIP 的 SHA-256、构建提交和验证时间写入发布回执，便于按版本复核。
