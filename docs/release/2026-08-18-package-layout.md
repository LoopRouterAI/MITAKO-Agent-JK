# 2026-08-18 交付包拆分说明

状态：当前有效
更新时间：2026-08-18 00:00:00 +08:00

## 当前有效

从 `2026-08-18` 起，发布物拆成三类，避免把运行代码、研发资料和敏感验收图片塞进同一个 ZIP：

| 包 | 面向对象 | 内容 | 明确不包含 |
|---|---|---|---|
| `MITAKO_Agent-internal-dev-YYYYMMDD.zip` | 我方 Java/Python/前端研发 | 源码、Prompt/Schema、必要技术文档、测试、配置和小型演示素材 | 大体量黄金样本视频、离线敏感图片 |
| `MITAKO_Agent-four-scenario-evidence-YYYYMMDD.zip` | 我方验收、甲方复核授权人员 | 8 份 HTML、质量索引、验收说明、119 个 WebP 和 SHA256 manifest | 运行代码、密钥、数据库 |
| `MITAKO_Agent-customer-preview-YYYYMMDD.zip` | 甲方客服、产品、IT/Java | 可运行演示、公开 API、客服工作台、脱敏说明和小型演示视频 | 源码、内部 Prompt、人工标签、原始身份/支付图片 |

## 为什么拆分

上一版内部包采用“复制全部 Git 跟踪文件”的方式，导致样本视频、PDF/DOCX、历史报告和 8 份报告的离线 WebP 混在一起，体积超过 300MB。代码本身不是主要占用来源。

拆分后：

- 研发人员下载代码包即可开始 Java 联调，不必下载 119 个验收图片资产；
- 需要逐案复核时单独下载证据包，图片和 HTML 仍然同包、可离线查看；
- 甲方包继续遵循隐私边界，静态敏感材料只能通过授权签名 API 访问；
- 每个包都有自己的 SHA256、提交号、内容边界和发布说明，可单独回滚。

## 验收与回滚

发布回执必须同时记录三类 ZIP 的文件大小、SHA256、Git 提交号、manifest 和验证时间。回滚时按 Release 版本整体回滚，不把证据包中的图片复制回运行包，也不覆盖历史人工验收记录。

## 仍未接入的外部系统

订单、仓库、CRM、历史客诉和客服会话接口仍按技术对接说明提供契约/Mock，不把 POC 的本地数据描述为甲方生产已接通。
