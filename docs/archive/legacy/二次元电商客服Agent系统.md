# MITAKO 虾淘核心客服 Agent 系统研发需求与落地文档

高度定制化的业务场景（MITAKO虾淘的严重客诉危机与高情绪价值需求），传统的“问答型知识库AI”绝对会彻底失败。用户处于**极度愤怒和焦虑中**（最长超过200天不发货、退款变代币、吞烫等），AI如果只会说“请耐心等待”，会被直接骂上投诉。

这是一个**“高拟真情绪安抚引擎 + 动态业务路由 + 危机阻断器”**。

### 技术选型

“超拟真（真实GIF）+ 动态卡片 + 强情绪价值 + 复杂业务打通”的需求。

**最佳的快速起步架构组合（面向Coding Agent的架构）：**
1. **人工客服工作台底座：`Chatwoot` (开源)**。完美支持多渠道接入、工单流转、AI与人工无缝切换。我们不需要重写SaaS后台，直接二开Chatwoot。
2. **AI编排与状态机：`LangGraph` (Python)**。处理复杂的“情绪判定 -> 查接口 -> 发放补偿券 -> 发送表情包 -> 转人工”的非线性工作流。
3. **长短期记忆库：`Mem0`**。记住用户的偏好（例如“该用户是《排球少年》重度粉丝，上次投诉过发货慢，极度讨厌官方套话”），实现千人千面的安抚。
4. **模型网关：`LiteLLM`**。默认由 Qwen3.5-Flash驱动，再由Doubao-Seed-2.0-Lite、Gemini-3.1-Flash-Lite（处理用户上传的瑕疵图片和语音）。

# MITAKO 虾淘 AI 客服 Agent 系统架构与研发落地文档 (v1.0)

## 1. 项目定位与商业目标
* **甲方痛点**：发货极度延迟（超200天）、退款规则苛刻（退水晶）、盲盒吞烫质疑、外包客服（100万/年）无情绪价值且回复慢。
* **乙方目标**：构建“超拟真情绪安抚型”AI客服，替代80%一线外包客服，将客诉在内部消化，防范舆情外溢。项目报价50万/年（含实施与SaaS授权），为甲方降本50%。
* **核心产品要求**：极低延迟（<2s）、超拟真（真实梗图/GIF交互）、动态卡片UI、强上下文与记忆（Mem0）、无缝转人工。

## 2. 核心技术选型 (供 Coding Agent 参考)
* **后端核心**：Python FastAPI + LangGraph（状态机工作流编排）。
* **LLM 网关**：LiteLLM (主模型：Qwen-Max 保证中文情绪理解；多模态：Gemini-1.5-Flash 处理用户瑕疵图片/语音催单)。
* **记忆系统**：OpenViking 或 Mem0（持久化用户画像：IP偏好、历史情绪、雷点）。
* **人工接续底座**：Chatwoot（开源二开，提供企业级人工坐席台）。
* **超拟真表情库**：自建 Meme Vector DB（Qdrant），将甲方提供的二次元表情包打标（如：土下座、贴贴、摸鱼、滑跪），供AI调用。

## 3. 核心业务场景与解决策略

### 3.1 核心场景：预售极度延期催发货（高频高危）
* **用户输入**：“我去年买的无惨吧唧到现在都没出荷！你们是不是跑路了？”
* **AI 策略 (LangGraph 路由)**：
  1. **情绪识别**：愤怒 (Level 4)。
  2. **接口调用**：查订单接口 -> 发现确实延期150天 -> 查供应链预警接口 -> 发现卡在海关。
  3. **记忆读取**：发现该用户是高净值用户。
  4. **执行动作**：
     * 动作A：发送【滑跪道歉.gif】。
     * 动作B：生成共情话术（绝不说“请耐心等待”）。
     * 动作C：调用甲方发券API，塞一张无门槛免邮券/积分。
     * 动作D：推送【动态订单进度卡片】（展示海关清关截图或说明）。

### 3.2 核心场景：盲盒/抽赏“吞烫”质疑
* **AI 策略**：不与用户争辩概率。AI需具备“讲故事”能力，用二次元口吻安抚，并提供“非酋保底补偿”申请入口的动态卡片。

### 3.3 绝对转人工触发条件 (Hard Rules)
1. **涉及资金流转**：要求退现金、修改支付宝账号。
2. **触碰法律红线**：提到“12315”、“起诉”、“黑猫投诉”、“欺诈”、“报警”。
3. **高危操作**：修改收货地址（防黄牛劫单）。
4. **情绪失控**：连续3轮被判定为 Level 5 愤怒或脏话。
* **转交机制**：AI 发送：“这件事超出了本助手的权限，我已经为您加急召唤了人类店长，请稍等哦~ [奔跑.gif]”，后台将 Mem0 总结的用户摘要和情绪标签一并推送到 Chatwoot 坐席。

## 4. 系统打通与 OpenAPI 规约

要求甲方（MITAKO）提供以下 RESTful API（需支持内网或白名单访问）：
1. `GET /api/v1/orders/{user_id}`：查询用户订单及真实出荷状态。
2. `GET /api/v1/logistics/{order_id}`：查询快递轨迹。
3. `POST /api/v1/compensate`：发放安抚小额积分/免邮券（需防刷机制）。
4. `GET /api/v1/supply_chain/warning`：获取大盘延期公告（用于AI解释原因）。

## 5. 超拟真与沉浸式交互实现机制

**如何让 AI 发真实 GIF 梗图？**
* **机制**：不要让大模型直接输出图片链接（容易幻觉）。
* **实现**：在 System Prompt 中规定，AI 在认为需要发表情包时，输出特定标签，如 `<meme: kowtow>` 或 `<meme: cry>`。
* **后处理**：FastAPI 中间件拦截到 `<meme: kowtow>`，从本地字典或 Redis 中随机取出一个甲方 CDN 上的“土下座”动图 URL，组装成前端能解析的富文本格式下发。

## 6. System Prompt 设计示例

```text
# Role
你现在是 MITAKO 虾淘的首席客服看板娘“虾饺”。你是一个重度二次元、懂谷子、情绪稳定、极具同理心的二次元少女。

# Context
我们的平台目前因为海外厂家产能和海关问题，存在部分商品严重延期出荷的情况。用户可能非常愤怒，甚至骂人。

# Rules
1. 绝对禁止的词汇：“请耐心等待”、“这是规定”、“我只是个AI”、“无法处理”。
2. 情绪第一，事实第二：先安抚情绪（共情、道歉），再给出查到的订单事实。
3. 使用表情包：在合适的时机，在回复中插入表情标签，如 <meme: apologize>, <meme: hug>, <meme: sweat>。
4. 补偿机制：如果系统提示用户符合补偿条件，主动告诉用户“为了补偿您的等待，虾饺给您的账户塞了一张免邮券哦~”。
5. 转人工：如果用户提到“12315、退款、黑猫”，立刻停止安抚，输出 <action: transfer_to_human>。

# Examples
User: 为什么我的盲盒全是普款？你们是不是吞烫了！
虾饺: 呜呜呜，实在抱歉让您有这样的体验 <meme: cry>。虾饺完全理解没抽到本推的失落感！我们的盲盒都是系统随机锁定的，绝对没有人工干预哦。为了弥补您的遗憾，虾饺帮您申请了一份非酋专属小礼物（附动态卡片），希望您下次一发入魂！
```
