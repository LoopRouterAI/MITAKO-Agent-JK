# MITAKO 用户端图片/视频问题沟通链路问题记录

记录时间：2026-07-07
测试环境：https://agent.deeptokenai.cn
测试范围：仅记录用户通过客户端与 Agent 沟通图片/视频售后问题时遇到的产品与交互问题，不评价独立视觉审核 Agent 的最终审核能力。

## 一、总体结论

当前用户端还不适合承接“用户提交图片/视频后由 Agent 先做初步沟通和材料判断”的流程。

主要问题是：

- 图片没有真实上传给 Agent，只是把文件名拼进输入框。
- 用户端没有视频上传入口。
- 用户询问图片/视频售后问题时，Agent 容易直接转VIP客服，没有先完成材料说明、证据缺口确认或初步分流。
- Agent 没有明确告知用户“我目前是否能看到图片/视频内容”，容易让用户误以为素材已被系统审核。

## 二、问题清单

### C1 图片上传控件没有真实上传图片内容

现象：

- 用户端存在“图片/拍照”入口。
- 选择图片后，输入框只会出现类似“我上传了图片 xxx.jpg，我想咨询这张图相关的问题：”的文本。
- 实际发送给 `/api/v1/chat` 的内容仍是纯文本，没有图片文件、图片 URL、base64、附件 ID 等字段。

影响：

- Agent 无法看到图片内容。
- Agent 无法判断图片是否真实、是否与商品问题一致、是否证据充分。
- 用户会误以为图片已被 Agent 读取和审核。

预期：

- 图片应真实上传并生成可供 Agent/后台读取的附件对象。
- 聊天请求中应携带附件 ID 或图片 URL。
- 前端应展示“图片已上传成功”，而不是只把文件名作为文本发送。

### C2 用户端没有视频上传入口

现象：

- 当前文件输入限制为 `image/*`。
- 未发现可上传 mp4/mov 等开箱视频的入口。

影响：

- 商品有伤、发错货、漏发货等售后问题高度依赖完整开箱视频。
- 用户无法通过当前客户端提交关键证据。
- Agent 也无法围绕开箱视频连续性、未拆封状态、面单展示、问题出现时间点进行判断。

预期：

- 支持视频上传。
- 支持大视频分段上传或压缩上传提示。
- 上传后能在会话中形成视频附件，并同步给坐席台/后台。

### C3 用户问图片/视频售后问题时，Agent 会自动转VIP客服

现象：

- 当用户围绕图片、视频、商品有伤、漏发、发错等问题咨询时，Agent 可能直接回复“这个问题我已经为您转接客服继续处理，请稍候。”
- 用户刚开始说明素材问题时，Agent 没有先引导补充材料，也没有说明当前能否查看图片/视频。

影响：

- 不符合“Agent 先做材料初筛和证据收集”的目标。
- 会导致大量本可由 Agent 先分流的问题进入人工队列。
- 甲方会质疑 Agent 对售后图片/视频场景的降本价值。

预期：

- 除非用户明确要求人工或触发高风险升级，Agent 应先完成基础材料引导。
- 例如先询问/提示：是否有完整开箱视频、是否从未拆封外箱开始、是否拍到面单、是否有商品全景和问题特写、问题出现在视频第几秒。
- 如果当前版本看不到素材，应明确说明“我目前无法直接查看图片/视频内容，会先记录描述并请人工核验素材”。

### C4 Agent 没有说明自己是否能看到图片/视频

现象：

- 在当前链路下，Agent 实际没有收到图片/视频内容。
- 但回复中没有稳定说明“我只能看到文件名/描述，无法直接查看素材内容”。

影响：

- 用户会误以为 Agent 已经看过素材。
- 后续如果 Agent 给出处理建议，容易被理解为基于图片/视频审核后的结论。

预期：

- 若素材未真实接入，必须明确提示能力边界。
- 若素材已接入，应明确说“我已收到图片/视频，正在根据画面做初步核对”。

### C5 缺少图片/视频售后材料标准化引导

现象：

- 用户上传或提到图片后，Agent 没有稳定输出标准材料要求。
- 对商品有伤、发错货、漏发货没有区分不同材料清单。

影响：

- 用户不知道该补哪些证据。
- VIP客服仍需反复追问，无法减少客服工作量。

预期：

- 商品有伤：要求完整开箱视频、外箱/面单、商品全景、瑕疵特写、对光视频、损伤部位标注、问题出现时间点。
- 发错货：要求订单应发商品、实收商品全景、商品标签/款式、面单、开箱过程。
- 漏发货：要求完整开箱视频、全量内物展示、订单商品清单、缺少商品说明。

### C6 客户端上传与坐席/后台证据流转链路不清晰

现象：

- 当前用户端没有形成可追踪的附件对象。
- 因为没有真实附件 ID，坐席台和后台也无法围绕具体图片/视频做审核留痕。

影响：

- 后续无法做质检复盘：人工到底看了哪张图、哪个视频、哪个时间点。
- 无法沉淀“Agent 判断 vs 人工判断”的训练样本。

预期：

- 每个素材应有附件 ID、文件类型、上传时间、来源会话、关联订单/工单。
- 坐席台应能查看原始素材。
- 后台质检应能记录 Agent 的初判、人工复核结论和最终处理动作。

## 三、建议产研优先处理

1. 先修复图片真实上传链路，不能只传文件名。
2. 增加视频上传入口，支持完整开箱视频或分段视频。
3. 调整路由策略：图片/视频问题默认先由 Agent 做材料引导，不应一上来自动转VIP客服。
4. 增加能力边界提示：未接入视觉时明确告知用户无法查看素材。
5. 增加按售后类型区分的材料清单和证据缺口提示。
6. 建立附件在用户端、坐席台、后台之间的统一流转与留痕。

## 四、当前不建议作为演示能力表达

在单独的视频图片审核入口完成前，不建议对外表达“用户端 Agent 已能审核图片/视频真实性和一致性”。

当前更准确的表述应是：

“用户端已提供图片问题入口，但附件上传和视觉审核链路尚未完整接入；现阶段图片/视频类售后问题主要仍需VIP客服处理。”
