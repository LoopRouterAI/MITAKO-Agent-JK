## 验收边界

本轮验证的是客服沟通业务状态机，不把语言模型文案波动混入业务判断。API 级验收使用 `deterministic_reply_plan_renderer`：模型只负责把程序生成的 ReplyPlan 原样表达，意图、事实、动作、回执、下一步均来自确定性代码。

真实甲方订单、仓库、地址修改和隐私接口仍未接入。读取类测试使用本地受控数据；写操作未接通时必须返回失败或待执行，禁止显示“已修改、已删除、已退款”。本轮没有调用真实外部模型或甲方接口，不将 Mock 结果描述为生产联调完成。

## API、Web、Pad、手机和坐席一致性

- SSE 的 `done`、`transfer`、`card` 使用同一个公开 `conversation_state`。
- 用户端与坐席端同一新会话均显示：`排队中`、相同下一步、相同回执号。
- 队列状态变化后，用户端通过状态查询更新公开动作状态，不再停留在旧简报。
- 1024×768 Pad 与 390×844 手机视口无横向溢出，状态卡可见。
- 普通“尚未上传材料”场景显示 `未提交 / 上传本轮待审核材料`，不会再弹高危 VIP 提示，也不会显示默认订单或“已生成售后处理单”。
- 公开状态不包含模型、渠道、Prompt、内部工具名、原始证件号或附件内部引用。
