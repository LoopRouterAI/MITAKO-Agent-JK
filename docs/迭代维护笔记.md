## 2026-07-07 15:42:58｜视觉审核工作台失败兜底与图片-only 链路修复

本轮来源：甲方 0707 三份反馈集中指出 `/visual` 专门审核后台在真实视频/图片工单中全部 `ok:false`、`successful_reviews=0`，但页面和报告统一展示“证据不足，需要人工复核”。这不是模型保守，而是系统失败被包装成了业务判断，会严重误导客服和甲方验收。

关键结论：

- 报告口径必须区分 `review_failed` 与 `insufficient_evidence`。模型未完成、限流、网关失败、Key 未配置、结构化字段缺失，都只能叫“审核未完成”，不能叫“证据不足”。
- 商品有伤真实售后可能只有图片，没有开箱视频。工作台文件夹模式不能硬要求视频；应允许图片-only 进入审核，并在报告里提示缺少开箱视频带来的证据风险。
- 本地内置 `sample_003` 走真实 Gemini 链路成功，说明抽帧、图片压缩、报告渲染不是全坏；甲方真实 17 例全失败更可能来自部署环境、渠道/限流、特定素材包或结构化返回问题，所以失败诊断必须在报告中可见。

本轮修复：

- `load_case_bundle` 支持无视频但有图片的工单证据包。
- `/api/review-folder` 前后端都允许视频或图片至少存在其一。
- 模型调用失败、429/5xx 重试后失败、缺 Key、结构化字段缺失时，返回 `diagnostics`，并在 HTML 报告首屏展示失败阶段、失败原因、客服动作。
- 前端右侧日志优先展示失败诊断，不再把 `ok:false` 的报告简化成“检查素材或改为本地上传”。
- Gemini 请求在只有官方 `GEMINI_API_KEY` 时不再误打 API Yi 地址；软错误重试会尊重 `Retry-After`。
- `scripts/check_visual_workbench_smoke.py` 新增两个防回退断言：图片-only 商品有伤可提交；模拟 429 时必须显示“审核未完成”，且不能出现“证据不足”。

已执行验证：

- `venv/Scripts/python.exe -m py_compile poc/visual_review_poc/local_video_triage_demo.py poc/visual_review_poc/model_selection_e2e.py poc/visual_review_poc/workbench_server.py poc/visual_review_poc/report_renderer.py scripts/check_visual_workbench_smoke.py`
