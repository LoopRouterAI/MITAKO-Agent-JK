# Mock 业务闭环改造计划

**日期**: 2026-06-29

**目标**: 不接入甲方真实系统，用本地 Mock 契约把甲方客服 Agent + 私域运营 Agent 的核心业务跑通，形成可演示、可测试、可审计的改造版本。

## 0. 2026-06-29 本轮 P1 核心落地状态

本轮目标收敛为“P1 核心 Mock 客服业务闭环”，不是生产接口上线版。已落地范围：

- `agent.py`：P0 转VIP客服命中后直接短路到 handoff，不再继续查单、补偿或调用 LLM；安全审核通过后才向用户发送 LLM 文本；`block` 不再回到生成节点循环；LLM 不可用时自动转VIP客服。
- `agent.py`：SOP 召回开始读取 `docs/_extracted_sop/*.txt` 的本地文件来源，保留现有硬编码摘要作为兜底。
- `main.py` / `handoff_service.py` / `src/hooks/useChatSSE.js`：handoff 用户侧 REST 轮询和发消息带 `handoff_token`，并校验会话、用户、租户绑定；desk 写接口从登录 token 派生坐席身份，禁止请求体冒充主管或其他坐席。
- `mock_api.py`：补齐最小 Mock 契约端点：工单、售后卡片、仓库任务、财务退款状态、商品库、多模态 fixture。
- `business_mock_service.py`：新增最小 SOP 状态机，覆盖申请退款、物流异常、商品有伤、漏发/发错、未成年人退款、账号换绑，并输出允许动作、禁止动作、人工确认边界。
- `handoff_store.py` / `main.py`：普通 AI 对话写入服务端 transcript，转VIP客服简报优先使用服务端消息；新增 `business_audit_events`，用 `order_id + event_type + idempotency_key` 做 Mock 写动作幂等审计。
- `agent.py`：在现有 LangGraph 中接入 `mock_business` 节点，多模态 fixture 可进入 SOP 分支和业务审计；高风险分支只生成 Mock 卡片/任务/人工建议。
- `src/admin/pages/AuditLog.jsx`：admin 审计聚合 handoff 事件与 Mock 业务事件，session 回放可查看业务审计 JSON。
- `tests/e2e/run_mock_business_guard_e2e.py`：守护验证覆盖 P0 短路、SOP 本地召回、handoff token、用户串会话、坐席冒充、SOP 分支矩阵、fixture、服务端 transcript、幂等审计。

仍未完成的范围保持在后续：每份 SOP 逐段结构化、坐席台 checklist、质检/SOP 更新闭环、真实多模态识别准确率、企微/飞书完整私域闭环、仓库 Agent 完整任务中心、真实甲方接口替换。

## 1. 合理改造目标

本期目标不是生产对接，也不是承诺真实视频/证件识别准确率。合理目标是：

> 在现有 V1 平台底座上，做出“虾淘客服业务 Mock 演示版”：用户提出售后诉求后，系统能按 SOP 判断工单类型，查询 Mock 订单/物流/售后/仓库/财务状态，给出对应卡片动作或人工审批建议；私域和仓库能力以 Mock 消息、Mock 商品库、Mock 任务流演示。

验收边界：

- 只用 Mock 数据和本地 fixture。
- 不调用甲方真实后台。
- 不调用真实企微、飞书、仓库、财务接口。
- 多模态/OCR 可以先模拟模型结构化输出，证明流程，不证明真实识别率。
- 高风险动作只在 Mock 后台生成审批、卡片或任务，不做真实退款、补发、换货。

## 2. 当前不满足甲方需求的设计与覆盖

| 缺口 | 当前状态 | 为什么不满足 |
|---|---|---|
| SOP 执行 | `search_knowledge_base()` 是硬编码摘要 | 不能覆盖退款、物流、有伤、漏发、发错、未成年人退款等真实分支 |
| 工单状态机 | 没有按工单类型建状态机 | 无法表达改类型、挂起、提交答疑、发卡片、审核通过等动作 |
| Mock 业务接口 | 现有 Mock 主要是订单、物流、补偿 | 缺少工单、售后卡片、仓库、财务、商品库、企微、飞书 |
| 服务端会话历史 | 依赖客户端 history | 多轮简报可缺失、重复或被篡改 |
| 安全审查顺序 | 流式回复先展示，后审查 | 高风险话术可能已被用户看到 |
| 转VIP客服副作用 | P0 命中后仍继续查单、补偿、LLM | 高风险场景可能产生错误动作 |
| desk 身份绑定 | 写接口信任请求体 agent_id | 可冒充主管或跨租户接单 |
| handoff token | REST 用户消息/状态未校验 token | 可猜 session 读取或注入消息 |
| 多端并发 | 无订单级锁/幂等 | 不能证明重复退款、补发、换货被拦截 |
| 多模态审核 | 无视频/图片/OCR 流程 | 会议核心问题无法演示 |
| 质检/SOP 更新 | 无完整质检与版本回滚 | 不能覆盖“规则不合理时质疑并推动 SOP 更新” |
| 私域运营 | 无企微 Mock、标签、商品推荐闭环 | 不能覆盖留存和转化目标 |
| 仓库 Agent | 无仓库 Mock 任务流 | 不能覆盖催货、缺货、仓库反馈收口 |
| E2E | 偏 happy path | 不能证明对抗、安全、SOP 分支和 Mock 业务动作正确 |

## 3. 改造阶段

### Phase 0: 安全和状态机前置

目标：先避免演示链路中的明显错误。

- 安全审查前置或改为非流式最终审查后下发。
- P0 转VIP客服短路，不再继续补偿、写记忆和生成业务回复。
- desk 写接口绑定 token 内坐席身份和租户。
- handoff REST 校验 handoff_token。
- 增加 LLM 失败、block、配额耗尽兜底转VIP客服。
- 建立服务端会话历史表或最小 transcript store。

验收：

- 冒充 `agent_id` 失败。
- 无 handoff token 不能读消息或发用户消息。
- P0 命中后没有补偿副作用。
- LLM 失败能自动进入人工/待办。

### Phase 1: SOP 入库与工单类型路由

目标：让 Agent 不再靠硬编码摘要回复。

- 将 `docs/_extracted_sop` 切分为 SOP 知识单元。
- 建立工单类型分类器：退款、物流、有伤、漏发、发错、未成年人退款、账号换绑、其他。
- 每个工单类型建立最小状态机。
- 回复必须带 SOP 来源和当前分支。
- 坐席台显示 SOP checklist。

验收：

- 每类至少 5 条 Mock 用例命中正确工单类型。
- 走错类型时能给出改类型建议。
- 回复不再只出现泛化“退款/物流”摘要。

### Phase 2: Mock 业务接口扩展

目标：用 Mock 补齐甲方系统能力。

新增 Mock 模块：

- Mock 工单系统：类型、状态、附件、留言、挂起、答疑、改类型。
- Mock 订单系统：订单、SKU、金额、拆单、售后状态。
- Mock 物流系统：未发出、已发出、停滞、拒签、丢件、销单。
- Mock 售后卡片：退款、补偿、补发、换货、退货退款。
- Mock 仓库系统：缺货、无品控、补货、清点、反馈。
- Mock 财务系统：退款审核、到账状态、小额退款。
- Mock 商品库：SKU 图、库存、价格、IP、活动。
- Mock 企微/飞书：群消息、标签、任务、表格登记。

验收：

- Agent 能查询 Mock 状态并选择 SOP 分支。
- 写动作只生成 Mock 审批/卡片/任务。
- 所有 Mock 调用有审计记录。

### Phase 3: P0 售后 Mock 闭环

目标：覆盖最核心客服场景。

- 申请退款。
- 快递物流异常。
- 商品有伤初步判定。
- 商品有伤有开箱视频。
- 漏发货。
- 发错货。
- 未成年人退款材料初审。
- 账号换绑。

验收：

- 每类至少 5 条端到端用例。
- 每条用例包含用户输入、Mock 后台状态、SOP 分支、动作建议、审计记录。
- 高风险动作均进入人工确认或主管审批。

### Phase 4: 多模态/OCR 流程模拟

目标：演示流程，不冒充真实识别能力。

- 使用 fixture 模拟视频审核结果。
- 使用 fixture 模拟商品损伤识别结果。
- 使用 fixture 模拟 OCR 和脱敏结果。
- 低置信度进入人工复核。

验收：

- 开箱视频合规/不合规/疑似不合规三类流程可演示。
- 商品轻伤/中伤/重伤/高反光不确定流程可演示。
- 未成年人退款材料齐全/缺失/关系链不成立流程可演示。

### Phase 5: 质检、私域、仓库 Mock 演示

目标：覆盖会议里的扩展诉求。

- 质检 Agent 检查越权承诺、手算退款、SOP 错分支。
- 质疑 Agent 输出“合理但超 SOP”的审批建议。
- Mock 企微消息生成用户标签和商品推荐。
- Mock 仓库任务生成催货、缺货、反馈闭环。

验收：

- 质检报告能指出具体回复和 SOP 依据。
- 私域每日摘要可生成。
- 仓库任务从创建到反馈到用户跟进可闭环。

## 4. 建议最终交付目标

交付名：`MITAKO 甲方业务 Mock Agent 演示版`

包含：

- 一个用户端售后对话入口。
- 一个 desk 坐席 Copilot。
- 一个 admin Mock 业务后台。
- 一套 SOP 状态机。
- 一组 Mock 业务 API。
- 一组多模态/OCR fixture。
- 一套对抗与业务 E2E。
- 一份演示用验收清单。

不包含：

- 真实甲方接口对接。
- 真实企微/飞书/仓库/财务写入。
- 真实视频识别准确率承诺。
- 真实证件自动审核结论承诺。
