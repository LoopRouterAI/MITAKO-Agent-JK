# 超拟人客服 Agent 可观测与评估闭环

## 目标口径

当前客服 Agent 的目标不是简单替代人工，而是把“一线客服会先理解用户、稳住情绪、核对事实、再推进 SOP”的能力产品化。系统必须做到四件事：客户侧稳定热情、不暴露内部实现；坐席侧可观测、可调试；研发侧可评估、可扩展；三大重点审核场景能形成辅助初筛和人工确认闭环。

真实甲方后台接口、客户接口、退款/补发/账号改绑等动作仍等待甲方提供物料和联调权限，本项目只提供本地业务就绪状态、任务中心草案、材料审核初筛和人工确认边界，不能伪装成已完成真实对接。

## 四项能力现状

| 能力 | 当前实现 | 验收方式 |
| --- | --- | --- |
| 可观测 | SSE 节点轨迹输出 `intent_classify`、`business_readiness`、`generate_reply` 等阶段；后台与人工台可读取 `business_events`、`business_cards`、`sop_state.checklist`。 | `tests/e2e/run_mock_business_guard_e2e.py::test_business_readiness_node_is_observable_and_debuggable` 验证节点队列与业务卡。 |
| 可调试 | `?dev=1` 才展示右侧观察面板；后端透传公开化的 `unified_analysis` 与 `api_log`，面板展示处理阶段、意图、情绪、记忆和节点轨迹；客户默认界面不展示调试信息。 | 前端人工回归：默认 URL 不显示面板，`?dev=1` 显示观察面板；E2E 验证 SSE 原文不含模型、Key、payload、供应商、接口地址等内部字段。 |
| 可评估 | 新增结构化场景矩阵，覆盖履约慢、退货退款、商品有伤、视频审核、未成年人资料审核；断言人格标签、SOP 分支、人工确认、不可越权动作。 | 运行 `.\\venv\\Scripts\\python.exe tests\\e2e\\run_mock_business_guard_e2e.py`。 |
| 可扩展 | SOP 分支集中在 `business_readiness_service.classify_sop_branch`；每轮输出 `review_design`、`evaluation_tags`、`checklist`，方便新增 SOP 场景后扩展测试矩阵。 | 新增 SOP 时必须补关键词、review 设计、checklist 和矩阵用例。 |

## 甲方 SOP 与重点场景覆盖

| 场景 | 当前入口 | 优化设计 | 人工边界 |
| --- | --- | --- | --- |
| 发货慢、出荷慢、清关慢、仓库慢、物流慢 | `classify_intent` 识别为物流追踪/催发货，`classify_sop_branch` 进入物流异常。 | 拆分发货、清关、入仓、仓库排单、承运商轨迹；生成仓储/履约协同任务；话术先承接等待焦虑。 | 不承诺绝对出货/到货日期，接口联通前由人工执行真实核查。 |
| 退货退款、东西不好 | 进入申请退款分支。 | 区分不喜欢、质量问题、错漏发、破损证据；优先解释材料和受理边界。 | 现金退款、退货退款必须人工审批，不自动核销。 |
| 商品有伤 | 图片/材料 fixture 或自然语言进入商品有伤分支。 | 输出材料核验、视觉初筛置信度、售后处理单草案。 | 补发、换货、退款均需人工确认。 |
| 视频审核 | 开箱视频、剪辑、离开镜头等表达进入商品有伤的视频审核设计。 | 核验开箱过程连续性、箱体是否离开镜头、关键画面是否存在剪辑断点；输出初筛置信度和疑点。 | 不能自动裁决是否造假或必须赔付，只能辅助售后复核。 |
| 未成年人资料审核 | 家长、孩子、未成年、监护人等表达进入未成年人退款分支。 | 核对监护人身份、订单归属、付款关系和隐私材料完整性。 | 默认转VIP客服/主管确认，不自动同意或拒绝退款。 |
| 漏发、发错货 | 进入漏发/发错货分支。 | 生成售后卡和仓储核查任务。 | 自动补发被阻断，需人工确认缺件/错件证据。 |
| 账号换绑 | 进入账号换绑分支。 | 创建工单，保留身份核验要求。 | 自动改绑被阻断，需人工确认账号归属。 |

## 客户侧人格与热情边界

默认人格为“小蛟 / ENFJ-A”：先接住情绪，再同步事实，再给下一步。对用户焦虑、愤怒、反复追问时，必须承认等待成本和不确定感，不使用说教、推责、戏谑或流程甩锅式表达。客户可见回复禁止出现模型、供应商、接口、外包、本地预演、后台 JSON、调试日志、真实对接状态等内部信息。

## 对抗式审查后修复

本轮按产品/需求验收、测试/评估、CTO/稳定性三个视角审查后，已补齐四个风险点：客户回复清洗器新增 `review_design`、`evaluation_tags`、`checklist`、`confidence` 等内部评估字段拦截；补偿 SOP 统一为“提交申请并由业务系统/人工确认”，不再写死权益金额；`planned_action.requires_human` 已成为转VIP客服判定源，商品有伤和视频审核也能进入人工确认闭环；SSE 开放公开化观测事件，前端节点轨迹保留时间序列而不是覆盖同名节点。

## 当前仍需上线前确认

前端 UI 的完整视觉回归、真实脏数据租户迁移备份验证、甲方真实接口联调、真实图片/视频样本集准确率评测，仍属于上线前工作。现阶段已具备 POC 级客服 Agent 闭环和三大审核辅助设计，但不能承诺无人工参与的自动裁决。
