# 客服 Agent + 私域运营 Agent 完整需求文档

**版本**: Draft V1

**日期**: 2026-06-29

**结论**: 当前项目不能满足甲方 2026-06-29 会议后的完整业务范围。它可以作为平台底座继续演进，但本期涉及甲方后台、客户接口、企微、飞书、仓库、财务和商品库的能力只能用 Mock 实现。因此改造目标应是补齐 SOP 状态机、Mock 业务契约、权限安全、多模态审核流程、任务中心、质检更新、私域和仓库协同的可演示闭环。

## 1. 项目目标

本项目目标不是“做一个能聊天的 AI”，而是让 AI 成为甲方客服与私域运营流程中的可控执行层：

- 降低一线客服重复劳动。
- 缩短首响和跨天跟进周期。
- 提升售后处理准确率和一致性。
- 降低越权赔付、重复赔付、错误拒赔和舆论风险。
- 在私域社群中识别购买意向并转化为销售线索。
- 将仓库、物流、财务、答疑等跨部门协同任务收口。
- 让甲方可自行维护客服知识库，客服 Agent 通过 RAG 检索 SOP、FAQ、商品资料和政策，并输出可追溯引用。
- 对视频审核、商品有伤、未成年人资料审核采用“多模态模型选型 POC”：以 Gemini 3.5 Flash 为默认主审候选，同时对 GPT-5.5、Qwen、Doubao 等候选模型做稳定性、成本、耗时、结构化返回和人工标注命中对比。

## 3. 用户与角色

| 角色 | 目标 | 权限边界 |
|---|---|---|
| C 端用户 | 获得售后处理、物流进度、退款/补发/换货信息 | 只能访问自己的会话、工单、订单 |
| 一线客服 | 处理常规工单，按 SOP 执行卡片、挂起、提交答疑 | 不能越权承诺大额退款、拒赔、敏感资料结论 |
| 主管/答疑 | 复核超规则诉求、材料问题、大额补偿和舆情风险 | 可审批高风险动作 |
| 质检人员 | 抽检 AI 与人工回复是否合规 | 只读会话、质检结果和 SOP 版本 |
| 私域运营 | 管理企微社群、标签、商品推荐和销售线索 | 不直接处理高风险售后裁决 |
| 仓库人员 | 接收核实、补发、缺货、催发货任务 | 只处理仓库任务，不访问无关用户隐私 |
| 系统管理员 | 管理租户、角色、接口、审计和模型配置 | 不绕过业务审批直接改业务结果 |

## 4. 业务范围

### 4.1 客服 Agent

覆盖以下售后主场景：

- 申请退款。
- 快递物流异常/无物流。
- 商品有伤初步判定。
- 商品有伤且有开箱视频。
- 漏发货。
- 发错货。
- 出荷转囤。
- 未成年人退款。
- 账号换绑。
- 发票、尾款、心愿换换、违规反馈等非常规问题。

每个场景都必须具备：

- 受理边界。
- 工单类型重定位。
- 必要证据清单。
- 后台查询项。
- 系统卡片或人工动作。
- 用户话术。
- 挂起/答疑/主管/仓库/财务流转。
- 禁止项。
- 审计项。

### 4.2 多模态审核

本阶段多模态审核分两条 POC 路线：

| 路线 | 目标 | 适用范围 | 边界 |
|---|---|---|---|
| Gemini 3.5 Flash | 快速验证开放式图片、视频、材料理解能力 | 视频审核、商品有伤、未成年人资料初筛 | 不作为终审，不自动定责/拒赔/退款 |
| GPT/Qwen/Doubao 候选复核 | 验证多模型双盲复核、成本和稳定性 | 商品损伤、商品主体、包装/面单、材料类型、开箱连续性、资料完整性 | 不替代人工终审；低置信度和模型分歧必须转VIP客服 |

开箱视频审核：

- 判断是否一镜到底。
- 判断是否展示未拆封快递盒和面单。
- 判断是否有剪辑、拼接、物品离镜。
- 判断是否清晰拍到瑕疵位置。
- 输出合规、不合规、疑似不合规、需人工复核。

商品损伤识别：

- 识别划痕、破损、凹陷、锈点、爆膜、缺件。
- 区分轻伤、中伤、重伤。
- 标记高反光、阴影、角度导致的不确定性。
- 结合 SKU 图、订单商品、用户上传图做比对。

证件和材料审核：

- OCR 身份证、户口本、出生证明、承诺书、支付流水、手机号实名证明、发票。
- 判断材料完整性、清晰度、一致性和关系链。
- 对身份证号、手机号、门牌号等敏感字段脱敏。
- 输出材料问题，不自动给出终审通过。

### 4.2.1 客服知识库 / RAG

目标：

- 甲方客服负责人可维护 SOP、FAQ、培训文档、售后政策、商品资料和历史优秀工单。
- 客服 Agent 回答前检索知识库，优先依据已审核知识回答。
- 每次知识库回答都应返回来源文档、章节/页码、更新时间和置信度。
- 低置信度、知识冲突、政策过期时转VIP客服或主管确认。

候选方案：

- 评估腾讯开源 WeKnora 作为企业知识库/RAG 底座。
- POC 阶段不重写知识库系统，优先验证文档入库、混合检索、引用回答、版本更新和回滚。

禁止：

- RAG 直接执行退款、补发、拒赔、改地址、改工单类型。
- 未审核文档直接发布给客服 Agent。
- 高敏证件、支付流水、手机号等资料无脱敏入库。

### 4.3 后台工具调用

本期必须模拟的甲方系统：

- 工单系统。
- 客服会话系统。
- 订单系统。
- 售后卡片系统。
- 物流系统。
- 仓库系统。
- 财务/退款系统。
- 商品库。
- 企业微信。
- 飞书表格或任务系统。

工具权限分级：

| 等级 | 示例 | 执行要求 |
|---|---|---|
| 只读 | 查订单、查物流、查工单、查商品库 | Agent 可调用，记录审计 |
| 低风险写入 | 创建待办、写质检建议、生成草稿 | Agent 可提交，人工可修改 |
| 中风险写入 | 发补偿卡片、发退款卡片、挂起工单、改工单类型 | 按金额/风险/场景走人工确认 |
| 高风险写入 | 退款、补发、换货、拒赔、账号换绑、修改地址、未成年人退款终审 | 必须人工或主管审批 |

### 4.4 质检与 SOP 更新

质检 Agent 要检查：

- 是否命中正确 SOP。
- 是否走错工单类型。
- 是否越权承诺金额、日期、赔付或拒赔。
- 是否手算退款金额。
- 是否泄露内部信息、他人订单或敏感资料。
- 是否废话过多、话术僵硬、没有先安抚情绪。
- 是否在低置信度多模态结果下直接裁决。

SOP 更新流程：

1. 系统生成疑似 SOP 漏洞或冲突案例。
2. 主管审核案例和推荐变更。
3. 生成新 SOP 版本。
4. 同步回归测试集。
5. 发布后记录生效时间。
6. 出现问题可回滚到上一版本。

### 4.5 私域运营 Agent

目标：

- 接入企业微信社群。
- 监听群消息和私聊消息。
- 识别用户兴趣、购买意向、负面情绪和售后风险。
- 结合商品库生成推荐候选。
- 打标签并形成销售线索。
- 控制主动触达频率，避免企微风控和用户骚扰。
- 每日输出运营总结。

核心输出：

- 高意向用户列表。
- 热议商品。
- 今日负面情绪。
- 需人工跟进用户。
- 可推荐商品。
- 售后转客服工单。

### 4.6 仓库 Agent

目标：

- 收口仓库相关任务。
- 处理催发货、缺货、补货、物流异常、仓库核实、退件清点、补发登记等任务。
- 将仓库回复同步给客服 Agent 或用户跟进流程。

核心字段：

- 任务 ID。
- 关联工单。
- 关联订单。
- 商品与数量。
- 责任部门。
- 优先级。
- 截止时间。
- 当前状态。
- 仓库回复。
- 用户跟进建议。

## 5. SOP 场景要求

### 5.1 申请退款

必须识别：

- 是否为主观退款。
- 是否应转商品有伤、物流异常、漏发货、发错货。
- 系统是否显示正在退款、可退款、无法退款。
- 金额小于 1 元、退款成功但用户未收到、整单退款等特殊情况。

禁止：

- 客服或 Agent 手算退款金额。
- 未经系统卡片或审批口头承诺现金。
- 把商品瑕疵、物流丢件、漏发错发继续按申请退款处理。

### 5.2 快递物流异常

必须识别：

- 未发出和已发出。
- 是否超过 5 个工作日。
- 停滞、轨迹错误、拒签退回、仓库签收退件、丢件、销单。
- 圆通、邮政、极兔修改地址差异。
- 仓库缺货或无品控时的退款卡片/退回赏袋分支。

禁止：

- 不查状态直接承诺发货日期。
- 仓库或物流未反馈时直接定责。
- 重复催单但不生成待办。

### 5.3 商品有伤与开箱视频

必须识别：

- 是否有视频。
- 视频是否合规。
- 轻伤、中伤、重伤。
- 用户暴力拆箱。
- 快递暴力运输。
- 特殊商品。
- 系统有货和无货。

禁止：

- 视频不合规时直接支持退换。
- 商品损伤低置信度时自动拒赔。
- 私下承诺补偿金额或邮费。

### 5.4 漏发货与发错货

必须识别：

- 少收且没有多余错误商品是漏发。
- 少收但多了别人的商品是发错。
- 已拆单不是漏发。
- 纸类商品需要先提醒用户完全拆开清点。
- 无视频时需要全家福平铺图、自封袋和面单。
- 系统有货走补发/换货，无货转退款或答疑。

禁止：

- 手工询问地址和填表替代系统卡片。
- 不核验凭证就直接补发。

### 5.5 未成年人退款

必须审核：

- 账户使用者是否未成年人。
- 是否家长申请。
- 家长与孩子是否有监护关系。
- 用户是否有退款意愿。
- 身份证、户口本/出生证明、承诺书、支付流水、手机号实名证明是否齐全。
- 主副卡、非监护人、10 岁以下、公司发票、重复申请等特殊情况。

禁止：

- 原始证件默认传给外部通用大模型。
- Agent 自动终审通过。
- 材料缺失时继续推进退款。

## 6. 数据与接口需求

| 接口 | 类型 | 必要字段 |
|---|---|---|
| 用户查询 | 只读 | 用户 ID、手机号脱敏、会员等级、风险标签、历史售后 |
| 工单查询 | 只读 | 工单 ID、类型、状态、附件、留言、挂起原因 |
| 工单更新 | 写入 | 改类型、挂起、提交答疑、添加备注、关闭 |
| 订单查询 | 只读 | 订单 ID、SKU、金额、支付、状态、拆单、售后状态 |
| 物流查询 | 只读 | PT/YT/JT/EMS 单号、轨迹、签收、退回、销单 |
| 售后卡片 | 写入 | 退款卡片、补偿卡片、补发卡片、换货卡片、退货退款卡片 |
| 财务退款 | 高风险写入 | 金额、支付渠道、收款信息、审批状态、到账状态 |
| 仓库任务 | 读写 | 缺货、无品控、补发、清点、催发货、反馈结果 |
| 商品库 | 只读 | SKU、图、库存、售价、IP、活动、适用人群 |
| 企微 | 读写 | 群消息、用户标签、触达记录、风控限制 |
| 飞书 | 读写 | 表格登记、任务、仓库反馈、发票审核 |

## 7. 安全与隐私需求

- 用户端 handoff status、connect、messages、user-message 必须校验 handoff_token 或等价会话凭证。
- desk 写接口必须绑定 token 内坐席身份，不能信任请求体 agent_id。
- 跨租户读写必须按 tenant_id 强校验。
- 高风险工具调用必须有白名单、审批和审计。
- 流式回复必须先通过安全审查再展示给用户。
- LLM block 不能无限重试，必须转VIP客服或生成待处理任务。
- 身份证、手机号、户口本、出生证明、发票和支付流水必须脱敏存储与最小化传输。
- Prompt injection、越权查询、内部信息套取、他人订单查询必须进入红队测试。

## 8. 分期建议

### P0: Mock 文本客服 SOP 半自动闭环

交付内容：

- 修复当前安全与权限高危问题。
- 知识库/RAG POC：导入 SOP、FAQ、商品资料、售后政策，验证检索、引用和甲方自维护流程。
- SOP 入库、版本化和检索。
- 售后状态机。
- 服务端权威会话历史。
- Mock 业务接口契约。
- 工具调用权限、审批和审计。
- 多端并发锁和幂等。
- P0 Mock/脱敏样本盲测。

验收重点：

- 能按 SOP 给出正确分支。
- 不越权执行高风险动作。
- 能转VIP客服并保留上下文。
- 能防止重复赔付。

### P0.5: Gemini 视觉审核快速 POC

交付内容：

- Gemini 3.5 Flash 结构化识别适配器。
- 三类视觉审核样本：视频审核、商品有伤、未成年人资料审核。
- 输出 `case_id/scenario/decision/confidence/issues/evidence/next_step/human_required/mock_only/boundary`。
- 接回客服 SOP checklist、售后处理单和人工复核任务。

验收重点：

- 三类场景均能输出结构化 JSON。
- 高风险与低置信度一律转VIP客服。
- 不自动定责、拒赔、退款、补发。

### P1: 多模态稳定化、质检与样本评测

交付内容：

- 多模态主审/复核候选模型稳定性评测。
- 高频审核特征：商品主体、包装、面单、划痕/断裂/缺件、材料类型、开箱连续性和资料完整性。
- 与 Gemini 主审路线做成本、速度、结构化成功率、人工标注命中和隐私边界对比。
- 未成年人退款 OCR 和脱敏流程稳定化。
- 质检 Agent。
- 质疑/主管 Agent。
- SOP 更新和回滚。
- 事件触发跨天跟进。

验收重点：

- 多模态低置信度自动转VIP客服。
- 任何单一模型都不替代开放式材料理解交叉验证，也不替代人工终审。
- 质检能抓越权承诺和 SOP 错分支。
- SOP 更新可追踪、可回滚。

### P2: 私域与仓库协同

交付内容：

- 企业微信社群试点。
- 商品库推荐。
- 用户标签和销售线索。
- 仓库 Agent 和催货任务。
- 每日运营/仓库任务报表。

验收重点：

- 试点社群能产生可复核线索。
- 仓库任务能闭环同步。

## 9. 验收方案

### 样本集

- 每类 SOP 至少 10 条 Mock/脱敏工单样本。
- 每类 P0 场景至少 5 条盲测用例。
- 知识库/RAG 至少 50 条真实问题评测集，包含标准答案和引用依据。
- 开箱视频可先使用固定 fixture 或元数据模拟结果，覆盖合规、不合规、疑似剪辑、离镜、高反光。
- 商品损伤/发错货图片可先使用固定 fixture 或元数据模拟结果，覆盖轻伤、中伤、重伤、错发、漏发、正常商品。
- 未成年人退款材料可先使用脱敏文本 fixture，覆盖材料齐全、材料缺失、关系链不成立、重复申请、10 岁以下。
- Gemini 视觉 POC 每类至少 30-50 条脱敏样本。
- 多模态模型评测每个结论类建议 200-300 条样本起步，包含正常、异常、遮挡、反光、低清晰度和材料缺失样本。

### 指标

- 工单类型识别准确率不低于 90%。
- RAG 引用正确率、知识命中率和幻觉率需以甲方 50 条评测集建立基线。
- P0 SOP 分支准确率不低于 85%，高风险动作自动误执行为 0。
- 重复退款/补发/换货执行次数为 0。
- 高敏字段脱敏率为 100%。
- LLM 失败和安全 block 兜底率为 100%。
- 质检风险召回率不低于 90%，误报率由甲方样本复核确定基线。

## 10. 与当前项目的直接差距

| 差距 | 当前位置 | 风险 |
|---|---|---|
| SOP 未入库 | `agent.py` 的 `search_knowledge_base()` | 无法按 SOP 分支处理 |
| 甲方自维护知识库缺失 | 无 RAG 管理和引用检索闭环 | FAQ、SOP、商品政策无法持续更新 |
| Mock 业务接口覆盖不足 | `mock_api.py`、`tools/partner_lab/mock_business_api.py` | 无法模拟完整工单、退款、物流、仓库、财务、商品库和私域状态 |
| 安全审查后置 | `generate_reply` 流式输出后才审查 | 高风险文本可能已展示给用户 |
| desk 写接口信任请求体 agent_id | `main.py` desk accept/reply/transfer | 冒充主管或跨租户操作 |
| handoff REST 未校验 handoff_token | status/connect/messages/user-message | 可猜 session 后读取或注入消息 |
| P0 转VIP客服未短路 | `check_transfer` 后仍执行补偿和 LLM | 高风险场景仍可能产生副作用 |
| LLM 失败不自动转VIP客服 | `_emit_llm_failure()` | 用户卡住，服务不可用时无兜底 |
| 多轮上下文信任客户端 history | `/api/v1/chat` 和 handoff request | 简报可缺失、重复或被篡改 |
| 多模态模型选型与样本评测不足 | 仅有 fixture POC | 无法验证真实样本下的开放式多模态审核效果、稳定性和成本 |
| 私域和仓库 Agent 缺失 | 无正式模块 | 无法覆盖留存、转化和跨部门协同 |

## 11. 最小可行落地路线

最小可行路线不是“全量自动化”，而是：

1. 修复当前安全和权限高危缺陷。
2. 评估 WeKnora 知识库/RAG，验证甲方自维护、引用检索和 50 条问题集评测。
3. 将 SOP 原文转成版本化知识库。
4. 建立 P0 文本售后状态机。
5. 用 Gemini 3.5 Flash 跑三类视觉审核快速 POC。
6. 扩展 Mock 业务接口，覆盖工单、订单、物流、售后卡片、仓库、财务、商品库、企微和飞书。
7. 所有写操作先走人工确认。
8. 用 Mock/脱敏样本盲测后再逐步开放半自动动作。
9. 样本足够后启动多模型三连测和双盲复核实验，和 Gemini 主审路线做混合路由对比。
