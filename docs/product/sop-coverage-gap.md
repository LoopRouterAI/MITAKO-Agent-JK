# 甲方 SOP 覆盖差距分析（Living Doc）

> 对照源：`docs/_extracted_sop/`（11 份虾淘售后 Word 抽取）  
> 最后审查：2026-06 · 结论：**平台能力已具备，SOP 执行层尚未对齐**

## 总览结论

| 维度 | 当前状态 | 是否满足甲方真实 SOP |
|------|----------|----------------------|
| **超拟人口吻（虾饺）** | `agent.py` 中 `XIAO_JIAO_SYSTEM_PROMPT` 规则较完整（禁怼客、短句、#高亮#、ENFJ 人设） | 部分满足 — 依赖 LLM 遵从 prompt，无话术质检 |
| **情绪价值** | L1–6 情绪、capsule UI、转人工心理画像、Companion 四性格 | 主站/Companion 有；**不等于** SOP 分支话术 |
| **SOP 分支执行** | `search_knowledge_base` 仅 **6 条硬编码摘要**，**未读取** `_extracted_sop` | **不满足** |
| **后台操作** | Mock 订单/物流 API；无虾淘「查看详情 / 退款卡片 / 挂起 / 答疑」 | **不满足** |
| **工单类型路由** | 无「申请退款 ↔ 物流异常 ↔ 商品有伤」互转逻辑 | **不满足** |
| **Companion** | 刻意 **不走** 主站 SOP；`cs_parttime` 仅共情+引导运营台 | 设计如此，不覆盖售后 SOP |
| **人工台** | `/desk` 简报含情绪/建议动作，坐席 **人工** 执行 SOP | 辅助合格，AI 不代执行 |

**一句话**：现在是「拟人客服 + 转人工平台 + Mock 业务数据」，还不是「按虾淘 SOP 逐步骤自动/半自动执行的 Agent」。

## 甲方 SOP 清单 vs 代码

| SOP 文件 | 核心要求（摘要） | 代码现状 |
|----------|------------------|----------|
| 申请退款 | 受理边界、系统三分支 A/B/C、禁止手算金额、退款卡片 | 仅 intent 含「退款」时注入 1 条 generic 规则 |
| 快递物流异常 | 未发出/已发出、5 工作日、答疑、退款卡片、改地址（圆通/邮政/极兔） | intent 含「物流」→ 延期补偿 SOP 一条；无 PT 单号查询 |
| 商品有伤（初步/开箱视频） | 拍照、判定、补偿/换货分支 | intent 含「破损」→ 1 条引导拍照 |
| 漏发货 / 发错货 | 工单转移、核实、补发/退款 | **无** |
| 出荷转囤 | 预售/囤谷状态解释 | **无**（仅有供应链 mock 预警） |
| 未成年人退款 2.0 | 合规流程 | **无** |
| 账号换绑 / 非常规 | 工单类型 | **无** |
| 售后订单操作（补偿/换货/补发） | 后台按钮与登记 | **无** API |

## 关键代码位置

- SOP 召回（应升级）：`agent.py` → `search_knowledge_base()` — 当前 **未** `open(docs/_extracted_sop/...)`
- 人设与拟人：`UNIFIED_XIAO_JIAO_SYSTEM_PROMPT`
- 情绪/转人工：`unified_analysis` JSON + `handoff_service.build_handoff_brief`
- Companion 隔离：`companion_agent.py` 明确禁止主站 SOP 口吻

## 推荐演进路线（P0→P2）

### P0 — SOP 可读（1～2 周）

1. 将 `_extracted_sop` 切块入库（SQLite/Chroma）+ intent/工单类型路由检索
2. `search_knowledge_base` 改为 RAG 召回 **对应 SOP 模块**（受理边界 + 当前分支）
3. 在 `docs/changelog` 记录每次 SOP 版本变更

### P1 — 半自动执行（需甲方 API）

1. 对接虾淘后台：订单详情、物流 PT 单、退款卡片状态（只读先行）
2. OpenUI 卡片：退款卡片 / 挂起 / 转工单类型（UI 与 SOP 按钮对齐）
3. E2E：每份 SOP 至少 1 条「边界 + 主分支」用例

### P2 — 质检与全包运维

1. 话术质检：禁止「手算退款」等 SOP 违禁句
2. 坐席 Copilot：desk 侧 SOP 步骤 checklist（来自同一份 RAG）
3. Chatwoot 全包部署文档已迁至 `integration/chatwoot-guide.md`

## 验收标准（对齐甲方）

- [ ] 用户说「快递半个月没动」→ 命中《快递物流异常》**未发出/已发出**正确分支话术（**V3**）
- [ ] 用户说「不想要了退款」→ 命中《申请退款》受理边界 + 系统状态分支（**V3**）
- [ ] AI **不** 自行承诺现金/免邮（除非 SOP+后台状态允许）
- [ ] 走错工单类型 → 提示/模拟「小铅笔改类型」（**V3**）

| V2 | 真实 IdP / Chatwoot Live |
