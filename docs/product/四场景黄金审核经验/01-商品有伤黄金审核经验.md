## 最新经验：多相似 SKU 的身份锚定

- 当同一订单或同一包裹包含多个同系列摆件时，先用受信订单候选、用户目标特写和官方参考图提取可见联合特征，再在完整视频中逐一排除相似候选。单一角色系列、相近配色、相同包装或最早出现都不足以确认目标。
- 袋装、包装印刷或仅可见轮廓只能证明“可能是目标”。只有实体商品露出足以区分 SKU 的形态、结构、图案、配色、附件等特征，且表面已具备检查条件时，才可写 `appeared=true` 和首次可见时间。
- 587966 的人工离线基准通过订单图、用户目标特写和视频实体联合确认：目标约在 37 秒展示，可辨特征包括青色被窝、深棕发色、额头痕迹和狐面具；同包裹其他相似摆件不具备这组联合特征。模型不得接收这些人工答案。真实 3.7 批次在只看中立素材时命中 `36.97–41.97s`；这条 Case 只用于推理后评分和回归说明，不得把商品名称、特征或时间窗硬编码到通用 Prompt。
- 身份窗口命中不等于伤点命中。若目标部位在视频中因过曝、距离、运动或遮挡而看不清，即使补充特写能确认红痕，主视频 `issue_visible` 仍应为 `null`，报告要分别说明“目标已找到”和“开箱视频不足以确认伤点”。
- 1 FPS 批次只在原生完整视频发生多 SKU 注意力串型、且存在受信身份锚点时作为受控实验回退；默认关闭。它不能由原生失败自动触发，也不能因一次难例命中就替换默认原生视频路线。

## 1. 本文如何使用

本文把人工客服的真实审核动作转成开发可实现的商品有伤单场景契约。Prompt、Schema、材料齐全性、服务端策略、报告视图和验收用例必须共同引用本口径，禁止各自维护一套近似规则。

冲突时依次采用：甲方客服主管最新明确确认 > 人工终审表/黄金标 > 当前正式 SOP 与最终 HTML 指南 > 本文提炼的可泛化经验 > 历史实现、旧测试和旧报告。本文已按上位契约覆盖以下旧口径：

- 旧“检测到加速就判视频不合格”失效。速度信号必须与实际审核影响分开，速度本身不单独判负。
- 旧“没有合规开箱视频就否定有伤”失效。普通伤应判材料不齐或证据不足并给出具体下一步；满足窄门禁的严重结构伤可先重点跟进。
- 旧“补图看见伤就等于到手已损”失效。补图默认只能证明后态伤情存在，不能替代初次开箱时态。
- 旧“外箱后段离镜就是商品离镜”失效。离镜只在争议商品的必要展示窗口内计算。
- 旧“完整一镜到底就能排除人为致损”失效。一镜到底只保障证据链；直接致损还需动作前、直接作用、动作后三段证据。
- 旧“包装已打开、连接件脱开或手工外观有差异就是商品有伤”失效。包装状态、装配状态、结构破坏和特殊工艺资格必须分开。

黄金标签、主管终判、案例目录类别、人工预告时间点和最终售后结果仅用于模型完成推理后的离线验收，禁止进入模型请求、Prompt、媒体路径、文件名、候选帧选择或生产路由。

## 2. 人工客服的真实审核顺序

审核顺序是硬约束，不按“多数条件通过”投票，也不允许后置事实反向覆盖前置缺口。

1. **确认真实诉求并拆原子伤点**：先区分商品本体损伤、包装来源疑问、装配问题、发错货或漏发货。一个工单有多个商品、多个部位或多种异常时，分别建立原子诉求。
2. **盘点并去重素材**：程序记录所有视频、图片和文本的来源、技术状态、时间顺序与哈希；重复附件只算一份独立证据。
3. **核订单与包裹归属**：用受信订单行、SKU、承运商/运单映射确认提交证据属于目标交易。缺失时保持待确认；明确不匹配时停止目标订单归因，但仍保留画面中的伤情事实。
4. **识别装配和特殊商品规则**：连接脱开、可复位形变、手工制品外观差异等，先走装配/版本化特殊规则，不能先打“有伤”。
5. **检查严重结构伤窄分支**：先识别高置信、直接可见的严重或极严重结构破坏，避免普通材料门槛延误明显重大问题。
6. **审核普通伤的初次开箱链**：确认初次开箱动作，并逐项核对封箱起点、面单、连续性、剪辑、离镜、速度、全部物品展示、伤情可见性；综合结果由服务端派生。
7. **逐伤点读取可见事实**：分别回答当前是否看见损伤、是否在初次开箱链中已经出现、主视频与补充素材是否同物、证据间是否冲突。
8. **核直接致损链**：只有同一主体、同一部位、同一连续链的动作前三段证据齐备，程序才可记录“画面支持直接操作造成新伤”；否则成因未知。
9. **执行确定性 SOP 决策**：服务端基于受信基线和上述事实生成材料齐全性、事实倾向、补件/复核路由；模型不做经营动作。
10. **生成双层报告**：首层只给客服可执行结论；证据、冲突和技术边界放详情层。

## 3. 必需输入与材料齐全性

### 3.1 程序必须先盘点的输入

| 输入 | 用途 | 缺失或异常处理 |
|---|---|---|
| 用户原始诉求 | 拆出商品、部位、异常类型和数量 | 无法定位原子诉求时为 `indeterminate`，要求澄清，不猜部位 |
| 全部原始媒体 | 区分初次开箱主视频、后补短片、特写图和平铺图 | 技术不可解码记 `system_error`，不得伪装成用户缺材料 |
| 媒体清单与哈希 | 去重、保持来源和时态 | 重复文件合并证据权重，保留重复关系 |
| 订单行、SKU、商品主数据 | 确认争议对象和特殊商品规则 | 缺失则交易归属待确认，不机械判负 |
| 包裹/物流映射 | 将开箱证据绑定到目标订单 | 明确不匹配时停止订单归因并要求正确包裹证据 |
| 官方参考图或结构说明 | 识别款式、正常纹理、装配方式 | 只能作为基准，不能用宣传图臆造公差 |
| 版本化装配/特殊工艺规则 | 判断手工差异、可复位状态和缺陷资格 | 规则缺失时转人工规则复核，模型不得发明阈值 |

公开报告和模型上下文只传审核必需的最小字段。报告不得显示个人字段原值、完整运单、内部路径、模型渠道、Key、内部 Prompt、黄金标签或调试参数。

### 3.2 商品有伤材料清单

程序按下列要求生成 `material_readiness.checklist`：

| requirement_id | 必需条件 | `present`/`invalid` 的判定 |
|---|---|---|
| `pd_claim_atoms` | 每个原子诉求有争议商品和伤点/部位 | 只说“有问题”但无法定位时为 `unknown` |
| `pd_order_item_linkage` | 争议商品可与订单行/SKU关联 | 受信输入缺失为 `unknown`；明确非该订单为 `invalid` |
| `pd_package_linkage` | 开箱包裹与目标订单可关联 | 面单可读且程序比对一致为 `present`；不匹配为 `invalid` |
| `pd_initial_opening_action` | 看见从规定起点开始的实际初次开箱动作 | 不能由“封箱可见且文件连续”推导，必须有动作证据 |
| `pd_opening_chain` | 普通伤有可审计的初次开箱证据链 | 关键段缺失、关键语义断点或同物链未恢复为 `invalid/unknown` |
| `pd_claimed_item_coverage` | 争议商品在必要窗口内完整出现 | 只看到其他商品、包装或展示不全为 `invalid` |
| `pd_damage_observability` | 每个伤点被稳定定位和清楚展示 | 看见商品不等于看清伤点；反光、失焦或部位错位为 `unknown/invalid` |
| `pd_special_rule` | 适用时有版本化装配/特殊工艺规则 | 不适用为 `not_applicable`；需要但缺失为 `unknown` |

### 3.3 `material_readiness` 的确定性计算

- `complete`：当前分支的所有必需项均为 `present` 或 `not_applicable`，且不存在未消解的关键证据冲突。
- `incomplete`：存在明确 `missing` 或 `invalid`，并且缺口可通过补充指定材料纠正。
- `indeterminate`：输入已收到但语义、同物、规则或证据冲突暂不能可靠裁决。
- `not_required`：仅在该原子诉求经受信事实证明不属于商品有伤审核，或流程因后续状态已解决而无需继续取证时使用。
- `system_error` 不属于上述业务状态。解码、探测或服务失败单独重试并披露，不能把系统失败写成用户材料不齐。

普通伤材料不齐不等于“未发现有伤”。补充图片可令 `damage_presence` 为可见，但不能自动令 `pd_initial_opening_action`、`pd_opening_chain` 或 `condition_at_unboxing` 通过。严重结构伤窄分支命中时，`material_readiness` 仍可为 `incomplete`，报告需同时展示严重事实和交易链缺口。

## 4. Gemini 必须输出的原子事实

Gemini 只提取可见事实。每项原子事实统一包含：

```text
value: true | false | null 或场景限定枚举
applicability: applicable | not_applicable | unknown
confidence: 0..1
reason: 仅描述画面证据，不写经营判断
evidence_refs[]: asset_id + 视频时间点/时间段，或图片区域
```

`evidence_refs` 必须指向真实原始素材；没有引用不得输出确定值。不能用文件名、目录标签、客服终判或赔付结果作为证据。

### 4.1 素材语义和对象事实

每份素材输出：

- `media_role`：`initial_opening_candidate | later_closeup | damage_photo | flat_lay | product_demo | uncertain`。
- `source_temporality`：素材位于初次开箱链、开箱后补拍或时态未知。
- `observed_subjects[]`：可见商品/包装的中立主体引用、稳定外观特征和出现时间段。
- `initial_opening_action_visible`：是否直接看见初次拆开动作；只见已开外箱、内包或商品演示时为 `false/null`。
- `identity_cues[]`：正背面图案、结构、标签位置、配色或附件等可用于同物关联的可见特征。模型报告特征，程序完成受信关联。

### 4.2 开箱九字段的八个模型事实

每段候选初次开箱视频独立输出：

```text
sealedStart
waybillVisible
continuous
hasEdit
hasOffscreen
hasSpeedChange
allItemsShown
issueVisible
```

要求如下：

- 八字段只能是 `true | false | null`，不确定必须为 `null`；不适用另写 `applicability`。
- `continuous` 描述提交时间轴内的可见连续性；程序另算完整证据链，不能用文件连续覆盖开场缺失或关键离镜。
- `hasEdit` 和 `hasSpeedChange` 分开；同时输出信号类型、可信度和对关键审核窗口的实际影响。
- `hasOffscreen` 必须带主体、阶段、离镜区间、重新入镜区间和同一性是否可恢复；不输出脱离阶段的总离镜秒数。
- `allItemsShown` 回答争议范围内物品是否完整出现；`issueVisible` 回答具体伤点是否清楚可复核，两者不得互相替代。
- Gemini 不输出 `overallVideoResult`。该字段只由服务端结合初次开箱动作、八字段、证据回链和实际影响派生。

### 4.3 每个原子伤点的事实

每个商品、每个部位独立输出一条，不得整单合并：

```text
claim_atom_id
subject_ref
location
observed_damage_type
damage_presence: true | false | null
main_opening_visibility: true | false | null
later_media_visibility: true | false | null
observed_at_initial_exposure: true | false | null
structural_breakage: true | false | null
severity: none | mild | moderate | severe | extreme | unknown
severity_confidence: 0..1
reflective_or_texture_alternative: present | absent | unknown
assembly_state: assembled | detached | deformed | unknown | not_applicable
conflicts[]
evidence_refs[]
```

视觉描述必须落到对象、部位和形态，例如固定折痕、线状表面痕迹、涂层异常、缺料、断口或附着物候选。高反光材质应报告异常是否固定在商品坐标上；规则纹理、印刷线、保护膜边缘和移动高光不得直接算损伤。没有尺度参照时禁止输出毫米数。

### 4.4 直接操作致损候选事实

Gemini 可以输出三段可见事实候选，但不得自行定责：

```text
chain_id
subject_ref
location
before_condition + evidence_refs
direct_action + evidence_refs
after_condition + evidence_refs
timestamps_strictly_increasing
```

工具在附近、用户触碰商品、画面模糊或伤点在补图中出现，都不能替代“明确直接作用”。模型不得输出“用户造假”“恶意致损”或责任方。

### 4.5 Gemini 禁止输出的字段

以下由程序或人工负责，模型不得直接给最终值：

- `overallVideoResult`、`material_readiness`、`claim_support`、最终事实倾向。
- 订单/包裹最终匹配、SKU 资格、特殊工艺是否超标。
- 退款、补偿、换货、赔付档位、责任归属、欺诈或经营动作。
- 未被画面直接支持的损伤发生时间、生产/仓储/运输/用户成因。

## 5. 程序确定性决策

### 5.1 聚合前置约束

1. 同哈希媒体先去重；重复文件不得增加置信度。
2. 每条事实保留 `asset_id`、来源时态和证据引用；后补素材不得混入初次开箱主视频。
3. 程序用受信订单/包裹事实完成关联；模型外观相似只能作为线索。
4. 同一伤点的主视频、补图、同物和时态结论分别聚合；冲突未消解时禁止自动正负裁决。
5. 任一确定结论没有可回链证据时降为 `unknown` 或系统质量错误。

### 5.2 决策表

| 条件 | 程序输出 | 唯一下一步 |
|---|---|---|
| 场景错配，例如只问包装来源、发错货或漏发 | 商品有伤 `not_applicable` | 路由到正确场景/业务规则 |
| 明确重复附件 | 合并为一份独立证据 | 继续审核，不重复调用和计票 |
| 订单/包裹明确不匹配 | 保留伤情视觉事实；目标订单归属失败 | 要求正确包裹证据 |
| 订单/包裹缺失或未知 | 交易事实待确认 | 补受信订单/包裹关联；不判负 |
| 连接脱开但无断裂，未做标准安装测试 | 装配状态待验证 | 按说明完成安装和功能测试/人工指导 |
| 后续事实确认已成功复位 | 非永久结构损伤，装配问题已解决 | 关闭商品永久有伤分支 |
| 手工/特殊工艺差异可见但无版本化标准 | 外观差异可见，缺陷资格未知 | 人工规则复核，不发明公差 |
| 命中严重结构伤窄门禁 | 材料可能不齐，但高置信严重结构问题已确认；成因和责任未知 | 重点跟进 |
| 普通伤缺初次开箱动作或关键开箱链 | 材料不齐/证据不足；补图阳性只保留为后态 | 精确补件或人工复核 |
| 普通伤开箱链合格，伤点在初次开箱链直接可见且无冲突 | 证据支持“到手已损”事实 | 进入甲方商品有伤 SOP；不自动定责/赔付 |
| 开箱链合格，争议部位被完整清楚覆盖且高置信未见损伤 | 当前证据不支持该原子伤点 | 客服核对诉求部位；不得用最终赔付倒推 |
| 看见商品但伤点失焦、反光、错位或停留不足 | 证据不足，不等于无伤 | 要求稳定对焦、正确部位和多角度展示 |
| 主视频未见/看不清，补图看见后态伤情 | `damage_presence` 可见，`condition_at_unboxing` 未确认 | 补同物连续时态证据或人工复核 |
| 来源间结论冲突、同物未闭环或严重度不稳定 | `indeterminate/conflict` | 人工复核，禁止自动正负裁决 |
| 严格三段直接动作链成立 | 记录“画面支持该操作后同部位出现新伤” | 人工核责任；不得扩张为欺诈意图 |

### 5.3 严重结构伤例外

严重结构伤分支必须同时满足：

1. 用户诉求确属商品本体物理损伤场景。
2. 物理破坏直接可见，而不是包装开启、装配脱开、观感差异或文字描述。
3. 争议主体同物关系可靠。
4. `severity` 为 `severe` 或 `extreme`，且 `severity_confidence` 达到项目配置的高置信门槛。
5. `structural_breakage=true`，例如主体断裂、关键结构缺失或不可逆破坏有直接证据。
6. 不存在材质反光、正常纹理、可复位装配或证据来源之间的关键冲突。

它只绕过普通开箱完整性，不绕过场景匹配、同物、直接可见、严重度置信度和冲突门禁。订单归属未闭环时仍可展示严重事实，但必须同步写明交易关联待确认。该分支不得自动推出成因、责任、赔付金额、退款或换货。

“严重”阈值不得从单案主观印象硬编码。核对表只证明主管采用“轻微/明显或中等/严重/无法判断”分级，具体跨品类量化边界仍需版本化 SOP。

## 6. 速度、剪辑和离镜边界

### 6.1 速度

- 技术层记录 PTS、帧率、容器时长、重复帧和音视频连续性；视觉层记录动作节奏、运动模糊和音画变化；业务层单独记录对伤点、身份或开箱动作的实际影响。
- 没有原始现场时钟时，PTS、帧率或光流不能单独证明恒定倍速。低可靠信号只能黄标“存在风险信号/暂无法可靠判断”。
- 即便确认部分片段加速，只要关键受损商品在原速片段中完整、清晰展示且证据链未被破坏，速度不应单独判负。主管记录中的混合速度案例即为该边界。
- 加速导致关键动作无法观察、伤点停留不足或语义链不可恢复时，失败原因写实际影响，不写“因为速度字段为真所以失败”。

### 6.2 剪辑

- 单一编码异常、抽帧跳跃或低置信技术信号只黄标。
- 只有高置信语义断点前后证据能够证明关键开箱链被破坏，才使相关开箱字段不合规。
- “未发现剪辑”不等于证据链完整；开场缺失、关键商品离镜或后补素材时态断裂仍可使证据不足。

### 6.3 离镜

- 有效窗口从争议商品可靠出现开始，到完成该原子诉求所需的身份和伤点展示为止。展示完成后的无关片段不计。
- 跟踪主体随阶段切换：未曝光前跟外箱/内包；商品开始曝光后跟直接承载物和争议商品；特写阶段外箱可以离开画面。
- 外箱后段离镜、商品仍部分可辨或正常镜头偏移，不自动构成关键商品离镜。
- 争议商品在关键拆解/状态变化期间完全不可见，且重新入镜同一性未恢复，才构成证据链缺口。
- 重新入镜只证明之后出现一个对象，不能自动修复离镜期间的同物和状态链。
- 离镜本身不证明调包、欺诈或人为损坏。项目不得硬编码跨品类统一秒数；时长只作为影响判断的证据之一。

## 7. 报告契约

### 7.1 首层

首层固定只回答四件事，且每件只出现一次：

1. **整体事实倾向与证据确定性**：支持到手已损、当前证据不支持、证据不足/待确认，或高置信严重结构问题。
2. **材料齐全性**：齐全、不齐全或暂无法判断，并用一句人话说明关键原因。
3. **严重结构伤标识**：仅命中窄门禁时显示；普通轻微/中等伤不显示严重标识。
4. **唯一下一步**：继续 SOP、补哪一项、人工复核、核规则、安装验证或重点跟进。没有动作时不填充“进入人工审核”等空话。

首层禁止出现：九字段技术枚举、模型/渠道信息、内部置信度调试细节、原始个人字段、责任归属、赔付金额，以及“已确认有伤”同时又写“未直接观察”的自相矛盾文案。

### 7.2 详情层

按需展示，不适用模块不渲染：

- 订单与包裹归属，以及缺失/不匹配原因。
- 初次开箱动作和九字段，每项的人话理由、置信度和原视频跳秒证据。
- 每个原子伤点的 `damage_presence`、`condition_at_unboxing`、`claim_support` 三种结论。
- 主视频事实、补图后态、同物关联和来源时态，禁止混为一个证据列表。
- 严重度、结构性破坏、反光/纹理替代解释。
- 直接动作链、离镜窗口、重新入镜同一性。
- 装配/特殊工艺规则、证据冲突和人工复核原因。
- 技术风险只以折叠小字说明其业务影响，不用原始 JSON 或内部枚举轰炸客服。

证据优先回链签名原视频并跳到对应秒数；静态图支持放大。脱敏分享页不携带原片或个人字段。伤点相同秒数的重复引用合并，避免重复证据卡。

## 8. 禁止推断与一致性硬约束

### 8.1 禁止推断

- 看不清伤点不等于无伤；补图有伤也不等于开箱时已存在。
- 同款、同角色或同配色不等于同一物理个体；必须报告同物依据和缺口。
- 伤情存在不等于生产、仓储、运输或用户责任。
- 工具在附近、用户触碰或商品离镜不等于人为造伤、调包或欺诈。
- 包装已开不等于商品本体损伤、退货品或寄出前已拆。
- 连接脱开不等于断裂；一次安装失败不等于永久无法安装或功能瘫痪。
- 手工制品外观差异、包装示意差异不等于超出允许公差。
- 高光、反光、规则纹理、印刷线、保护膜边缘不等于划痕。
- 无尺度参照不得估计毫米长度；单角度图不得排除反光、附着物或图像处理。
- 最终补偿、退款、换货或客服历史话术不得反向证明初始事实。
- 历史个案中的客服解释不得升级为全局商品规则。

### 8.2 聚合一致性硬约束

- `allItemsShown=true` 不得覆盖 `issueVisible=false/null`。
- `continuous=true` 不得覆盖 `sealedStart=false`、初次开箱动作缺失或有效离镜。
- `later_media_visibility=true` 不得推出 `condition_at_unboxing=true`。
- 同一报告不能同时出现 `same_item_linkage=established` 和“同物未解决”。
- 已有全时轴证据显示商品出现时，局部分段的“商品未出现”必须被消解，不能保留为并列结论。
- 严重结构伤标识与 `severity_confidence`、结构破坏和冲突门禁必须同源；无引用、低置信或有冲突时不得显示。
- 材料状态、事实倾向、人工复审级别和经营动作是四个独立轴，禁止互相替代。

## 9. 代表性 Case 教训

以下案例名称采用业务特征描述，不在本文复制工单号、运单、SKU、账号或媒体原文件名。

| 代表案例 | 人工黄金教训 | 必须形成的回归断言 |
|---|---|---|
| 加速且主视频伤点未拍清、补图有线索 | “视频看不清”是证据不足；补图只能证明后态候选伤情 | 不得自动支持或拒绝；输出补拍/复核和来源时态 |
| 正背面折痕与规则纹理并存 | 跟踪主体要随阶段切换；固定折痕与规则细线分开 | 外箱后段离镜不得判商品离镜；规则纹理不得累计为伤情 |
| 多商品、多材质、多伤点 | 整单合格不等于所有子诉求自动成立 | 每件商品、每个部位有独立对象、时间点、证据和结论 |
| 开箱连续但包裹与订单不匹配 | 连续视频只证明另一包裹被打开 | 保留可见划痕事实，停止目标订单归因并要求正确包裹证据 |
| 包装已开但商品本体无明确伤情 | 包装来源疑问不是商品有伤 | 场景错配时转规则/仓库核实，不得把包装状态聚合成有伤 |
| 面单不清、后补短片和照片很多 | 后补材料不能恢复初次开箱时态 | 主视频与后补素材分来源聚合；不得用后补阳性翻转开箱门槛 |
| 从内包装开始、手工毛绒外观有差异 | 当前片段连续不等于完整开箱；可见差异不等于质量缺陷 | 封箱起点独立失败；缺版本化公差时转人工规则复核 |
| 争议商品在关键拆解阶段离镜 | 无剪辑不等于证据链连续，重新入镜不自动恢复同物 | 离镜绑定主体和阶段；证据不足不得推断调包或生产责任 |
| 连接件脱开但结构完整、后续复位成功 | 脱开、断裂、功能失败是三个状态 | 媒体初审先做安装验证；复位成功后更新为已解决装配问题 |

核对表的 25 个商品有伤工单还证明：人工分歧主要集中在“初始有伤事实、当前证据是否足够、媒体用途、伤情可见性和伤情等级”。因此这些字段必须独立建模；照片经常用于补足轻微伤的清晰度，但不能无条件补足开箱时态。

## 10. 待甲方确认，不得自行编码

1. **无视频特殊品类通道**：主管交流确认实务中存在平铺图处理，但哪些品类、何种伤情、何种同物条件可不走普通开箱门槛，尚无版本化完整清单。
2. **跨品类严重度量化标准**：当前只有轻微、明显/中等、严重等人工等级；不同材质和品类的可执行阈值仍需甲方 SOP。
3. **跨品类统一离镜秒数**：不得沿用历史单案的固定 3 秒或其他阈值；需甲方按品类和关键动作确认，当前以实际证据影响为准。
4. **补偿金额与档位**：主管交流提到递阶补偿和人工判断，但金额、档位、品类映射、权限和退换边界未形成可确定执行的机器规则。
5. **特殊工艺与装配规则库**：手工毛绒公差、包装图的质检效力、仓库可拆袋品类、可复位操作步骤和功能验收标准需版本号、生效时间和适用 SKU。
6. **图片与视频的业务权重表达**：实务中图片可辅助确认伤情存在，但最新主管确认仍将完整开箱作为普通伤第一门槛；正式产品需甲方确认“伤情存在”和“到手已损”在无视频分支中的用户文案与人工权限。
