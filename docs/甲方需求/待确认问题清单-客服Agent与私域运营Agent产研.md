# 客服 Agent + 私域运营 Agent 产研待确认问题清单

> 适用对象：产研部门
> 来源：客户会议纪要整理
> 范围：客服 Agent、私域运营 Agent、仓库 Agent / 跨部门协同相关问题

---

## 二、客服 Agent 相关产研待确认问题

### 1. 开箱视频审核能力是否可实现？

客户的售后场景里，用户需要提交开箱视频。人工客服目前会逐帧查看视频，判断视频是否符合要求，例如：

- 是否完整展示商品六面
- 是否一镜到底
- 是否有剪辑点
- 商品是否中途离开镜头
- 视频是否能证明商品从开箱到展示的连续性
- 是否能基于视频判断售后责任

客户希望确认：**AI 是否可以自动审核开箱视频是否合规，并给出审核结论和理由**。

产研需要回答：

- 是否可以做“开箱视频合规性审核”？
- 需要使用通用多模态模型，还是需要额外的视频切片、关键帧抽取、规则引擎？
- 是否能判断“六面展示”“一镜到底”“是否剪辑”“是否离开镜头”？
- 能否输出结构化结果，例如：合规 / 不合规 / 疑似不合规 / 需人工复核？
- 置信度低于多少时转人工？
- 客户需要提供多少真实开箱视频样本用于测试？

---

### 2. 商品损伤识别能力是否可实现？

客户希望 AI 能从图片或视频中识别商品是否存在伤痕、划痕、破损、发错货等问题。尤其关注：

- 视频切片后能否识别商品是否有伤
- 商品是否存在划痕、瑕疵、破损
- 高反光商品在拍摄条件不好时，是否还能识别
- 能否区分“真实划痕”和“反光 / 阴影 / 拍摄角度导致的误判”

产研需要回答：

- 图片识别、视频识别分别能做到什么程度？
- 高反光商品是否需要先做图像增强、去反光、关键帧筛选？
- 是否需要客户提供商品标准图、SKU 图库、瑕疵样本库？
- AI 能否判断“发错货”？需要依赖商品库图片、订单 SKU、用户上传图三方比对吗？
- 是否建议该能力先作为“辅助质检”，不直接自动赔付或拒赔？
- 该能力适合 MVP 阶段上线，还是应作为第二阶段能力？

---

### 3. AI 是否能判断商品损伤责任？

客户不只是想识别“有没有伤”，还希望 AI 能结合视频前后逻辑，判断商品损伤更可能是谁造成的。例如：

- 商品是否可能是用户拆封时自己划伤
- 开箱视频是否能支持用户的售后主张
- 用户是否存在恶意售后或故意损坏
- 虽然视频不完整，但结合购买记录、沟通过程、外箱情况，是否仍然可以合理赔付

产研需要回答：

- AI 能否基于视频、图片、订单、历史售后、用户话术等信息做综合责任判断？
- 责任判断应采用纯大模型推理，还是“大模型 + 规则引擎 + 置信度评分”？
- 是否能输出判断依据，供人工复核？
- 对于“疑似用户造成”“证据不足”“应当赔付”“建议安抚补偿”等情况，如何分级？
- 是否需要设定高风险决策必须人工确认，比如拒赔、拉黑、重大补偿？

---

### 4. 跨工单、拆单、重复售后问题如何处理？

客户提到一个实际场景：用户可能在 A 工单里提到 B 商品或另一个订单的售后问题。人工客服目前可以通过系统查看其他订单信息后直接处理，而不是让用户重新提交。

产研需要回答：

- Agent 是否支持跨工单查询？
- 能否根据用户账号、手机号、订单号、商品 SKU 自动关联相关订单？
- 用户在当前会话里提到另一个订单时，AI 是否能自动识别并拉取对应订单信息？
- 多个工单之间如何避免重复回复、重复赔付、重复退款？
- 系统需要客户开放哪些接口：用户信息、订单列表、工单列表、售后记录、赔付记录？
- 跨工单操作是否需要权限控制和日志审计？

---

### 5. 规则冲突与“合理但超 SOP”的诉求怎么处理？

客户担心 SOP 不是绝对正确的。很多场景下，用户诉求虽然超出规则，但从购买体验、舆论风险、老客价值等角度看，可能应该特殊处理。

会议中明确提到，希望有一个更高级的 AI 或“质疑者”角色，能够对僵硬规则提出质疑，避免完全机械执行 SOP。

产研需要回答：

- 是否可以设计“客服 Agent + 质检 Agent + 质疑 Agent / 主管 Agent”的多角色机制？
- 当 SOP 结论与用户体验冲突时，AI 如何识别并上报？
- 是否能设置“超规则但合理”的判定维度，例如：
  - 用户历史消费金额
  - 用户是否老客
  - 是否存在舆论风险
  - 商品本身是否特殊
  - 客服沟通情绪是否升级
- AI 能否输出“建议特殊处理”的理由？
- 是否需要一个人工主管审批流？
- AI 是否可以沉淀这些特殊案例，反向推动 SOP 更新？

---

### 6. SOP 质检与自我更新机制如何设计？

客户提到，当前质检主要是事后复核客服是否遵守 SOP，但缺乏自我更新 SOP 的能力。客户希望 AI 不只是执行 SOP，还能发现 SOP 不合理、遗漏或容易引发舆论问题的地方。

产研需要回答：

- 是否可以做一个“质检 Agent”，自动抽检客服 Agent 的处理过程？
- 是否能判断客服回复是否符合 SOP、是否情绪安抚到位、是否存在废话过多或僵硬话术？
- 是否可以生成“疑似 SOP 漏洞”清单？
- SOP 更新是自动更新、人工审核后更新，还是只生成建议？
- SOP、规则、流程文档应该存在哪里？知识库、配置后台、版本化规则库，还是内部记忆系统？
- 是否支持 SOP 版本管理和回滚？

---

### 7. 后台系统接入方式与权限边界

客户希望 AI 接入企业的数据库、工单系统、客服系统等后台，但也关心权限控制。通常需要企业提供接口或双方共建接口，AI 不应轻易操作后台，但规划中希望具备操作能力，并根据企业权限管理设置。

产研需要回答：

- 我们的方案是嵌入客户现有系统，还是另做一个独立后台？
- 需要接入哪些系统：
  - 工单系统
  - 客服系统
  - 订单系统
  - 商品库
  - 物流系统
  - 仓库系统
  - 财务 / 退款系统
  - 企业微信
  - 飞书
- 每类系统需要读权限还是写权限？
- 哪些动作允许 AI 自动执行，哪些必须人工确认？
- 是否支持账号级权限管理？
- 是否支持操作日志、审计记录、回滚机制？
- 是否需要做工具调用沙箱或隔离层？

补充建议：

Agent 一旦具备工具调用和后台操作能力，就不能只靠提示词约束。产研方案里需要明确最小权限、敏感操作人工确认、工具调用审计、对抗测试等机制。

### 8. 多端并发接入与工单合并问题

客户担心同一用户可能从多个端同时发起咨询，例如：

- 手机端
- 小程序端
- 语音端
- 企业微信
- 其他客服入口

当前系统里有些工单可合并，有些不合并，会话基于用户账号；但是否会出现冲突，需要结合客户实际需求进一步确认。

产研需要回答：

- 同一用户多端并发发起咨询时，Agent 如何识别是同一用户？
- 多端会话是合并成一个上下文，还是分别处理？
- 如果两个端同时触发退款、补偿、改地址等操作，如何防止冲突？
- 是否需要会话锁、工单锁、订单级操作锁？
- 工单合并规则由客户现有系统决定，还是我们需要补一层会话管理？
- 语音、文字、小程序消息是否统一进入同一个 Agent 会话状态？

---

### 9. 跨天自动跟进与任务提醒机制

客户提出一个典型需求：用户今天问物流问题，但仓库或物流第二天才回复。系统需要在有结果后自动联系用户，而不是依赖人工记忆。

产研需要回答：

- 是否可以基于工单状态变化触发 AI 自动跟进？
- 是否采用“事件触发”而不是定时轮询，以降低成本？
- 仓库 / 物流回复后，AI 是否能自动生成并发送用户回复？
- 哪些场景可以自动跟进：
  - 物流更新
  - 仓库反馈
  - 缺货补货
  - 退款到账
  - 用户补充资料
  - 人工审核完成
- 是否需要任务队列、提醒中心、未完成任务看板？
- 跟进失败或用户情绪升级时如何转人工？

---

### 10. 未成年人退款审核能否由 AI 辅助处理？

客户提到未成年人退款是高频且复杂的客服场景。AI 需要审核多类证明材料，包括身份证、户口本、出生证明、监护关系、家长申请、用户退款意愿等。

会议中明确了四类判断标准：

1. 账户使用者是否未成年人
2. 是否家长申请
3. 家长与孩子是否存在监护关系
4. 用户是否有退款意愿

产研需要回答：

- AI 是否可以做证件 OCR 和材料完整性审核？
- 是否可以判断监护关系链条是否成立？
- 是否可以判断申请人与账号使用者、付款人、收货人之间的关系？
- 是否可以根据客户给定规则输出审核结论：
  - 材料齐全，建议通过
  - 材料缺失，要求补充
  - 信息矛盾，转人工
  - 疑似风险，主管复核
- 该场景涉及大量敏感信息，是否需要本地部署 OCR / 脱敏模型？
- 身份证号、手机号、户口本等数据如何脱敏、加密、留痕？
- 第三方大模型是否会接触原始证件信息？如果接触，是否合规？

---

### 11. 隐私、安全与用户“破壳”问题

客户关心用户是否可能通过提示词诱导 Agent 说出无关内容、泄露信息、执行越权操作，类似“把 AI Agent 攻破”的情况。客户希望确认我们是否有相关测试和处理经验。

产研需要回答：

- 是否具备防 prompt injection / jailbreak / 越权提问的经验？
- 用户问无关内容时，Agent 如何限制回复？
- 用户试图套取系统提示词、后台信息、其他用户信息时，如何处理？
- Agent 调用后台接口前是否有权限校验？
- 是否有敏感操作白名单？
- 是否有红队测试或对抗测试流程？
- 是否能输出安全测试报告？

补充建议：

这部分要作为正式方案的独立章节，因为客户系统里涉及订单、退款、手机号、身份证、未成年人资料等敏感信息。安全方案不能只写“模型会拒绝”，而应写成“权限隔离 + 敏感信息脱敏 + 工具调用审计 + 人工确认 + 对抗测试”的组合方案。

---

### 12. 是否需要内部记忆系统？

第三方大模型 API 本身没有长期记忆能力，每次调用都需要传入上下文。客户也讨论到需要“内部记忆系统”，用于保存流程、SOP、用户状态和历史过程信息。

产研需要回答：

- 是否需要独立设计内部记忆系统？
- 记忆系统需要保存哪些内容：
  - 用户历史沟通记录
  - 当前工单状态
  - 订单售后进度
  - SOP / 政策文档
  - 特殊案例
  - 用户标签
  - 私域运营偏好
- 记忆是按用户、按订单、按工单，还是按会话维度存储？
- 如何避免每次把完整历史上下文都塞给模型导致 token 成本过高？
- 是否采用分层上下文策略：
  - 当前问题
  - 当前工单摘要
  - 用户历史摘要
  - 相关 SOP
  - 必要订单数据
- 记忆数据是否需要过期、删除、脱敏？

---

### 13. 模型选型、部署方式与成本估算

客户倾向使用国内模型控制成本。目前以文字输入输出为主，初步估算每日 token 成本约一两百元，但仍需结合真实在线聊天情况确认；客户有 58 万条工单数据，但在线聊天历史未完整留存。

产研需要回答：

- 推荐使用哪些模型？
- 文本客服、图片识别、视频理解、证件 OCR 是否使用同一个模型，还是分模型处理？
- 是否需要本地模型？哪些场景必须本地化？
- 是否需要微调，还是 RAG + SOP + 工具调用即可？
- 基于客户日工单量，预估每日、每月模型调用成本是多少？
- 图片 / 视频识别的成本是否单独估算？
- 58 万条历史工单如何用于：
  - SOP 梳理
  - 语料分析
  - 测试集构建
  - FAQ 聚类
  - 模型效果评估
- 需要客户补充哪些在线会话样本，才能准确估算 token 成本？

### 14. 实施节奏：一次性全量实现还是按功能模块切入？

客户会议中讨论了两种路径：

1. 一次性搭好整体客服 Agent 系统，再按优先级内测
2. 先从未成年人退款等规则清晰的场景切入，再逐步扩展

该问题需要产研确认。

产研需要回答：

- 是否建议一次性搭建完整 Agent 底座？
- 是否建议先做 MVP？如果做 MVP，优先选哪个场景？
- 哪些功能适合第一阶段：
  - 文本客服自动回复
  - 工单分类
  - SOP 检索
  - 未成年人退款审核
  - 物流自动跟进
  - 跨工单查询
- 哪些功能适合第二阶段：
  - 开箱视频审核
  - 商品损伤识别
  - 多 Agent 质检
  - 私域主动运营
  - 仓库 Agent
- 内测如何做？客户提到希望对常见业务点做盲测，产研需要设计测试方案。

## 三、私域运营 Agent 相关产研待确认问题

### 15. 企业微信社群接入与商品库对接

客户的私域主要基于企业微信，希望 Agent 不只是陪聊，而是能促进销售转化。社群部分主要基于企微，需要接入商品库，实现商品推荐、主动消息推送、用户产品收集等功能。

产研需要回答：

- 企业微信社群接入方案是否成熟？
- 是否支持群聊消息监听、用户标签识别、关键词触发？
- 是否能接入商品库，根据用户需求推荐商品？
- 商品推荐需要哪些数据：
  - 商品名称
  - SKU
  - 库存
  - 售价
  - 商品图
  - 适用人群
  - 活动信息
  - 历史销量
- 是否支持主动消息推送？
- 主动推送如何避免骚扰用户或触发企微风控？
- 是否能识别用户购买意向并打标签？
- 是否能把社群互动转化为销售线索或客服工单？

---

### 16. 私域运营 Agent 如何做用户标签与转化？

客户提到最终目标要反映在销售上，“纯聊天没有意义”。商品推荐、主动触达、用户产品收集、销售转化是社群 Agent 的核心方向。

产研需要回答：

- Agent 是否能根据用户聊天内容自动打标签？
- 标签体系由客户提供，还是我们帮助设计？
- 标签示例：
  - 感兴趣品类
  - 价格敏感度
  - 购买意向
  - 售后风险
  - 老客 / 新客
  - 未成年人相关
  - 高价值用户
- 是否能根据标签触发不同运营动作？
- 是否能生成每日社群运营总结：
  - 今日高意向用户
  - 今日需人工跟进用户
  - 今日热议商品
  - 今日负面情绪
  - 今日可推送商品
- 是否能和客服 Agent 打通，让售后用户后续进入私域运营链路？

## 四、仓库 Agent / 跨部门协同相关问题

### 17. 是否需要单独设计仓库 Agent？

客户提到目前仓库沟通效率低，多人向仓库提需求，仓库响应慢、容易遗漏。客户设想给仓库做一个 Agent，统一接收需求、整理任务、每天询问仓库任务清单。

产研需要回答：

- 是否建议把仓库 Agent 纳入本期方案？
- 仓库 Agent 的定位是：
  - 仓库任务收口
  - 催发货
  - 催补货
  - 处理缺货反馈
  - 同步物流异常
  - 给客服提供仓库状态
- 是否需要对接仓储系统？
- 如果仓储系统暂未打通，是否可先通过飞书 / 企微任务流实现？
- 是否可以每天自动生成仓库任务清单？
- 是否可以按任务等级提醒仓库处理？
- 仓库回复后，是否能自动同步给客服 Agent 或用户？

---

### 18. 多 Agent 架构是否必要？

会议中客户提出多个 Agent 角色的设想，例如客服 Agent、质检 Agent、质疑 Agent、仓库 Agent、催货 Agent 等。是否真的用多 Agent 实现，需要在方案阶段对比。

产研需要回答：

- 本项目是否需要多 Agent 架构？
- 哪些角色是真正独立 Agent，哪些只是同一个 Agent 的不同工作流？
- 建议角色拆分：
  - 客服 Agent：直接处理用户问题
  - 质检 Agent：复核客服回复是否符合 SOP
  - 质疑 Agent / 主管 Agent：处理规则冲突和特殊诉求
  - 私域运营 Agent：社群运营、商品推荐、用户标签
  - 仓库 Agent：跨部门任务收口
  - 催货 Agent：缺货、补货、发货提醒
- 多 Agent 之间如何通信？
- 是否会增加开发复杂度和成本？
- 是否可以先用单 Agent + 工作流编排实现，后续再拆成多 Agent？
