# 2026-08-17 发布治理与验收证据计划

## 目标

完成四项交付：

1. 让高级客服主管可在 JKAdmin 配置审核强度和媒体预处理预算；配置必须租户隔离、理由不少于 6 个中文字符、可审计、可回档，并在新任务中生效。
2. 将当前四场景 8 份正式 HTML 报告作为可追溯交付证据，增加质量索引和不夸大能力边界的评价。
3. 更新甲方验收 HTML，说明旧测试/自我限制清理、结构化数据流、媒体持久化预处理、开箱视频预检、未成年人主体/证件局部识别，以及可配置与不可配置边界。
4. 更新双版本打包门禁、README、CHANGELOG，重打双 ZIP，创建私人仓库和公司仓库 Release。

## 实施顺序

1. 审计现有治理、媒体预处理、报告证据和发布脚本的调用关系。
2. 新增结构化策略版本库与受保护 API；复用现有 SQLite 管理库和版本审计模式。
3. 在工作台正式任务入口读取租户策略，传给视频质量预算和审核强度解析；未经配置时使用当前已验证默认值。
4. 增加 JKAdmin 策略页面，仅展示客服可理解字段，不返回 Prompt、Key、供应商内部参数。
5. 生成 8 份报告的质量索引，更新验收说明和打包清单/哈希校验。
6. 运行后端定向测试、前端构建、发布门禁和浏览器验收；确认 API 与 Web 使用同一结果快照。
7. 以最终提交重新生成 ZIP/校验回执，并在两个仓库创建同版本 Release。

## 验收口径

- 没有真实外部渠道凭据时，不声称真实模型冒烟通过；只报告本地契约与已存在的历史运行证据。
- 8 份 HTML 逐份检查首屏结论、材料齐全性、场景专属详情、证据回链、脱敏和移动端溢出。
- 配置变更历史必须包含账号、角色、时间、原因、源版本；回档生成新版本，不覆盖旧记录。
