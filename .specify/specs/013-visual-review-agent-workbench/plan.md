# 三大视觉审核 Agent 工作台商业化改造计划

## 目标

把视觉审核 POC 从“能跑模型的单入口 Demo”升级为“客服能实际试用的三入口审核工作台”，同时收敛拟人/陪伴表达，符合工作助手定位。

## 技术方案

- 前端：继续使用 `poc/visual_review_poc/workbench.html`，避免新增前端构建依赖；用三入口卡片驱动同一套上传和 URL 解析组件。
- 后端：继续使用 FastAPI `workbench_server.py`，扩展 `/api/review` 表单参数和受限 `/media/{rel_path}` 路由。
- 模型上下文：扩展 `local_video_triage_demo.py` 的 `--scenario` 与 `--context-json` 参数，确保客服证据包进入 Prompt。
- 报告：继续通过 `/reports/{name}` 渲染 HTML，但 Agent 报告新增媒体证据画廊和证据卡缩略图。
- 合规：客服主 Agent Prompt 从“MBTI/陪伴/拟人化”改成“专业、同理、有边界的服务型工作助手”。

## 验收路径

1. 启动 `python -m poc.visual_review_poc.workbench_server`。
2. 访问 `http://127.0.0.1:7861/`。
3. 切换三个入口，检查文案、取证策略、证据包字段和控制台。
4. 在商品有伤入口运行 `sample_003`。
5. 打开生成的报告，检查结论首屏、证据卡、抽帧图、补充图和视频时间点链接。
6. 运行 Python 编译检查，确认后端语法无误。

## 风险与边界

- 公开视频 URL 解析受平台风控、地区权限、登录态和文件大小影响，POC 必须保留本地上传主路径。
- 证据包字段进入模型上下文，但真实订单、物流、仓库系统未联调前仍是 Mock/手工录入。
- 商品有伤样本能跑通不等于准确率达标；正式准确率评估仍需甲方提供每类正负样本至少 50 条，推荐 200-300 条。
- 未成年人资料审核涉及敏感个人信息，POC 默认只演示脱敏材料完整性检查。
