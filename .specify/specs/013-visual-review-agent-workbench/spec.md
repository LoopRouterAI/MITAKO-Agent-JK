# 三大视觉审核 Agent 工作台商业化改造 SPEC

**创建日期**：2026-07-04
**状态**：已进入 POC 落地
**范围**：开箱/发错货审核、商品有伤审核、未成年人资料完整性审核

## 背景

甲方反馈视频审核、商品有伤、未成年人资料审核三类任务占客服人力约 60%，且爆单时会挤占客服主链路人力。当前 POC 已证明 Gemini 3.5 Flash 对商品有伤样本存在业务信号，但旧工作台把三类任务混在一个入口，证据包输入和报告可读性不足，不利于客服高频处理。

## 用户故事

### US-001：客服按独立入口处理任务

作为VIP客服，我需要从三个独立入口进入不同审核任务，避免在一个混合入口里选择场景，减少错投材料和误读报告。

### US-002：客服提交完整证据包

作为VIP客服，我需要把工单号、用户 ID、订单号、用户申诉、商品/SKU、物流状态、投诉进展、商品/仓库主数据、历史对话与视频材料作为同一个证据包提交给审核 Agent。

### US-003：客服快速读懂审核报告

作为VIP客服，我需要报告第一屏直接给出视觉证据结论、置信度和下一步建议；后续再查看证据链、关键帧、补充图片、视频时间点和人工需知。

### US-004：负责人评估模型与流程边界

作为客服负责人，我需要知道该系统只做视觉证据辅助和人工复核分流，不做自动退款、拒赔、补发、定责或未成年人资料终审。

## 功能需求

- FR-001：系统必须提供三个独立入口：开箱视频审核、商品有伤审核、未成年人资料审核。
- FR-002：每个入口必须有独立证据清单、默认抽帧策略、提交按钮文案和审核目标说明。
- FR-003：审核表单必须支持本地视频上传和公开视频 URL/分享文本解析。
- FR-004：审核表单必须支持工单证据包字段：工单号、用户 ID、订单号、申诉文本、订单商品名、SKU/规格、物流进度、申诉进展、商品/仓库主数据、历史对话。
- FR-005：普通上传审核必须把证据包字段传入后端，并进入模型 Prompt 上下文。
- FR-006：报告必须结论优先，展示置信度、系统参考结论、核心理由、VIP客服下一步、连续性分数和调包风险。
- FR-007：模型引用关键帧或补充图片时，报告必须展示可点击缩略图；视频帧必须提供原视频目标时间点预览链接。
- FR-008：商品有伤入口必须保留甲方 sample_003 的一键演示能力；其他入口不得伪造样本。
- FR-009：工作台必须提供默认可见且可折叠的右侧任务控制台。
- FR-010：所有用户可见文案不得暴露外包、渠道商、API Key、供应商失败、内部 Prompt 等信息。

## 合规需求

- CR-001：甲方业务接口、客户接口、订单接口在 POC 阶段只能使用 Mock、手工录入或脱敏样本，不得伪称真实对接。
- CR-002：AI 结论只能作为客服复核参考，不得直接触发退款、补发、拒赔、定责、账号处置或未成年人资料终审。
- CR-003：客服系统保留同理心与清晰解释，但不得以“虚拟伴侣、私人陪伴、角色扮演、MBTI 人格”为甲方交付主线。
- CR-004：Companion/陪伴模式如继续保留，必须从甲方客服 POC 交付隔离，默认关闭，不作为视觉审核或客服主链路卖点。
- CR-005：涉及未成年人资料时，模型只做材料完整性、清晰度、前后一致性和补件线索检查；敏感原始证件默认不送外部通用模型。
- CR-006：依据《人工智能拟人化互动服务管理暂行办法》（2026-04-10 发布，2026-07-15 施行），本 POC 应定位为AI客服/工作助手，不设计持续性情感互动目标。

## 成功标准

- SC-001：打开 `http://127.0.0.1:7861/` 后，首屏能看到三个独立审核入口。
- SC-002：切换三个入口时，证据清单、抽帧策略、按钮文案和右侧日志同步变化。
- SC-003：商品有伤入口运行 sample_003 后，能生成 Agent 报告并展示媒体证据画廊。
- SC-004：浏览器控制台无初始化错误；移动端 390px 宽度下入口、上传区、报告链接和控制台可操作。
- SC-005：后端 `/api/review` 接收证据包字段并传入 `local_video_triage_demo` 的模型上下文。
- SC-006：客服主 Agent Prompt 不再使用 MBTI/角色扮演/陪伴服务作为核心定位。
