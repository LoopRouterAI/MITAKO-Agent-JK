用人话说明这次改了什么

普通审核不再只看十来帧

商品有伤普通档现在至少按 1 FPS 审查完整时间轴，并执行主体连续性与损伤成因专项通道。618205 普通档从旧版的错误 positive / 0.95 改为 review / 0.6425。

Strong 统一为 2 FPS

Strong 用于离镜、动作前后和争议时点强化复核，最多 1800 帧。618205 Strong 识别到争议商品约在 00:52.22 首次曝光，并保持复核结论。

报告不再把一个分段当完整视频

每个分段明确知道自己只是局部；公开结论改由完整帧注册表和全局时长生成。原报告“00:11.44 视频结束，但 00:52.22 才出现商品”的矛盾已消除。

可自动分类，但不能自动拒赔

只有甲方批准并带版本号的规则才能把“缺必需开箱视频”等情况输出为 negative。这只是审核分类建议，退款、拒绝、补发、换货和最终定责仍由甲方系统及授权人员执行。

真实测试发现并修复的工程问题

1. 内部请求被代理转发，固定约 602 秒返回 503

首轮大样本盲测真实捕获 614176、617911 的 503。三次尝试分别约 602 秒，网络连接显示内部 127.0.0.1:7861 请求先进入本机代理端口，代理超时后工作台仍继续推理，形成孤儿请求。

整改后内部服务调用强制绕过环境代理并直连 7861；清理孤儿进程后复用原 job 重试。614176 单次直连约 963.047 秒成功，617911 单次直连约 952.923 秒成功，重试次数均为 0。

2. 成本统计被公开报告脱敏逻辑误删

公开 HTML 不应展示模型、Token 和成本，但受保护的审核 API 必须保留内部运维统计。本轮已拆分两条输出路径。复验任务返回 20,358 Token、估算 0.08084 美元、1 次模型调用；估算仅用于容量和方案比较，不等同于供应商账单。

3. 600MB 级上传与媒体取证

614176 单视频为 602,861,197 字节，整案 675,087,928 字节；正式 API 提交成功，ffprobe 在真实文件上完成容器、音视频流、帧率和 packet timeline 检查。Nginx 参考配置已统一为审核入口 800MB，并关闭请求缓冲。
