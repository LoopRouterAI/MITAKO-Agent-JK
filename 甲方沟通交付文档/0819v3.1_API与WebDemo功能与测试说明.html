API 版本功能

客服对话

统一意图、事实和处理状态

API 先确定场景，再生成回复。用户端、坐席端和 API 读取同一个公开状态，不靠自然语言猜测“是否已转人工”。

可验证：未提交、待执行、排队中、已完成、未执行成功、等待人工。

异步审核

创建任务、轮询、JSON 与 HTML

视觉审核通过正式 /api/v1/review/* 接口创建任务，返回材料状态、审核建议、证据引用和签名报告。四场景使用不同的 Prompt、Schema 和报告细节。

真实订单、仓库、退款执行仍由甲方接口决定。

安全边界

公开结果自动脱敏

公开 DTO 不包含模型名称、渠道、Key、Prompt、内部工具名和证件原值。租户、幂等、签名媒体和失败回执是 API 的固定边界。

Java 接入

推荐调用顺序

  1. 校验场景和业务字段。
  2. 提交 metadata 与附件。
  3. 轮询任务状态或批次状态。
  4. 读取公开 JSON；需要时读取签名 HTML。
  5. 根据材料齐全性和下一步生成客服动作。

Web Demo 功能

用户端 / 客服对话

上传材料、查看真实处理状态、停止生成、重试失败操作、进入人工队列。状态变化不要求刷新页面。

VIP 坐席台

查看用户当前公开状态、人工队列、简报和下一步；不显示模型渠道和内部调试字段。

JKAdmin

查看租户级审核策略、模型启停、默认档和历史版本。业务策略修改必须填写理由并留存账号、时间、版本和回档记录。底层 Prompt、Schema 和密钥不开放给客服人员。

视觉审核工作台

接收目录或多文件、盘点材料、进行图片 WebP/视频代理预处理、运行四场景审核并查看双层 HTML 报告。

建议测试顺序

  1. 先测未提交：只输入用户说“我有材料”，确认系统不会假装已经收到附件。
  2. 再测场景识别：分别测试商品咨询、发错货、漏发货、退款、隐私和高风险投诉，检查主回复与右侧意图一致。
  3. 再测失败：让工具返回失败，确认页面显示失败、重试或人工入口，不显示成功。
  4. 再测转人工：分别验证入队成功、入队失败、等待回执，确认 API、用户端和坐席端一致。
  5. 再测视觉审核：用四场景各自材料，检查材料齐全性、场景专属字段、证据跳秒和报告首层结论。
  6. 最后做甲方联调：接入真实订单、包裹、仓库、CRM、改址、隐私和退款接口后，再验证业务动作，不把 Mock 结果当生产能力。

当前可改变与不可改变的设置

客服主管可调整

审核强度、材料缺口处理倾向、是否启用高成本模型档、媒体压缩阈值、1 FPS 回退开关、人工复核等级和场景策略版本。每次修改需要填写不少于 6 个汉字的理由，并支持历史查看和回档。

研发或管理员维护

Prompt、Schema、租户密钥、签名规则、模型请求协议和内部日志详情属于技术配置，不开放给普通客服人员。生产 Java 服务应以 API 契约为准，不直接调用工作台内部路由。

联调边界：不是当前代码缺陷

以下事项需要甲方提供真实接口、凭证、回调或测试数据后才能完成：订单和 SKU 查询、包裹/仓库实发查询、历史客诉查询、改址写入、隐私删除、退款执行、CRM/企微/飞书消息回写。当前系统会保留诉求、显示待执行、失败或人工入口，不会伪造成功。

这类事项记录为“外部联调依赖”，不作为 v3.1 Beta 本地代码质量障碍。
