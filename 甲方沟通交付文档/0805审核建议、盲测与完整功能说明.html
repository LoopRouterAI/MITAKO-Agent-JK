先说人话：这次到底改了什么

以前：只要媒体取证、可见度、离镜、补图关联或某个分数没有全部达标，商品有伤就容易回到“待确认、补材料、转人工”。

现在：Agent 先按核心 SOP 回答“当前证据支持还是不支持诉求”，再把离镜、成因不明、轻度图片风险等放到“建议抽检”中。抽检不等于每单转人工。

业务边界没有取消：Agent 可以明确给审核建议，但不会自己执行退款、换货、补偿或拒绝。最终动作仍由甲方系统和授权人员决定。

本轮六项修正

商品有伤

删除默认“全门槛同时通过”

完整视频未见所诉损伤可给不支持倾向；主视频有明确可回链损伤可给支持倾向。其他疑点保留在风险和抽检中。

复审分流

建议、复审、业务动作真正分开

optional 只表示抽检，not_required 表示无需人工；不再出现“建议抽检但下一步仍要求 VIP 复核”的矛盾。

未成年人

模板、截图和真实资料分层

空白模板和示例图不算证明；普通运营商账户截图只作辅助；已填写且类型可识别的证件不会因个别字段未知被误报为缺件。

风险判断

不再泛化“疑似编辑”

只有图片级、位置明确的异常或多项独立证据相互印证才升级。缺 EXIF、压缩、扫描和转发本身只提示注意。

客服报告

首屏只保留真正要看的内容

第一屏展示证据结论、SOP 倾向、证据分数、人工复审、具体缺口、客服下一步和关键证据；技术细节默认折叠。

测试安全

模型推理前看不到答案

盲测使用中立 Case 编号，过滤人工标注、客服最终回复、管理员消息、正负目录名和隐藏资源文件，推理完成后才加载期望结果。

真实盲测结果

以下结果来自真实审核接口。人工期望只在模型推理完成后用于评分。

中立案件场景Agent 结果证据分数人工/流程建议验收

为什么不是“4/4 准确率”？CASE-D 的正确业务动作是先补具体资料，而不是强行判正或判负，所以它单独按流程验收。前三个可直接比对结论的案件为 3/3。

报告现在怎么读

绿色：可以继续

证据倾向明确。甲方可按自身规则继续，或按比例抽检；不需要客服把整单重新看一遍。

黄色：看重点或补材料

轻度疑点不会抹掉结论。报告会直接写明看哪张图、哪一帧，或只补哪一项材料。

红色：必须复核

仅用于实质证据冲突、明确高风险或技术处理失败；授权人员重点回看原始证据。

  1. 先看“按照 SOP 的审核倾向”，确认支持、不支持或待补件。
  2. 再看“人工复审”，区分必须复审、建议抽检和无需复审。
  3. 需要补件时直接看具体清单，不必在十几屏技术细节中寻找。
  4. 只有需要进一步确认时才展开完整技术分析和全部证据画廊。

建议这样复测

  1. 分别选择一个商品有伤支持样本、不支持样本、未成年人完整资料和缺件资料；不要把人工标签、正负目录名或最终客服回复提交给接口。
  2. 网页端先用“工单文件夹”逐案提交，再用“批量工单”提交多个案件；确认隐藏文件不会变成待审视频。
  3. 接口端调用 `/api/v1/review/jobs`，轮询任务状态；读取事实结论、SOP 建议、证据分数、人工复审等级和流程建议。
  4. 确认 `optional` 的下一步只写抽检，`not_required` 不要求 VIP 复核，缺件案件列出具体材料。
  5. 打开 HTML 报告，确认第一屏信息一致、关键图片可点开、完整技术分析默认折叠。
  6. 正式准确率请在双方冻结标签的黄金集上统计混淆矩阵、正负召回、确定性覆盖率和人工复审率。
