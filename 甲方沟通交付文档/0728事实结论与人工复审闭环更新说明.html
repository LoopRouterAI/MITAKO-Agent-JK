审核 Agent 不再把“有疑点”一律等同于“必须转人工”

本轮针对“结果普遍落在 0.5-0.7、全部不确定、报告前后矛盾”的反馈完成了机制修正。系统现在分别回答：证据支持什么事实、成因与责任能否确定、是否需要人工复审、甲方业务系统下一步可怎样处理。

事实与责任分层三级人工复审补件不占人工席位API / HTML 同一结论源真实请求回归

先说结论

代码能力已经更新，不是只改了报告文案。明确看见商品有伤时，系统可以给出“证据支持有伤”的事实建议；即使暂时无法判断伤是在出厂、运输还是用户操作中形成，也不会因此把事实结论强行改成“不确定”。离镜、轻度连续性疑点等非阻断信号进入风险说明或可抽检，不再默认要求 VIP 客服逐案复核。

本轮实际改了什么

01

“看见有伤”与“谁造成的”分开

伤情清晰可见时可以输出事实 positive；形成时间、原因和责任另给倾向与置信度。成因不确定不再覆盖已经成立的伤情事实。

02

补充照片可以成为有效证据

只有照片确实进入审核、证据分达到门槛且与争议商品建立同物关联时，才用于确认可见伤情；它不会被进一步推断为平台责任。

03

减少无意义的全量人工复核

服务失败、实质冲突、权威核验待完成仍为必须复审；结论明确但有轻度疑点改为可抽检；缺材料优先请用户补件，不先占用客服席位。

04

报告各位置使用同一结论

报告标题、事实结论、人工建议和流程建议统一读取同一份审核建议对象，修复“上面说需复核、下面又说无需复核”等矛盾。

05

视频论证改为四个独立维度

分别说明抽帧首尾覆盖、媒体技术取证、开箱过程完整性、争议商品连续性，避免把其中一个维度写成整段视频已经确定完整。

06

API 与网页保持同一业务口径

正式 API 返回结构化字段；需要人工阅读时可生成同一任务的 HTML。网页工作台用于 UAT 和报告查看，不要求甲方在生产中手填订单。

成因与责任问题更可能在哪个阶段形成、哪方责任倾向更高。与事实结论分开消费；证据不足时允许保持不确定。

甲方建议这样测试

1. 单案复测分别提交明确支持、明确不支持和证据不足案件，核对事实、成因和复审等级是否分开。
2. 批量盲测每案独立任务、共享 batch_id；请求中不出现人工标签和最终处理答案。
3. 对照报告核对标题、事实结论、人工建议、流程建议和证据帧是否一致，不允许局部矛盾。
4. 冻结黄金集四个视觉场景各 25 案，另建未成年人材料集，再校准阈值与人工复审率。
