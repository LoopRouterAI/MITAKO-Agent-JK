统一检查项

  • 首屏能看到整体建议、确定性、材料是否齐全和下一步。
  • 详情按场景显示证据、置信度和原视频/图片预览；不显示原始响应、底层配置、上游渠道、访问凭据或个人字段原值。
  • API JSON、Web 工作台和 HTML 使用同一工单的建议数据，不各自重新判断。
  • 技术异常、速度未知、剪辑弱信号和证据不足均保留边界，不伪造准确率。

报告副本位于本目录下的“四场景审核报告”文件夹；甲方运行包只包含脱敏 HTML，不包含内部测试、人工标签和内部结构化结果。

八案能说明什么

  • 商品有伤：开箱链、伤点与成因分开呈现；不确定时保留黄标，不把补图直接升级成主视频事实。
  • 发错货：按应收基线、同包裹证据和实收身份属性对账；静态材料不足时保留人工核验边界。
  • 漏发货：区分视频、静态资料和仓库终核路线，不因缺视频机械判负。
  • 未成年人：五类材料逐项核对，点名缺口和冲突，不输出退款批准或把材料问题写成欺诈。

这八案证明的是当前数据流、报告结构和场景边界可复核，不是生产准确率；未学习黄金集仍需另行统计。

三份交付 ZIP

  • 甲方运行包：供客服、产品和 IT 联调，不包含源码、内部指令和敏感原始图片。
  • 内部研发包：供 Java/Python/前端研发，包含源码和技术文档，不再混入大体量样本与离线敏感图片。
  • 四场景验收证据包：包含本页、8 份 HTML、119 个 WebP、manifest 和哈希，只向授权验收人员提供。

三个包绑定同一 Git 提交和 Release，分别记录大小与 SHA256；详见交付包拆分说明。

离线图片证据

独立验收证据包提供 WebP 证据包 manifest，报告中的图片可以在没有签名 API 的情况下预览。该包包含未成年人身份证、支付等敏感材料，只向授权验收人员提供；甲方运行包和内部研发包均不携带原始静态证据，客户环境通过授权 API 获取签名媒体。视频仍需启动 API 才能按秒跳转和全屏查看。
