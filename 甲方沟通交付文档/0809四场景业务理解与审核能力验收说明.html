本说明供客服主管、项目负责人和测试人员核对：系统现在理解哪些业务事实、能给出哪些客服动作，以及哪些情况仍必须保留人工判断。

当前商业阶段可控试点

可减少确定性案件和明确补件的人工判断，但复杂多视频、特殊商品和证据冲突案件仍需抽检，暂不作为无人终审系统。

本轮结论

系统已经从“罗列风险”转为“先给审核倾向，再说明理由和下一步”。确定性硬失败、明确缺件、跨户口本关系缺口、可信仓库终核和高置信低龄风险可以直接分流；证据不足时给一次性补件清单，技术失败不会冒充用户缺件。

系统如何形成结论

确认本案基准

先读取订单、商品、包裹、申请主体和已知仓库结果。

提取可见事实

只记录本案图片、视频和材料中能回看的事实。

按场景套用规则

商品有伤、错发、漏发与未成年人材料不混用判断条件。

给客服动作

继续处理、补充材料、可选抽检或必须复核四类动作互斥输出。

系统区分“画面看到了什么”“材料是否符合 SOP”“责任属于谁”和“最终退款/补发动作”。前两项可由当前系统给建议，最终经营动作仍由甲方授权系统或人员执行。

四大场景的当前业务理解

01 · 商品有伤

开箱链与伤情链分别判断

  • 核对完整未拆封外包装起始、面单、连续拆封、同一商品和争议部位。
  • 记录伤情是否可见、首次出现时点和可能成因；补充图片不能改写主视频时点。
  • 手工品、毛绒和天然材质先记录外观差异，再按明确标准判断是否构成缺陷。
  • 开箱材料不合规不等于商品无损，也不等于用户造假。
02 · 错发货

以订单和实收商品身份做对照

  • 核对版本化订单/SKU、实收商品、包装面单和赠品/随机款规则。
  • 证据关联完整时，清晰照片可以形成判断链，不再一律强制开箱视频。
  • 只看到气泡膜或外包装、未展示商品本体时，不会直接判错发。
  • 工单号、目录名或文件尾号不参与业务判断。
03 · 漏发货

应收、实收、全部包裹一起核对

  • 核对应收清单、实收清单、分包物流、赠品/选款规则和全部包裹覆盖。
  • “缺少应购商品 A，同时多出未购商品 C”转入错发方向，不按漏发处理。
  • 可信仓库终审可以覆盖早期“需要核实”的过程备注。
  • 工单 568689 已确认实收摆件与订单商品一致，应输出确定未漏发。
04 · 未成年人退款

材料事实、关系链和支付风险分层

  • 五类材料分别检查存在性、可读性、字段一致性和适用主体。
  • 姐姐、学校登记材料或分属两本户口本，均不能自动闭合法定监护关系。
  • 支付截图不能替代手机号归属；电脑录入姓名不能替代亲笔签名。
  • 不把水印、涂改或年龄本身直接等同于造假或退款结论。

视频加速如何处理

1 FPS 仍可判断加速只作为橙色提醒，不单独改变审核结论。
1 FPS 无法判断保持待确认，并在必要时有界强化到 2 FPS，不重复发送无关画面。
2 FPS 后仍受影响只有关键开箱或伤情事实仍不可判断时，才记录为实质审核影响。

跳切、拼接、缺少封箱起始、面单不可读和关键过程缺失仍是独立问题，不由“是否加速”替代。

客服实际看到什么

首屏先给可执行结论

审核倾向、主要理由、下一步和关键证据固定在首屏；技术细节默认折叠，避免客服在大量字段中寻找动作。

补件与人工不再混写

能补材料时给唯一清单；证据冲突或高风险时才要求人工；系统失败只提示重试。

API 与网页口径一致

两种入口使用同一业务后处理逻辑，结论、补件、人工等级和报告字段有自动化一致性测试。

公开报告最小化信息

不展示内部模型、渠道、提示词、调试参数、成本、身份证号、手机号或 OCR 原文；证据媒体通过受控地址回看。

高级客服可维护业务规则：后台按场景提供规则版本管理；每次发布必须填写原因并记录账号和时间，支持追加、替换、历史查看、回档预览和版本冲突保护。普通客服和公开测试页面看不到该入口或内部提示内容。

建议甲方测试时重点核对

  1. 同一案件在网页和标准 API 中，审核倾向、补件、人工等级是否一致。
  2. 商品有伤报告是否把开场合规、伤情可见和伤情成因分开，不互相覆盖。
  3. 错发是否允许完整照片证据链，漏发是否正确处理“少 A、多 C”和仓库终审。
  4. 未成年人报告是否合并同义补件，是否识别跨户口本关系链、亲笔签名和手机号持有人。
  5. 未满 9 周岁是否只触发重点复核，不直接改变退款或支持结论。
  6. 首屏是否让客服无需阅读技术细节即可知道“结论、原因、下一步”。
