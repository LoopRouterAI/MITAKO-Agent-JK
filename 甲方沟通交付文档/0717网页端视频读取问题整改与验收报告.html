发生了什么

1

目录内混入系统生成的伪文件

从 macOS 或部分压缩工具复制目录时，会出现 __MACOSX、._视频名.mp4 等资源副本。它们扩展名像视频，实际不是视频。

2

旧网页入口只看扩展名

旧逻辑在清洗文件名后再判断，可能把 ._002.mp4 变成看似正常的文件名并送去抽帧。

3

坏文件导致整个工单失败

多视频按顺序读取时，只要一个伪视频无法解码，旧流程就终止，因此页面显示“视频无法读取”。

4

正式 API 原本校验更严格

正式审核 API 已校验媒体内容，所以相同业务样本可以成功。网页端与 API 的接收规则不一致，造成表面矛盾。

整改后的处理链路

浏览器预过滤隐藏目录、资源副本、空文件不提交
后端再次过滤不信任浏览器，重复执行系统文件规则
内容签名校验扩展名与实际图片/视频内容必须一致
解码失败隔离坏视频单独记录，有效视频继续审核
清晰回执显示选择、提交、接受、跳过及原因
