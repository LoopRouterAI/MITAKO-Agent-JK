MITAKO 视觉审核服务
0723 结果契约更新
不是只改文档，本轮已修改 API 与报告代码

审核服务现在给出结论和证据分数，再说明是否真的需要人工

旧版容易把“有疑点”直接等同于“必须转 VIP 客服”。新版把事实判断、证据强弱、风险信号和人工建议分开，目标是减少不必要的人工复核，同时保留可追溯的证据链。

事实判断支持、不支持或证据不足，并说明依据
三级人工建议必须复审、建议抽检、无需复审
JSON 或 HTML系统自动化可只取字段，网页默认保留人类报告

最重要的变化

审核服务不再把退款、换货、补发或拒绝写成自己的决定。它只回答：看到了什么、证据支持什么、分数是多少、有哪些风险信号、建议甲方下一步怎么处理。

例如：商品离开镜头 3.2 秒新版结论是“当前开箱证据不完整，建议用户补充连续原视频”。这不等于用户调包，不等于视频被剪辑，也不等于自动拒绝。

三种人工复审建议

LEVEL 1

必须人工复审

服务执行失败、证据之间有实质冲突，或证据分数低于甲方配置的必须复审线。

LEVEL 2

建议抽检

有短暂遮挡、轻度风险信号或中等证据分数，但不要求每一单都交给人工。

LEVEL 3

无需人工复审

证据链达到配置门槛，或当前问题可以直接通过补充材料继续处理。

离框、遮挡和疑似剪辑怎么处理

短暂离框或手臂遮挡

记录持续时间和对应帧，作为橙色风险信号降低证据强度，不单独强制人工，也不判断为调包。

连续离框达到 3 秒

默认建议补充连续原视频。甲方可配置秒数，但该阈值只控制补件建议，不是自动拒绝阈值。

怀疑剪辑或篡改

必须结合码流、时间线、帧率、编辑器元数据、物体前后同一性等多个信号。单一离框时长不能证明剪辑。

证据真的冲突

主视频、补充图片、订单基准或资料字段出现实质冲突时，才进入“必须人工复审”。

给甲方系统的主要字段

assessment.conclusion 事实结论 assessment.confidence 未校准的证据强度分 human_review.level required / optional / not_required workflow_recommendation human_review / request_more_material / continue_by_customer_policy signals[] 离框、冲突、材料缺口、媒体取证等信号 policy.business_action_allowed = false

“证据强度分”不是客观正确率，也不是退款概率。正式准确率仍应使用冻结输入的独立盲测集评估。

API 和网页分别怎么用

网页单件/单文件夹
默认生成结构化结果和完整 HTML，客服可查看关键帧、反证和时间点。
网页批量父目录
逐案件独立审核，默认每案生成 HTML，不让一个失败案件污染其他案件。
正式异步 API
默认兼容旧版生成 HTML；甲方可设置只返回 JSON，减少存储和报告生成。
Java 批量
每案一个异步任务，共用 batch_id；每案可独立选择是否要 HTML。
