# 视觉审核下一轮测试建议

版本日期：2026-07-16

## 测试目的

下一轮测试建议把三个问题分开回答：

1. 服务是否稳定接收、并发处理并返回全部案件。
2. 在完整业务上下文下，视觉结论是否与人工对“材料是否支持用户诉求”的判断一致。
3. 系统能否把证据不足、高风险和疑似剪辑案件可靠路由给人工，而不是错误自动放行。

## 建议输入

每个案件通过标准审核接口提交：

- 唯一案件号、场景、批次号和幂等键。
- 用户诉求、订单商品、SKU、数量和物流/仓库信息。
- 相关客服对话和适用 SOP 摘要。
- 全部图片和视频，以及每份素材在原系统中的字段来源。
- 审核强度：默认 `adaptive`，疑点案件可选 `strong`、`forensic` 或 `custom`。

人工标签只在推理完成后通过案件号离线关联，不传给审核模型。

## 标签口径

- `positive`：当前材料支持用户诉求。
- `negative`：当前材料不支持或反驳用户诉求。
- `review`：当前材料不足或冲突，不能可靠自动判断。

退款、补发、换货和最终定责属于业务处置，不直接作为视觉标签。

是否采用双人复核或仲裁由双方根据样本风险协商；这不是审核 API 的必填要求。

## 抽帧强度

| 档位 | 方案 | 建议场景 |
|---|---|---|
| adaptive | 低成本全时间轴自适应 | 批量初筛 |
| strong / strict | 1 FPS | 有疑点、连续性重要 |
| forensic | 2 FPS + 非 AI 取证信号 | 疑似剪辑、高风险、反证冲突 |
| custom | 0.1-2 FPS 自定义 | 特殊成本或精度目标 |

系统报告应说明实际抽帧数、时间轴覆盖、模型分段数、估算成本和是否建议升级。1 FPS 或 2 FPS 可提高发现瞬时异常和跳切的概率，但不能单独证明视频未剪辑。

`adaptive` 默认只执行主审核；对疑点案件选择 `strong/strict/forensic` 后，系统自动增加主体连续性专项通道，商品有伤还会增加损伤因果专项通道。采样规划会在上传前返回各通道调用数和总调用数，便于甲方按成本与风险选择。

## 报告指标

工程指标：任务创建成功率、完成率、413/415、重试、P50/P95 延迟、单位案件成本。
模型指标：三分类一致率、混淆矩阵、每类召回率、F1、置信区间。
风险指标：负向被判 positive、正向被判 negative、review 路由率、自动判定覆盖率。

`review` 作为人工复核出口单独统计，不等同于自动通过或自动拒绝。

## 三类场景需要提供的业务基准

这部分用于双方对接字段确认，不要求甲方在生产接口中提交“双人标注、标签仲裁”等评测治理信息。

- 发错货：每个订单商品行的 SKU/条码/包装标识，或可唯一识别的商品名+规格/款式/角色；应发数量；建议提供商品主图、随机/盲盒规则。
- 商品有伤：SKU 不是判断明显可见损伤的硬前提，但商品主图、材质、正常纹理、包装结构和质检标准能降低反光、设计纹理误判。完整开箱与争议部位动作前后画面决定是否能判断损伤形成阶段。
- 漏发货：版本化应发清单、每项数量、套装/赠品/特典规则、拆包/分包规则、包裹数、物流单号关联、标准装箱清单，以及本次实际提交的全部包裹和物品展示。

若漏发视频没有完整展示全部应发包裹或全部配件，服务只输出已识别物品、疑似缺失项、未确认项、证据时间点和置信度，并固定转人工复核，不直接认定漏发。

## 大文件

单文件约 500MB 以上或超长视频建议走对象存储直传和转码/故事板服务，再把受控码率的视频、关键帧索引和原文件哈希交给审核服务。甲方可使用现有云厂商的媒体处理能力；具体供应商、回调签名和存储策略在联调阶段确定。

## 双方边界

我方当前可提供标准 API、异步任务、批次查询、证据报告、审核强度计划、成本估算和失败诊断。
对象存储、云转码、订单/商品/库存、客服工单和最终业务动作需要甲方提供接口与测试环境后联调；当前演示数据不代表这些系统已真实接入。
