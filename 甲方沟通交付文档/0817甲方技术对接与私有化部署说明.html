甲方技术对接与私有化部署说明

本文说明稳定版 Java 后端需要接入的业务字段、接口边界、异步审核状态、媒体压缩服务和安全要求。当前订单、仓库、CRM、历史客诉和客服对话均为契约设计或 Mock，联调时需由甲方提供真实地址、鉴权和字段映射。

原则：甲方系统提供事实，MITAKO Agent 负责材料盘点、媒体预处理、视觉事实抽取、证据对账和客服报告；退款、补发、换货、赔偿和最终定责仍由甲方业务系统执行。

一、建议接入的甲方接口

接口组建议字段用途
工单/客诉case_id、tenant_id、user_id、scene、投诉原文、客服沟通摘要、历史处理状态、创建/更新时间建立一次审核的业务上下文，避免模型只看孤立图片。
订单/SKUorder_id、order_line_id、sku、商品名、规格、应发数量、商品主图、活动/赠品规则、订单状态发错/漏发的应收基线和商品身份锚点。不要把整库或价格隐私送模。
物流/包裹package_ref、tracking_ref（可脱敏）、包裹与订单行映射、分包状态、签收时间判断同包裹关系；一个物流号不能自动推导 SKU 映射。
仓库核验baseline_version、package_ref、实发 SKU/数量、出库扫描、仓库快照、verified_at、verification_ref漏发/静态三图/争议来源的终核。只接受可追溯逐项对账，不接受三个字符串直接给 1.0。

二、正式审核 API 约定

  1. POST /api/v1/review/metadata/validate：校验场景、订单/SKU、客诉和媒体清单。
  2. POST /api/v1/review/jobs：提交 metadata、附件引用和幂等键，返回 job_id。
  3. GET /api/v1/review/jobs/{job_id}：轮询状态、材料齐全性、客服建议和场景详情。
  4. GET /api/v1/review/jobs/{job_id}/report：获取签名 HTML；媒体端点支持按证据秒数跳转和 Range。
  5. GET /api/v1/review/batches/{batch_id}：批次统计与失败任务，不把失败技术状态伪装成用户缺件。

所有请求必须带租户、幂等键和可审计请求 ID。公开数据不包含底层指令、上游渠道配置、访问凭据、内部路径、识别原值和人工标签。

三、私有化媒体预处理与存储

原片不覆盖，送审版持久化。系统保存原片 SHA-256、送审版 SHA-256、编码、分辨率、FPS、码率、转码命令摘要、耗时和失败原因。客服可以对比原片与送审版，确认模型看到的素材没有被误解。
  • 图片逐张转 WebP，不拼图；超过 4K 才缩至最长边约 2560，无损优先，必要时质量 90。
  • 视频达到 100 MB、超过 2K、24 FPS 或 6 Mbps 时评估全时长代理；默认 VP9 WebM，HEVC 由兼容性策略显式选择。
  • 1080P、24 FPS、约 6 Mbps 且时长可接受的视频不强制转码；超长视频可按完整时序无损分 Part，Part 之间保留原始时间偏移。
  • 优先使用受控 HTTPS 地址；临时安全访问桥接只在上游服务无法读取私有文件且甲方明确允许时启用，不是默认上传方式。
  • 运行目录通过 VISUAL_RUNTIME_MEDIA_DIR 指向独立数据盘，避免系统盘空间影响转码。

四、客服工作台与 JKAdmin

页面给谁看可操作内容
审核工作台客服查看简洁建议、材料状态、证据预览、原片跳秒和补件清单；不显示上游渠道和内部参数。
JKAdmin 审核策略高级客服主管/主管角色审核强度、视频/图片送审预算、开箱角色预检、高成本抽帧回退开关和编码偏好。
JKAdmin 能力档位超级管理员启停成本可控档与高质量档、切换默认档位并执行连通性测试；高质量档明确提示成本更高。

任何策略发布或回档要求至少 6 个汉字理由，日志记录账号、角色、租户、时间、源版本、目标版本和变更内容。底层指令、字段契约、访问凭据和上游私有参数不开放给客服主管。

五、联调验收清单

  1. 用一条真实工单贯通订单、包裹、媒体、客诉历史和仓库查询，确认字段映射及权限。
  2. 验证原片/送审版双哈希、断点续传、转码失败重试和独立数据盘运行目录。
  3. 验证四场景各一正一负：API JSON、Web 摘要、HTML 详情同一 job；媒体证据可预览、跳秒、Range 返回 200/206。
  4. 验证租户隔离、签名过期、重复请求幂等、失败用量保留和日志脱敏。
  5. 验证 JKAdmin 发布、历史查询、回档、6 字理由门槛和权限边界。

甲方真实接口上线前，当前 POC 只提供本地缓存和契约适配器；不要把模拟响应当作生产数据。
