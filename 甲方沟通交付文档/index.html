对接目标

把客服工作台、人工复核与 三类视觉审核 打通

3独立审核入口：开箱视频、商品有伤、未成年人资料

端到端流程

01 用户提交App / 小程序提交咨询、视频、图片和诉求文本。
02 Java 后台同步同步工单、订单、SKU、物流、历史投诉和材料地址。
03 创建审核任务按三类任务入口生成独立审核队列。
04 证据摘要输出置信度、证据链、缺失材料、复核建议。
05 人工确认坐席抽检、逐条复核、补件或升级。
06 回写工单人工结论回写甲方系统，客服 Agent 继续服务表达。

三类独立入口

开箱视频审核

重点看连续性与规格匹配

关注箱体和商品是否离开画面、是否存在剪辑断点、用户实物与订单 SKU / 规格 / 角色 / 款式是否一致。

商品有伤审核

重点看损伤证据强弱

关注损伤位置、包装状态、拍摄质量、图片真实性风险和是否需要补拍关键角度。

未成年人资料审核

重点看材料完整与隐私

关注监护人关系、订单归属、付款记录、材料缺失和隐私保护，最终必须人工确认。

接口总览

方向方法路径用途
甲方 -> MITAKOPOST/openapi/v1/tickets/sync同步客服工单与上下文
甲方 -> MITAKOPOST/openapi/v1/review-tasks创建视觉审核任务
甲方 -> MITAKOPOST/openapi/v1/review-tasks/{taskId}/materials上传或追加材料
甲方 -> MITAKOGET/openapi/v1/review-tasks/{taskId}查询审核进度和摘要
甲方 -> MITAKOPOST/openapi/v1/human-decisions回写人工最终处理意见
MITAKO -> 甲方POST{callbackBase}/mitako/review-result审核完成回调

鉴权与重试

Authorization: Bearer <access_token>
X-Timestamp: 1783216400000
X-Nonce: 3a7d6a0b9f
X-Signature: HMAC-SHA256(...)
Idempotency-Key: ticketId-taskType-requestId

429、502、503、504 使用指数退避重试；400、401、403、409 不自动重试。所有写请求必须带幂等键。

WebClient client = WebClient.builder()
  .baseUrl("https://mitako-gateway.example.com")

client.post()

状态机

状态含义下一步
CREATED任务已创建等待材料或进入队列
MATERIAL_READY材料已齐开始审核
AI_REVIEWING正在生成证据摘要等待结果
NEED_MORE_MATERIAL材料不足通知客服补件
REVIEW_COMPLETED审核摘要完成进入人工复核或抽检
HUMAN_CONFIRMED人工已确认回写甲方工单
